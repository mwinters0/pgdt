# 2026-09-20

## `M120`: which refusals are named after the source is a match the compiler checks

`naming_the_source` (`pgdump_query-cli/src/main.rs`) tested two variants with
`matches!` and let every other `pgdump_query::Error` fall through, so the
classification was carried by memory: `14.6` added the second arm by hand,
three slices after the one that wrote the function, and nothing would have
failed had it been forgotten. It is now
an exhaustive `match`, every variant listed in one of three groups — those
given the source's name, those that already name a source or a URL in their own
sentence, and the rest, which are about a place inside the dump, a value in it,
or the request made of it.

**No error's wording moves**; what changed is that a variant added to the
library does not compile until it has been classified. Checked rather than
argued: adding a probe variant to `Error` fails the CLI build with `E0004`
naming it as not covered.

Grouping them forced a verdict on every variant, and one group's was a
judgement call rather than a transcription of what the code already did. It is
settled below, as `M127`.

## `M126`: the pruned-map assertion is read off the heap, not the capacity

`gather::tests::a_map_made_to_hold_its_entries_allocates_the_table_it_is_charged`
closes on what `DictionaryGatherer::renumber` rebuilds its interning map for: a
map pruned in place keeps a table above the one a rebuild allocates for the
entries it kept. It prunes nine entries in ten and reads `map_heap` against
`grown_map_heap`'s charge, then empties the map and reads `map_heap` against the
nothing `renumber`'s `kept == 0` arm charges. Both hold under **every** hash
seeding, because `retain` erases in place and `growth_left` only ever grows: a
pruned map's capacity is at least the 12 slots the 100 entries left free, which
`map_heap` reads as a table above what either prune's rebuild charges. Checked
over 20,000 seedings, zero failures.

**A capacity assertion is not that property.** Whether an erase hands its slot
back to `growth_left` depends on the group the bucket sits in, so under a layout
where every erase does, an emptied map's capacity stands where it started —
**384 of 20,000 seedings**, the seed varying with how many `RandomState`s the
process built before the test. That is why the old closing
`pruned.capacity() < before` passed 400 runs of its own here and failed one of
eleven `cargo test --workspace` runs. `renumber`'s rustdoc claimed the fall too,
and now says the capacity stops naming the table, which is what
[`../../design/runtime-invariants.md`](../../design/runtime-invariants.md),
"RT11" limits its scope to.

## A refusal about a source that moved is named after it, on every command

`M127`. Four `pgdump_query::Error` variants refuse *because the source moved*,
and all four now lead with the name the user typed: `SourceChangedWhileRead`
and `CacheSourceMismatch`, which already did, plus `StrictIdentityUnmet` and
`CachedBlockChanged` in both its arms — the cache-less arm naming neither a
cache nor a dump before this. The classification is `about_the_source`
(`pgdump_query-cli/src/main.rs`), `M120`'s exhaustive match lifted out of
`naming_the_source` so that `parse`, `query` and `info` share one answer:
`query`'s reporter asks it instead of listing `SourceChangedWhileRead` again,
and `info` sends `strict_identity_refusal`'s error through
`naming_the_source` rather than into `anyhow` unclassified. Per-variant rather
than split on `path.is_some()`, so the compile-time coverage stays whole. The
manual moved with it ([`../../manual/dump-inspection.md`](../../manual/dump-inspection.md),
"`--strict-identity`: when a moved file should stop the run").

**What bears on it is the P14 spec's "D18" review**, which called the missing
source name load-bearing on `CacheSourceMismatch` *because the cache path is
derived from a URL's last segment* — true word for word of a
`StrictIdentityUnmet` naming its `path`, and of a `CachedBlockChanged` naming
one. What does **not** bear on it is
[`../../design/decisions.md`](../../design/decisions.md), "D20"'s "the CLI
words both refusals with one tail": that is the *size-mismatch* condition,
`Error::CacheSourceMismatch` and `unusable_cache_message`'s `SourceChanged`
arm, both carrying `TWO_WAYS_OUT` and pinned by `refusals_name_both_ways_out`
(`pgdump_query-cli/tests/partial_reporting.rs`). Neither variant added here
carries that tail.

## `M124` is withdrawn: the walk's cost is not the file's shape

The row asked for a `DiagnosticKind` carrying a `.xz` file's stream count, on
the premise that no caller draining diagnostics can get one. `pgdq info --json`
gets it today: `CompressionShape::streams` (`pgdump_query/src/cache.rs`) is
exported by `IndexJson::compression` and printed by `compression_line`
(`pgdump_query-cli/src/main.rs`), and over a two-stream `.xz` it answers
`"compression":{"container":"xz","streams":2,"blocks":2,…}`.

**Where the shape does and does not reach.** `CompressionShape` hangs off a
`CacheStatus`, so it reaches the two `info` paths and nothing else:
`parse --preamble-only` drains diagnostics and prints them with no compression
line, and a caller holding only a `DumpIndex` has neither and must ask the
source (`ByteRangeSource::seek_table`). So the gap, if it is ever felt, is that
the scanning path projects the file's shape nowhere — a decision about what
`DumpIndex` carries, which is grilled and sliced, not an out-of-band row.

**Two of the three grounds for withdrawing it do not hold**, and are recorded
so they are not reached for again. "A fact is stated once" is a rule about
*documents*; `pgdump_query/src/diagnostic.rs`'s module header is the rule for
this channel and says the opposite — a property of the file belongs there even
when a status line already said it. And the precedent for an unconditional
number on that channel is `TocCoverage`, not `NonSeekableCompressedSource`,
which `non_seekable_compression_diagnostic` (`pgdump_query/src/index.rs`)
raises only for an unseekable table;
[`../../design/roadmap-P14-remote-input.md`](../../design/roadmap-P14-remote-input.md),
"D1" refuses a threshold that would *refuse the file*, not a severity.

**What carries the withdrawal** is that the variant would pick one field out of
a projection that already exists, and that the row's own motivation — the cold
walk's cost — is what that channel excludes by its own rule. Filed at
`announce_remote_walk` (`pgdump_query/src/io.rs`), whose rustdoc had claimed
the number reaches no such caller. Nothing was admitted in its place.
