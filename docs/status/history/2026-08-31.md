### The floor's disqualification threshold is its own number

`measurements.md` had one number, ~8%, doing two jobs: the resolution floor for
warm *figures*, and the tolerance that disqualifies a sweep whose co-measured
warm `dd` floor comes in slow. The two jobs have different noise bands, and
both are already measured in that doc — pure drift moved a warm floor **13.6%**
(and the *same* floor, measured twice inside one sweep pair, disagreed with
itself 13.6% against 11.3%), while the one witnessed contention episode moved
the warm floors **+19–24%** with the cold floor at +0.1%. So ~8% sat inside the
band drift alone produces, and a sweep drifting 9–13% slow would have been
thrown out as contended.

The threshold is now **~15%, measured on floors**, and it takes a second
condition: the slow move must be **shared across the sweep's warm floors**.
That is the measured signature of the mechanism — contention is machine-wide
and moved every warm floor together, while tmpfs staging luck is per-file, and
in the stamped pair the `control` file's floor moved 13.6% while the `arrays`
file's moved −0.9%. The number is the backstop, the shared move is the
discriminator, and both must hold. Two costs are stated in the doc rather than
hidden: a contention episode milder than ~15% now passes the gate, and
"shared" is a weak test across only two or three warm files.

Decision: [`../../design/measurements.md`](../../design/measurements.md), "The
floor is read directionally". The check remains a human rule read off the
sweep's own tables; `measure.py`'s automated gate is the counters
(`contention_verdict`), which does not look at the floor.

### A `--filter` value is trimmed on both sides — settled, not yet landed

The maintainer chose trimming over the alternatives, on both sides of the
value: `--filter 'foo = the answer '` searches for `the answer`.

Three facts the grilling turned up, which is what changed the shape of the
question:

- **The column side already trims.** `parse_filter` does `column.trim_end()` on
  every form, so the asymmetry is trimming left of the operator and not right
  of it, rather than no trimming at all.
- **The variant `STATUS.md` proposed — trim only for the ordering operators,
  "where no value can begin with a space" — is refuted by the ordering
  register.** `Utf8View` reached by `text`/`varchar`/`char`/`name` is an
  orderable row, so an ordering literal that begins with a space is
  legitimate.
- **The hazard is narrower than the entry stated, and worse where it bites.**
  On a typed column the spaced spelling fails loudly, as
  `Error::PredicateValueDecode` before any row, naming the value. The silent
  case is a text column under `=`: `--filter 'name = alice'` looks for
  `" alice"`, matches nothing, and prints an empty result that reads as an
  answer.

**Trimming is the CLI parser's alone.** `Predicate` is a plain public struct an
embedder fills in field by field, with no library-side parse of `column=value`,
so there is no ambiguity there to repair — and trimming everywhere would make a
space-padded `char(n)` value unaskable through the API.

**Whitespace is Rust's `str::trim`**, matching the `trim_end()` the column side
already uses, so the parser holds one definition rather than two; a
non-breaking space pasted out of a web page is the case this exists for. An
all-whitespace value collapses to the empty string with no special handling.

Lands as **`P5.9`**, together with the quoting work below — not as out-of-band
work. The admission rule permitted an `M<k>`, since no spec recorded the
whitespace rule, but this changes a documented contract of the mechanism `P5.5`
and `P5.6` built, wants a notes doc that out-of-band work does not get, and P5
is open. It is a clarification of the P5 work that would have gone into the
spec had it been anticipated, and the spec now carries it: "A filter term is
parsed for two audiences". It touches `parse_filter` in
`pgdump_query-cli/src/main.rs`, the `--filter` help text, the whitespace
paragraph at the end of `architecture.md`'s "Ordering operators compare typed",
and `type-handling.md`'s filter-term line.

## Two kinds of user read the filter syntax differently

CLI feedback from real use, and the first thing pooled for the CLI-feedback
pass. **Sysadmin-shaped users find the bare `column=value` spelling natural.
SQL-fluent users assume a string literal must be quoted**, and write
`--filter 'foo = "the answer"'` — double quotes rather than SQL's single ones,
because the term is already inside shell single quotes. Today that searches for
the six-character value `"the answer"` including the quote marks, and on a text
column it silently matches nothing.

So `P5.9` supports both spellings rather than choosing between them: an
unquoted value is trimmed, and a quoted value is taken exactly as written. That
also replaces the escape the trim decision was leaning on — a value with real
leading or trailing spaces becomes expressible on the command line as
`--filter 'foo = " x"'`, so the CLI is no longer weaker than the library, and
the `char(n)` case is reachable from both.

### The quoting grammar

**Both `'` and `"` open a quoted value, matching pairs only.** Accepting one
would punish whichever half of the audience reached for the other, and from
inside the term both look equally like SQL. Which one a user picks is decided
by the shell, not by taste: the term is normally already inside shell single
quotes, which is why the feedback shows `"` even from users whose SQL instinct
is `'`.

**A quote inside a quoted value is doubled**, as SQL does it — `'it''s'`, and a
double-quoted value holding `"` doubles it the same way. Backslash escaping was
rejected because a backslash inside a shell double-quoted argument is itself
shell-processed, so the correct spelling is something nobody writes right
twice — and because doubling keeps the grammar closed, with no escape alphabet
and so no second decision about what a backslash-n or a doubled backslash mean.
Two quote characters give a lazier escape for free: a value holding `"` can be
written in single quotes, and the reverse.

**Quotes work on the column side too, and the operator split is quote-aware.**
PostgreSQL identifiers hold spaces, case and operator characters, and SQL
spells that `"my column"`; the quotes are stripped and nothing else happens,
since column names are matched verbatim and there is no case-folding to
reproduce. `split_filter_op` skips quoted regions rather than taking the
earliest operator byte anywhere, which is what makes a column named `a=b`
parse. The existing rule — earliest position, longest spelling — is unchanged
for every unquoted term, so `name=alpha>x` still parses as documented. The
`IS NULL` / `IS NOT NULL` forms get quoting for the same reason: they take a
column name and nothing else.

**A malformed quote is refused, never reinterpreted.** If what remains after
trimming outside the quotes opens with a quote, it must close with the matching
one at the very end, with every interior occurrence doubled; an unterminated
quote and trailing text after the closing one are the same error with the same
message. Falling back to the unquoted reading instead would hand a user who
mistyped one quote a value nobody meant and an empty result that reads as an
answer — the defect this whole grammar removes, in another hat. Whitespace
outside the quotes is tolerated on both sides.

**A value that opens and closes with a matching quote is quoted, always** —
there is no way to tell a SQL user quoting a string from someone searching a
`json` column for the six characters that spell a quoted `hello`, and a rule
that guessed from the column's type would make a term's meaning depend on a
schema resolved much later. The escape is the doubling rule. That case and the
`char(n)` one are the two the manual has to show, since they are where a user
needs to know the rule exists.

**Quoting stops at `--filter`; `--column` and `--table` take their names
verbatim.** Quoting earns its place in a filter term because one string has to
be split into three parts and the quotes say where the boundaries are.
`--column` has no boundary to find — the shell already delimited it — so quotes
there would be decoration that made a column genuinely named with quote marks
unaskable. The failure is loud either way, so what is added is the missing
sentence: a name that is not found and that opens and closes with a matching
quote says it was matched literally, quote marks included, and that the flag
takes the name as given. Same for `--table`.

**The `IS` forms are the fallback, not the first test.** `parse_filter` checks
for an operator outside quotes first and tries `IS NULL` / `IS NOT NULL` only
on a term that has none. That is a fix, not just a reordering: today the suffix
is stripped from the whole term before any operator is looked for, so
`--filter 'note=this is null'` parses as `IS NULL` on a column named
`note=this`. Under the new order it is an equality against the value
`this is null`, which is what it plainly says. Quote-awareness is needed on top
of the reordering rather than instead of it — that unquoted term goes wrong
with no quotes anywhere — and it is what lets `--filter '"is null" = x'` name a
column `is null`. The architecture paragraph has to say the `IS` forms are the
fallback, or the next reader restores the order that reads more naturally and
reintroduces the misparse.

## Queued: the floor check is not automated

`measure.py`'s automated gate is the counters (`contention_verdict`); the
directional floor check is read by a person off the sweep's own tables. Now
that it takes two conditions — a ~15% slow move, shared across the sweep's warm
floors — the second needs every warm floor read together, which is what a
person does worst at the end of an hour-long run. The harness has the inputs
already: `raw.json` holds every floor reading and `--drift` already re-derives
a cross-sweep comparison from two of them.

Queued as out-of-band work of its own, after `P5.9`. The shape agreed: a
computed line in the sweep's `tables.md` — each warm floor against its standing
value, the direction, and a verdict when both conditions hold — **not** a gate
that fails a figure mid-sweep, which would discard eleven good tables over a
condition that only means anything once every warm floor has been read.
