# 2026-10-16

## 36.4's refusal: attribute exactly, then rework or accept

36.4.2 left 36.4's rise unattributed and offered the maintainer three ways out:
an exact count, acceptance, or a revert. The answer is the exact count, as
36.4.3, with its reading fixed in its STATUS row before it runs. Neither
acceptance nor a revert was chosen before the rise is placed.

- **No profile taken so far rules out the key path.** The per-symbol
  sampling error is about ±300 samples (36.4.2's notes, the `observe_row`
  example). That is the size of the split between changed and identical code
  that the profile reads, so the split is unresolved. Only the total is.
- **A key-path cost of this size is plausible.** `control.sql` is one table
  of 814,379 rows and 16 columns, so the rise comes to about 38 instructions
  per field. That is more than one added branch, and about what a change in
  inlining around `stored_order`'s new `Key` match and `Option` would cost.
  The gatherer builds only `Key::Scalar`.
- **The count answers either way.** Code cost does not depend on addresses,
  so callgrind reproduces it exactly. A total callgrind does not reproduce
  depends on addresses, which is layout. A layout outcome means the
  identical-sources pair (36.1.1) could not have caught it: a rebuild of one
  source moves no heap address. `--count-pair` would then be pricing layout,
  so how it is read is reopened before another slice is counted.
- **The instrument stands.** 36.4.3 put the whole rise in 36.4's own code
  ([its notes](../../design/roadmap-P36.4.3-callgrind-notes.md)), so
  `--count-pair` is read as before. `pgdt-dump` does not depend on
  `pgdt-codec`, so 36.5 was linked to 36.4 only through that instrument.
  36.4.1 waits on 36.4's rework or acceptance, because it reshapes the
  match the count prices.
- **A cost in 36.4's own code is reworked only into a shape as clean, and
  otherwise accepted.** This phase's goal is the architecture, and the rise
  is minor. One candidate to weigh: the gatherer never holds a nested key
  and already reaches the key code through `internal`, so it could keep the
  scalar key without the wrapper's match. The amendment is the spec's "What
  a hot-path slice owes".
