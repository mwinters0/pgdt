## The v18 statistics prefix is queued, because its degradation is misleading rather than graceful

`map::parse_toc_header_line` does not recognize `TOC_PREFIX_STATS`
(`"Statistics for "`, the v18+ `--statistics` component), and the entry has
stood as a deliberate deferral on the grounds that it degrades gracefully. The
number says otherwise: `fixtures/18/objects/stats.sql` reports **TOC coverage
126/175 (72%)** where the same schema without statistics reports **126/147
(86%)**. Each of the 14 `Statistics for Name: …` entries leaves two
unattributed spans, so the one diagnostic whose job is to tell a user how much
of their file the map understood reads 14 points worse than the truth.

It stays opt-in, which is why this is out-of-band and not a slice:
`InitDumpOptions` sets `dumpStatistics = false` in both v18.6 and master, and
only `--statistics` / `--statistics-only` turn it on, so a default `pg_dump 18`
emits none and the tiling is byte-exact either way. The fix is one prefix plus
the object-census kind, the fixture exists, and no decision changes. It rides
with the 9.5 round.

## The block-count benchmark gets a script, and 9.5 gets a notes doc

**`scripts/generate_block_count_bench.py`**, taking `--blocks` and `--out`, is
part of 9.5 rather than out-of-band work: the slice's verification *is* the
500/1000/2000/4000 series, and a verification that cannot be re-run is not one.
It is a second script rather than a section in `generate_perf_data.py`, which
is documented as a single-table throughput generator parameterized by size —
the precedent in `scripts/` is one script per benchmark shape
(`generate_insert_run_bench.py`, `generate_large_object_bench.py`). The
generator inlined in [`2026-08-26.md`](2026-08-26.md) is the reproducer until
the script exists, and the `measurements.md` table cites the script once it
does.

**9.5 writes its own per-slice notes doc**, like 9.1-9.4, and the phase wrap
consolidates all five. The shortcut — writing 9.5's detail straight into the
consolidated doc because the wrap follows immediately — costs the phase's
record the moment that ordering slips, and orderings slip; the consistency
costs one file that lives briefly.

## 9.5 lands alone, and koji's wrap run doubles as the guard's only real-scale test

**Two rounds, not one.** The 9.5 round would otherwise have carried four
things: the slice, plus three out-of-band changes that have nothing to do with
each other. The slice is the one with behavioural exposure — signals, exit
codes, a rule that decides when *not* to persist — and an unattended round with
four landings offers one review surface for four unrelated risks. So 9.5 lands
alone (slice, `scripts/generate_block_count_bench.py`, `measurements.md`, notes
doc), and the three out-of-band items follow as a second round with one ledger
update between them. The metadata move is the only one with a claim to riding
along, and it does not need one: it and the throttle touch `map_forward`'s tail
sequentially, not interdependently.

**Phase 4's wrap koji run is stopped partway on purpose.** The shape most
likely to break the interrupt guard is the one no fixture can build — a signal
arriving inside a hundred-gigabyte block, against a cache already holding
dozens of completed ones. The container recipe supplies it for free, since
`nerdctl stop` sends the `SIGTERM` the guard is built to catch. So the wrap's
`--verbose` identity run is stopped partway, checked for a loadable cache
reporting partial coverage, resumed to completion, and compared against the 9.1
block/row/byte figures: the identity check and the guard's real-scale test for
the price of one extra resume. If sequencing a stop unattended proves awkward,
identity keeps priority and the interrupt test drops to fixture scale.

**The remaining Known gaps stay where they are.** Three of the five reach their
decision point through a phase inbox, which is the mechanism working. The other
two — an array inside a composite decided optimistically, and the two array
shapes that come back as text with no way to ask for more — share one fix, the
shape-general representation, which is strictly additive whenever it lands.
Pulling it into Phase 4 would mean designing a representation knob against a
census a week old.
