## Byte sizes for every column: slice 25.7

The review of 25.6's typed-only `value_bytes` turned it into slice 25.7,
admitted to P25's spec ("Same-pass gathering", "Slices") and checklist. "D91"
changes when 25.7 lands. What decided it:

- **Only storing is gated, not counting.** `ColumnGatherer::observe` adds every
  column's text length (`pgdump_query/src/gather.rs`). `close_group` keeps it
  only where `ColumnGatherer::new` saw a `Utf8View` or `Binary`. Widening it
  costs one `u64` a group per column, no work a field.
- **The cache is gathered under `SchemaMode::Typed` whatever reads it.** The
  measure is the text's, and "D91" already refuses a `bytea`'s decoded length
  for being below what a `:strings` read emits. A user whose dump holds a value
  its type cannot is on `:strings` for the whole dump, and weighed only by rows.
- **DataFusion 55's Parquet source sizes every column**: `rows × width`
  `Exact`, and everything else `Inexact` from its uncompressed Parquet size
  (`datasource-parquet`'s `compute_arrow_column_size`). A boolean, an enum or a
  nested column leaves a typed scan with no total, and `join_selection` falls
  back to rows.
- **An enum's bound holds because a batch's dictionary holds only the labels
  that batch uses** (`StringDictionaryBuilder`, `batch.rs`). So its labels
  never exceed its values' text bytes. A nested column's text is no bound:
  `{1,2}` is five bytes of text and eight of `int4`.
- **Rejected: sizing `:strings` from the stored bounds and per-type text
  widths**, which needs no bump. It needs a width table per type tracking
  `pg_dump`'s output (fractional seconds, BC dates, `infinity`), as a new
  invariant, and is looser than a count already made and thrown away.
- **Landed now, not with a later phase's bump**, since none is scheduled and
  P25 would otherwise wrap with a known hole in its own statistic.
