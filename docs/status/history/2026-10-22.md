## The zlib-ng leg, reviewed

The maintainer reviewed 15.1.1's "Decisions worth another look" entry.

- **`inflate-throughput` keeps a zlib-ng leg, and the spec's floor stays
  against zlib-ng** (`../../design/roadmap-P15-gzip.md`, "`gz-seek`'s bar is
  ours"). `zlib-rs` is `gz-seek`'s likeliest backend, so a floor set against
  it prices `gz-seek`'s overhead over its own backend and not the backend's
  choice; that `zlib-rs` matches zlib-ng at inflate is upstream's figure,
  never ours.
- **The instrument is committed without it**, at `f49fc0fb`, its two legs
  standing whatever the third's build turns out to be.
- **The leg is `libz-ng-sys`, in an apparatus member of its own**: the
  `gzip_inflate` instrument leaves `pgdt-io` for a workspace member whose
  manifest sets `[package.metadata.pgdt] apparatus`, all three backends its
  dependencies, so `D110` keeps it out of the release suite and no CI runner
  needs CMake. `mise run check` still builds it, so **CMake is a `mise.toml`
  pin**, which also installs it in the release image; this host's CMake today
  is a shim outside the project's pins. `xz_decode` stays a `pgdt-io`
  example, needing nothing beyond what ships.
- **"Nothing in the shipped build reaches CMake" becomes a check**, in place
  of the absence `M218` relied on: `release.py build` refuses a build in which
  a package of `pgdt`'s normal-dependency closure (`cargo metadata`) left a
  `CMakeCache.txt`, scoped so because the instrument's `libz-ng-sys` builds in
  the same target dir. Rejected: `ENV AWS_LC_SYS_CMAKE_BUILDER=0` in the
  Dockerfile, which forces `aws-lc-sys` 0.46.0's `cc` builder by name
  (`builder/main.rs`, `get_builder`) but guards that one crate alone.
- **`M244` admits the pin and the check, blocking P15**; 15.1.1's zlib-ng leg
  follows it.

## The spacing figure, reordered

The maintainer reviewed 15.1.1's second "Decisions worth another look" entry.

- **15.1.2 runs after 15.4, on `gz-seek`, before 15.5**, the spec's "Slice
  order" amended. Its instrument was a checkpoint-and-resume of its own — no
  backend's stable API offers one (the spec's "Facts the grilling found") —
  which is the core of 15.4; on `gz-seek` the figure times the code the
  constant ships with, and still lands before 15.5 and 15.6, its first
  readers. **`gz-seek` takes the spacing as its caller's parameter**, the
  shipped constant being `pgdt-io`'s, so 15.4 reads no value.
- **The figure prices gzip's own terms only**: the checkpointing first pass
  against a serial inflate (with `Z_BLOCK` the decoder stops at every block
  end whatever the spacing, so only the window copy scales with it), a
  resumed unit decode's fixed cost, and the window section's size. What a
  unit's size moves that xz shares — residency, the block pool, the partition
  grain — is read off figures xz already drives (`parallel-peak-rss`, at two
  block sizes), and 15.7's gzip readings check the result. Rejected: a search
  over the whole `pgdt parse` on gzip, which exists only after 15.5 consumes
  the constant.

## `M244`: CMake pinned, the shipped build checked

- **`M244` is landed** (`../../design/decisions.md`, "D111"): `mise.toml` pins
  `cmake` 4.4.3, the version this host already had, so the release image
  installs it and links it onto `PATH`; `release.py build` reads its build's
  cargo messages and refuses a `CMakeCache.txt` under the `OUT_DIR` of a crate
  `pgdt` depends on. The closure is `cargo tree`'s, not `cargo metadata`'s as
  "The zlib-ng leg, reviewed" above put it; D111's `Rejected` says why.
- **The check is shown to fire**: `runs/M244-cmake-probe/probe.sh` forces
  `aws-lc-sys` onto its CMake builder in a target directory of its own, and
  `probe.log` is its refusal; `shipped-build.log` is the shipped build passing
  it in the rebuilt image.
- **15.1.1's zlib-ng leg is landed**, the instrument moved to the
  `gzip-inflate` apparatus member with `libz-ng-sys` beside the other two
  backends; the readings are next.
