## `cargo fmt --check` is red from `2e8bd7b`, and nothing in the slice made it so

`cargo fmt --check` reports **25 diffs** across eleven files at `a8f0960`. The
first commit carrying them is `2e8bd7b` ("Renames for clarity"); `3feeaff`, one
before it, is clean under the same `rustfmt 1.9.0-stable`. So it is a rename
pass that pushed import lists and expressions past the 100-column limit and was
not re-run through `cargo fmt`, not a toolchain bump and not a disagreement with
`rustfmt.toml`.

None of it is comment prose — `wrap_comments` is off, so the humanization
commits' wording is not what `cargo fmt` would rewrite. It is import ordering
and expression wrapping in `gather.rs`, `lib.rs`, `map.rs`, `stream.rs`,
`main.rs` and six test files.

Queued as `M115` rather than fixed here: it touches eleven files that this
slice does not, and folding it in would put twenty-five unrelated reflows into
a small slice's diff ([`../../process.md`](../../process.md), "Working
unattended").

**The check a session runs is therefore already red before it starts.** Until
`M115` lands, `cargo fmt --check` is read by counting diffs against that
baseline — `cargo fmt --check 2>&1 | grep -c '^Diff in'` returning 25 is
unchanged, and anything above it is the session's own.

**`M115` blocks `P14`**, which is why its `Blocks` column names the phase. Not
because a remaining slice depends on the reflow — none does — but because the
gate every slice is landed through cannot pass while it stands. A session
reading `cargo fmt --check` against a remembered count of 25 is distinguishing
its own errors from the baseline's by arithmetic, and the unattended loop stops
on the check failing at all; so the reflow comes before 14.2 rather than after
the phase.
