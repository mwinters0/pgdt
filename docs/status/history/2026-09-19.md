## `xz-seek`'s `P9` is wrapped, and `vendor/xz-seek` is at `565135b`

The standing was reviewed here against `14.7`'s spec and approved with no ask;
upstream wrapped and keystoned on that approval, and `M122` re-synced the copy.
`cargo check --workspace --all-targets`, `cargo test --workspace`,
`cargo clippy --workspace --all-targets` and `cargo fmt --check` are green over
it, and upstream's own differential sweep is clean under both backends.

**What `14.7` composes over**, none of which existed at `6e5702e`:

- `Walk::begin(file_size) -> (Walk, Request)` with `supply`/`supply_at` and
  `Step::Need|Done` — the footer walk as a machine we drive, so the fetch is
  ours and can `await`. `Request` is `Copy` and lifetime-free, `Walk` is `Send +
  'static`, a short supply is `Truncated`, and the first request is
  `0..min(6, size)` — exactly the `ORIGIN_LEADING_BYTES` the `Origin` probe
  already holds, so the walk starts on bytes already fetched.
- `BlockTask::begin` → `BlockRead`, with `read`/`advance_to`/`complete(self)`.
  The source is a per-call argument rather than something the handle holds, so
  one call is served from a `Window` and the next from a `File`; `Send +
  'static` and borrowing nothing are asserted upstream, which is what keeps
  `KD35`'s N-handles-at-a-time possible.
- `Error::OffsetPastBlockEnd`, carrying the target and the block's uncompressed
  range in fields of its own and answering neither `compressed_offset()` nor
  `uncompressed_range()`. `XzSource::with_table` (`pgdump_query/src/io.rs`) is
  its whole route in; the one arm matching a crate variant recognises
  `InvalidTable` alone and propagates the rest, so it surfaces as `Error::Xz`.
- `Layout` — table, memory limit, verification state and backend as one value,
  built by `Builder::layout(table, size)` with no source, answering `index`,
  `index_shared`, `block_task`, `decode_footprint`, `decoder_bytes`,
  `input_chunk_bytes`, `plan_range`, `verify` and `backend`. Both memory terms a
  remote block read is charged are answerable before any byte is fetched:
  `BlockTask::compressed_range()` for the window, `decoder_bytes()` for the
  decoder over a source that lends.

**`P19.14` is unblocked**: `decode_footprint()` and `RangePlan::footprint()` are
what replace the 8 MiB constant, and they understate a stream whose later block
declares a larger dictionary (upstream's `KD10`).

**The persisted seek table is unchanged in shape**, so every cache on disk
survives the sync. `SeekTable::validate` is stricter — a check id above `0x0f`
is refused, and `Check::size` masks to the nibble rather than shifting on the
raw byte — which is a table only deserialization can produce, and ours is
deserialized.

**The growth meter counted the frozen copy** (`M123`): `repoint.py`'s tracked

`test_repoint.py` asserts, so this sync alone read as 415 lines of record growth
and turned the meter red. Filtered, the meter reads what it did before the sync.

**What `14.7` owes on our side**: `ByteRangeSource::read_range`
(`pgdump_query/src/io.rs`) has no doc comment, and upstream's "the file's end is
the machine's" decision now rests on this transport being
exact-length-or-error.

## `14.7`'s two unattended calls, reviewed

Both entries under STATUS's "Decisions worth another look" were put to the
maintainer and **affirmed**, each on a reason other than the one the landing
session gave. The calls stand; the record around them moved.

**The walk is announced on the status channel, and D1 is corrected to say so.**
A `Diagnostic` hangs off a `DumpIndex` or a `CacheStatus`, both built from a
source that already exists, so it cannot arrive before the walk it describes —
which is the whole value of the line. The entry defended this on the ground
that a cost depending on cache state is "not a property of the file that a
*persisted* `DiagnosticKind` can hold"; **that premise is false** —
`DumpIndex::diagnostics` is `#[serde(skip)]` and recomputed on load
(`pgdump_query/src/diagnostic.rs`, module header, citing D34). The two channels
divide by **kind**: `tracing` carries cost and progress as a run meets them, a
`Diagnostic` a structured finding about the file. That division is now stated
at `crate::diagnostic`'s module header, whose founding sentence — "the library
cannot `eprintln!`" — had been false since D64 gave the library a status
channel, and was the sentence a later session would have read to conclude that
anything user-facing must be a `Diagnostic`.

**So the stream count is owed to the diagnostic channel too** — it is a
property of the file, exactly as the block count behind
`NonSeekableCompressedSource` is, and that one is pushed on warm loads from
`cache::status_from_file` as well. A caller draining diagnostics, `pgdq info
--json` among them, currently learns nothing about a walk it paid for or a
cache it should keep. Admitted as `M124`; it blocks nothing.

**A fetched `.xz` keeps `default_workers = 1` because the errors are
asymmetric**, not because the phase defers network tuning. Recommending too few
costs throughput a caller takes back with `--jobs`; recommending too many opens
`min(cores, block_count)` concurrent connections to a *third party's* server for
a command carrying no flag that says so. Filed beside
`FetchedXzSource::default_workers`, because it is what should stop a later
reading showing the link underused from raising the number — that reading argues
for raising `--jobs`. The deferral reason was too weak to do that work: by it,
`partitions()` would also have stayed at one, and it did not.

Two facts found while checking the entries, neither a defect: D7's
`default_workers = 1` rests on two joined reasons, and only "concurrency here is
tuning" survives onto a source that *has* block structure — the plain remote
source it governs is untouched, so D7 needed no amendment. And `KD35`, which
D20 speaks for, was not stranded by `14.7` taking `KD36`: it carries its marker
at `pgdump_query/src/io.rs` and `deficiencies.py` resolves it.

Five blind readers, one per module group, against the record lines naming each.

moves to `bc7cbba`. What is worth knowing beyond the diff:

default cache path was given as `./mydump.dqcache` for
`…/mydump.sql`; `remote_name_of` keeps the segment verbatim and

below already said. Four help snapshots moved with it.

**Two comments in `map.rs` contradicted each other** about whether a blank line
closes a pending comment block. `feed_line`'s said it does; `step`'s says it
does not, and `on_copy_start` depends on it not doing so (I3).

Nothing exercises the fourth — said now at the test rather than asserted.

**Listed, not corrected — `measurements.md` has drifted from its own
