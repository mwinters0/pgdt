# 2026-09-07

## Decode scaling bends well before 24 workers, and the thesis table's worker counts are floors

`P16`'s thesis table
([`roadmap-P16-parallel-scan.md`](../../design/roadmap-P16-parallel-scan.md),
"The thesis") extrapolates a probe linearly: one core decodes ~446 MB/s of
plaintext, four reach ~1.48 GB/s, therefore *~12 fused workers reach the HDD's
4,656 MB/s offer* and *~17 reach it for a typed query*. `16.1` built the
instrument that turns the probe into a measurement, and both probes reproduce —
~431 MB/s at one worker on real koji bytes, ~1.48 GB/s at four. The
extrapolation past them does not: on koji's bytes the curve flattens to about
7.8× one worker at twenty-four, with the twenty-fourth worker buying essentially
nothing over the sixteenth.

**What that changes is the arithmetic, not the conclusions.** Decode is still
far below every device's offer, still the stage worth parallelizing, and the
fused worker is still self-balancing for the reason the spec gives — the ratio a
split pool would need is a property of the command. What it changes is that the
worker counts the table names are **floors on what will be needed** rather than
estimates of what will suffice, so the slices that price parallelism read the
figure and not the table.

The reasoning and the mechanism are beside the slice:
[`roadmap-P16.1-xz-decode-scaling-notes.md`](../../design/roadmap-P16.1-xz-decode-scaling-notes.md).

## The figure is built, taken, and deliberately not published

`measure.UNTAKEN` carries `xz-decode-scaling` and
[`measurements.md`](../../design/measurements.md) carries no table for it. That
is not an unfinished fold-in; it is the one thing the sitting could not honestly
do.

A figure published outside a stamped sweep declares the commit it was taken at
inside its own marker, and `--stale`, acknowledgement spentness and
`--verify-additive` each argue from that commit. This sitting ran from a working
tree carrying the instrument, its generator and its register entry
**uncommitted**, so no commit exists that both contains them and could be named:
the parent names a tree where the instrument does not exist, and a marker
pointing there would report the figure stale against the very commit that lands
it — red with no explanation, which is the state
[`measurements.md`](../../design/measurements.md)'s staleness rules exist to
prevent, and which no acknowledgement can excuse, since an acknowledgement
asserts that a commit moved no reading and this one *created* the reading.

So the sitting was taken under `--alone`, which marks its tables NOT
PUBLISHABLE, and the readings live in `runs/`. Taking it for the document is
`cd scripts && uv run measure.py --figure xz-decode-scaling` on the commit that
lands the slice: minutes, not the hour a sweep costs. Folding it in also
replaces the session stamp's accounting sentence, which `--check` prints
verbatim, since the register goes from 18 figures to 19.

## koji has no compression ratio, it has a range — so a decode rate is quoted with its density

The koji leg's offset was raised under "Decisions worth another look" as a call
worth review, and the review found the offset defensible and its *justification*
wrong. Sampling eight streams at twelve depths — a seek and ~10 MB each —
profiles the download as anything but homogeneous:

| offset | ratio | | offset | ratio |
|---|---|---|---|---|
| 0 G | 33.05× | | 20 G | 15.89× |
| 2 G | 25.56× | | 24 G | 15.23× |
| 4 G | 27.15× | | 28 G | 11.50× |
| 8 G | 28.15× | | 32 G | 16.83× |
| 12 G | 31.74× | | 36 G | 22.88× |
| 16 G | **5.02×** | | 39 G | 24.10× |

The whole file is 19.41× and the chosen slice 15.70×, which the slice notes had
called "the file's own neighbourhood". It is not one: koji's regions differ from
each other by 6.6×, so no offset is representative and the sentence was deleted
rather than softened.

**What settles it is that the figure's own two legs measure the effect.** The
control at 5.4× decodes ~200 MB/s on one core where koji's 15.70× decodes ~431,
so density drives the absolute rate hard — and the control therefore sits on top
of koji's *densest* sampled region (5.02× at 16 G) rather than being merely
"the synthetic leg". The two legs bracket the corpus. Three consequences, all
folded in: the scaling curve is what the figure publishes and an absolute rate
is always quoted with the density it was taken at; a third koji column is
refused, because leg one already spans the spread; and the slice's ratio is
gated to 14–18× rather than remembered, since a moved offset or a refreshed koji
could republish a rate for 31× bytes under the same heading — the plausible-table
failure the instrument already refuses twice.

The offset itself did not move. The decision is beside the mechanism
([`architecture.md`](../../design/architecture.md), "The compressed source") and
the profile is beside the slice
([`roadmap-P16.1-xz-decode-scaling-notes.md`](../../design/roadmap-P16.1-xz-decode-scaling-notes.md)).
