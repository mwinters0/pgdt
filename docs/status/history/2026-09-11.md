# 2026-09-11

## `M80`: help text is not wrapped, and nothing looked

`clap` wraps help text at **no width at all** without its `wrap_help` feature —
not the terminal's, not `COLUMNS`. Every flag's help here is the rustdoc above
it and most of those are paragraphs
([`../../design/architecture.md`](../../design/architecture.md), "A flag's help
is its doc comment, citations included"), so the four commands printed single
lines up to **748** columns. A terminal hard-wraps those mid-word with no
hanging indent, which destroys the option-list alignment a help page is read by.
The feature is now on; the width is the terminal's, falling back to `COLUMNS`
and then to `clap`'s own 100 columns.

It survived every session that wrote one of those comments because the rendering
is invisible from the source: nothing under `pgdump_query-cli/tests/` rendered a
help page, so no artifact anywhere showed what a reader sees. `tests/help_text.rs`
now holds all eight pages — both depths of the root command and of the three
subcommands — at a stated `COLUMNS`, so a wording change puts the rendered
result in front of a reviewer.

**Two properties are asserted beside the snapshots rather than left to them**,
because a snapshot of a broken page is exactly as plausible as a snapshot of a
good one: no line exceeds the width, and no flag renders with nothing beside it.
Both were verified to fail by reintroducing the defect. The second found one:
`pgdq info --detail` had no doc comment at all and printed as a bare spec in the
option list. Its help is written from the manual's own description of the flag.

**It went ahead of `19.11`.** `pgdump_query-cli/Cargo.toml` is a declared
`depends` path of the `allocator` and `rss-attribution` figures, so landing a
feature change after the closing sweep would put `rss-attribution` — the figure
that sweep exists to publish, closing `M74` — stale on its first outing. Landed
here it adds no red that is not already there: `uv run measure.py --stale`
reports both paths this change touches as already held red by earlier commits,
and `19.11`'s sweep republishes them.

## Closed: whether `--help` should be split from rustdoc

Raised by `19.10`, reviewed the same day, and the call was affirmed: a flag's
help stays its doc comment, citations and emphasis included. The reasoning is
filed beside the mechanism ([`../../design/architecture.md`](../../design/architecture.md),
"A flag's help is its doc comment, citations included"), including both
rejected alternatives — a `long_help` per flag, and help rewritten as the
manual's abstract.

Three facts the entry had not established, and the first reframed it:

- **`clap_derive` already splits the text by depth.** The first paragraph of a
  doc comment is the short help `-h` prints; the whole comment is the long help
  `--help` prints. The unserved split was help against rustdoc, not short
  against long.
- **The leakage is not confined to `--help`.** `-h` already prints a citation on
  `--preamble-only` and `--chunk-size`, and `pgdq --help`'s subcommand list
  prints `**bold**`.
- **Help-and-manual duplication was already the accepted shape**, on the record:
  a raised chunk size's whole cost is deliberately stated in the flag's help, in
  the manual and in `DEFAULT_CHUNK_SIZE`'s doc comment. So the alternative's
  duplication cost was not a new one being introduced — which is what made
  `19.10`'s own three falsified manual sentences the decisive argument against
  paying it twice over.

One rider considered and dropped: citing a measurement by figure id rather than
by heading. `citations.py`'s id form is `<!-- section: <id> -->`, which exists
only in `architecture.md` and only on four profile sections;
`measurements.md`'s `<!-- figure: <id> -->` markers are a different register
that citations never address. No help-text citation names a finding-quoting
heading in any case.
