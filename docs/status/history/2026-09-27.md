## 27.5 evaluates a dynamic filter's rows in every block

Settled with the maintainer, reviewing STATUS's "Decisions worth another look":

- **Row-level evaluation runs in every block a sub-stream reads**, statistics or
  not, and under `use_statistics: false` too, which governs consulting
  statistics, and row evaluation consults none. The condition 27.5 built —
  evaluate only where `DynamicPruning` exists — is dropped.
- **Why.** `DynamicFilter`'s "drops nothing on its account where the query does
  not use statistics" was 27.3's description of pruning's precondition
  (`7f5002d`), not a requirement; the spec's "Scope", item 3, states no such
  condition. The blocks it exempts are a `--statistics none` cache, a block
  that declined ("D85"), statistics not believed, and every block past `KD33`'s
  prefix — on a long dump, the tail, where row evaluation has most to save. A
  join's state is final at the probe's first poll (the spec, "Facts found while
  grilling"), so how often the state is read bears only on a TopK's or an
  aggregate's.
- **The state is read at each chunk the replay takes, in every block**, as well
  as at each group entry, wherever the generation has moved. Per row is refused
  (a read lock per held filter per row, on a line every partition shares); per
  output batch, upstream's cadence, is refused because here the filter runs
  before the batch fills, so a state would age with its own selectivity; group
  entry alone is refused because merged groups on a long block make a state
  older where statistics exist than where they do not. So it lands before the
  readings, changing the TopK figure's path.
- **A state read mid-group acts as one read at entry does**: the current group
  is judged again, and the rest of it skipped with every later group the state
  rules out, a group still kept being re-armed under it. Otherwise when a state
  was read would decide what its proof saves.
- **Landed ahead of 27.5's readings**, the cadence and the mid-group rule
  filed as "D93"; the readings are what remains of the slice.

## 27.5's readings reopen "D53" for a set-membership term

Settled with the maintainer, reviewing STATUS's "Decisions worth another look":

- **`dynamic-filter-join` and `dynamic-filter-topk` are taken at `28e804f`**
  (`measurements.md`, "What DataFusion's dynamic filters buy a query"; raw
  sitting `runs/measure-20260927T200534/`). Both wins are group pruning; row
  evaluation acts alone on the unclustered join and the costing input and
  loses on both, in proportion to the `IN`'s terms.
- **The answer is a set-membership term, reopening "D53".** Each `=` of the
  `Or` fetches and decodes its field again (`predicate::ResolvedTerm::eval`),
  so a row pays per term; one term finding and decoding its field once and
  answering by one lookup makes that constant in the list's length. Its
  default is still decided by re-taken figures, the term's cost being a
  prediction from the code until then.
- **No `pgdump.*` switch.** "Two tunables" refuses a default right only once a
  third knob is turned, and DataFusion's own
  `enable_{join,topk}_dynamic_filter_pushdown` is already the user's switch.
- **No adaptive evaluation**, a stream ceasing to evaluate a filter that
  rejects nothing: the flag on is the user's explicit request, and an
  explicit request is never ignored ("D77"'s rule). Both refusals are "D93"'s.
- **Every `IN` uses the term**: both DataFusion translators and `pgdt
  --where`, which gains `in (…)`. "D53" is the library's operator set, so a
  front end still spelling `IN` as `Or` would keep its refusal alive there.
- **The term is a leaf of its own, `Expr::In`**, proved against the `Or` of
  `=` by a generated check; a resolver recognizing that `Or` is refused by
  "D54". The spec's slices 6 and 7 carry both.
- **27.5 is ticked at what it delivered**, and the term is admitted after spec
  time as **27.6**, the library term and `pgdt`'s `in`, and **27.7**, the
  translators and the re-take, sized by review: a predicate change, then a
  translator change with the evidence it moves. 27.5 shipped its contract, so
  no third level is earned. Evaluation stays on until 27.7's readings.
- **The criterion is set before the readings**: on only if the unclustered
  join wins with its legs' spreads apart and the costing input's Δ lies inside
  its legs' overlapping spreads. Failing it, evaluation goes off and a switch
  is reconsidered, the maintainer being open to one where no universal win
  can be shown ("D93", **Reopens**).
