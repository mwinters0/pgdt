## Seams: a dump's databases, in the model

Two concepts of the declared schema were scattered (`docs/process.md`, "Seams"). A database's DDL by name was
`pgdt-codec`'s `database_for_name`, the `KD133` marker's site, and four inline copies past it (pgdt-model's
`timescaledb/catalog.rs` and `findings.rs`, pgdt-mapping's `stored.rs`, `pgdt`'s `info/logical.rs`), so a fix there
would miss them. The databases a dump holds were walked three times: `info/logical.rs`'s `databases` and `findings`'
copy of it, and pgdt-query's `Dump::databases`. Both are model vocabulary (D74), so both move to pgdt-model:
`DumpMetadata::database` beside the declared schema it reads, carrying `KD133`, with `DumpIndex::ddl` over it; and
`DumpIndex::databases`, beside `blocks_with_database` — each database the DDL names, then any a block holds rows in,
so an unnamed one only where a block is in it, which `Dump::databases`, `findings` and `pgdt info` all read.

```moves
pgdt-codec::resolve::database_for_name -> pgdt-model::catalog
pgdt::info::logical::databases -> pgdt-model::span
```

Landed whole, one cut. `pgdt info`'s TimescaleDB section now counts databases as the map does: one any block is in,
not only its catalog blocks, so a plain dump's segment ahead of a `--create` TimescaleDB dump makes the section name its
database; a plain dump with no block counts none.
