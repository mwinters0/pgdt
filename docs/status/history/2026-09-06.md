# 2026-09-06

## P13's blocker is discharged: a positioned read over `.xz` exists

The decision to vendor an unpublished decoder
([`architecture.md`](../../design/architecture.md), "The compressed source";
written that day into the phase spec's D9, and into its now-struck "Blocked"
section before that) rests on a survey concluding that no crate answers
`read_range(offset, len)` over an `.xz` file.
That is no longer the case. `xz-seek` — the crate carved out for it, at the path
`CLAUDE.local.md` records — ships `Reader::read_at`, held to `xz -dc`'s own
output over 531,684 `(offset, len)` pairs on its fixture corpus under every
backend it compiles, and confirmed over both koji files including `xz -dc | cmp`
across all 730 GiB the 40 GB file decodes to.

The three properties P13's decisions need are all present: the exact
uncompressed size from the stream index (D1), a `SeekTable` that is a plain
value handed out and taken back with no re-walk, behind a `serde` feature (D5),
and compressed bytes arriving through a caller-supplied trait rather than a file
the crate opens (D3's composition, and P14's).

**P13 needs serial decode only.** D6 is one streaming decoder restarted on seek,
and it hands parallel decode to P16 explicitly. So `xz-seek`'s own `P3`
(parallel block decode) is not on P13's critical path — its consumer is P16,
which has no spec.

**What this leaves for P13's grilling**, which is now the next thing this phase
needs: the "Blocked" section is false and comes out; the roadmap index row's
caption goes with it; and the phase's remaining decisions — how a source is
recognised as xz, the diagnostic that announces a non-seekable file, the
fixtures, the figures owed, and the slice list — are still ungrilled, as that
row already says.

## What `xz-seek` was told, and what it commits us to

That crate's `P3` grilling stopped at questions only its first downstream could
answer, and put them to this project in two rounds — eleven about the interface,
then eight more once those were folded in. They were answered as `pgdump_query`
rather than as a neutral reviewer, which is what was asked for. The answers
themselves are machine-local and uncommitted, beside the questions
(`CLAUDE.local.md` names the directory); what belongs in the tree is the part
that binds phases here, and it is filed by destination:

- **P16's inbox** — the decode pool is `xz-seek`'s and the pieces are what that
  phase probably wants; the memory bound it must promise is in bytes; ordered
  delivery was asked for and the unordered case routed to the pieces on purpose;
  the decode/consumer rates say the pool suits `parse` and not `query`; and
  whole-block decode makes the retained unit a block rather than a chunk, which
  the byte budget does not count.
- **P14's inbox** — the fetch policy over a remote source is that phase's to
  own, the crate ships no knob for it, and the sync/async seam bites there and
  nowhere else.

**One round-one answer was withdrawn in round two**: the fetcher-count parameter
asked for on P14's behalf. Two things removed it — a correction to the crate's
evidence (the 249.6 MB/s reading was one thread issuing *block-sized* reads in
file order, so coalescing has nothing measured to buy on a spindle), and the
recognition that a fetcher inside a synchronous crate reaches an async object
store only by blocking on a future from a blocking thread, so a count multiplies
parked threads rather than removing them. What replaces it is the public
pre-fetched window, which hands P14 the whole fetch policy. The one thing asked
for in its place is a promise that the single fetcher walks blocks in ascending
order, without which a prefetching source cannot anticipate it.

Four answers bind P13 instead of a later phase, and they are inputs to its
grilling rather than decisions taken here:

- **Delivery is repeated fill** — `read(&mut buf) -> Result<usize>`,
  fill-or-EOF — because that is what the three read loops already are, and
  because an iterator of owned chunks would reintroduce the per-chunk `calloc`
  the buffer pool exists to remove *and* hand the query path 24–128 MiB buffers
  to retain behind Arrow string views that address a few kilobytes of them.
- **The boundary is blocking, wrapped here**, matching what
  `io::LocalFileSource` already does and leaving the runtime the binary's
  choice. An async API inside `xz-seek` was refused outright.
- **Verify-before-return is wanted as the bulk path's default.** This is the
  answer with the most force behind it: a scan persists the structure it
  discovers into the cache as it goes, so bytes whose check fails two calls
  later have already been recorded as fact and nothing re-examines them. The
  crate's seeking path keeps the weaker default, which matches `xz -dc`; the
  bulk path can afford the stronger one because it decodes each block whole
  anyway. On failure: bytes valid up to the fault, with the uncompressed offset,
  because that is the coordinate space this project's whole index lives in.
- **`SeekTable` gains `blocks_in(range)`.** D2 already commits this project to
  announcing a non-seekable container when it is discovered rather than letting
  a user meet it as a stall; the block count over a range is that warning with a
  number in it, and the same remedy attached.

**Contingent on `xz-seek`'s `P3` landing as specified.** The answers were given;
nothing is built against them.

## `xz-seek` is not published until this repo has integrated against it

Settled by the maintainer. **This project is `xz-seek`'s first real-world
consumer, and that consumption happens before publication, not after.** The
crate's interface is vetted by being used — bugs and shape changes shaken out
locally, against a caller with a cache format, an async trait and a 512 MB
cgroup — rather than frozen into a published version and then discovered. The
gate is both phases complete, P10 and P13, with the shape questions resolved;
publication and a proper versioned dependency follow.

**The mechanism is a frozen copy of the crate inside this repo, committed** —
not a path dependency pointing at the sibling working tree. The distinction
decides whether the repo stays self-contained. A path dependency is resolved
when the dependency graph is built, **not** when a feature is activated, so an
optional `xz-seek` behind an off-by-default feature does *not* rescue a checkout
lacking the sibling repo: `cargo check` fails with `failed to read
…/Cargo.toml` before features are considered. A committed copy has neither
problem, and it also decouples this build from the state of a tree that is still
iterating — which is the arrangement's purpose, since `xz-seek` continues
through its own `P3` while this phase runs.

The copy is a **snapshot, never a fork**: read-only, stamped with the commit it
came from, re-synced by script when `P3` lands, and replaced by a versioned
dependency at publication. That discipline is what answers the standing
objection to vendoring — that it creates a second authority over the source.
The mechanics, including the manifest transformation the copy requires and the
C-toolchain consequence of the default `liblzma` backend, are in
[`../../design/architecture.md`](../../design/architecture.md), "The compressed
source" (filed at this phase's grilling as the spec's D9; the inbox this was
first written into had already been drained and deleted, and the spec went at
the phase's keystone).

Publishing early was the alternative and is rejected on the ground that
publishing an interface nobody has consumed is what produces the 0.x churn it
was meant to avoid.

## The wrap audit: the seek table is persisted and never read back

The wrap's audit of what the slices learned against
[`../../design/architecture.md`](../../design/architecture.md) turned up one
thing that was a gap rather than a filing job. D1 promised that the seek table
would be "persisted in the cache, so only a source with no usable cache ever
pays for" the stream-footer walk. Persisting had landed and reading back had
not: `cache::save` recorded the table through `ByteRangeSource::seek_table()`
and `cache::load` round tripped it, while `XzSource::open` walked the footers
anyway, because nothing constructed a reader from a cached table. The decoder
crate supported that construction; this tree never called it. `M61` closed the
gap the same day; the mechanism as built is below.

**No slice is unfinished by its own row.** 13.3 owed the source and the seek
table's content, 13.4 owed recognition and the diagnostic, and neither row
mentioned consuming a persisted table — 13.3's and 13.4's notes both named the
optimization and left it unclaimed, each pointing at the other or at P14. The
gap is between the spec's prose and what the five rows between them covered,
which is exactly what an audit at the wrap is for and what a checklist cannot
see.

What it costs is bounded and lopsided by container shape: a single-stream file's
walk is one read whatever its size, while the koji upstream download's 31,150
concatenated streams cost **85 s** of HDD seeks, on every command, however
complete the cache is. So it is a real cost on the one file that motivated the
phase and nearly free on the shape a user gets by compressing in one go.

Filed as `KD15` and **owned by `M61`** in the out-of-band ledger. The maintainer's
answer, given at the keystone, is that this belonged inside the compressed-input
work and would have been a slice of it had the gap surfaced before the wrap;
since that phase had closed, the remedy is an out-of-band item rather than a
reopened phase. It qualifies as one on both halves of the admission rule — it
changes no decision the spec recorded, it *delivers* one, and the fix is located
enough to fit a session: recognition already decides which source to build, so
it is the layer given a loaded cache to consult, and `open_local`'s signature is
what that moves. `Blocks` is empty because no phase is open.

The audit's own filing stands beside it: detail beside the mechanism
([`../../design/architecture.md`](../../design/architecture.md), "The compressed
source"), an entry in
[`../../design/roadmap-P14-remote-input-inbox.md`](../../design/roadmap-P14-remote-input-inbox.md)
because the walk is that phase's worst latency case, and a caveat in
[`../../manual/dump-inspection.md`](../../manual/dump-inspection.md) because a
user meeting a minute per command deserves to have been told.

**What the unowned filing got wrong is worth keeping.** The audit read "nobody
holds the intent" off the artifacts — no phase's checklist claimed the work, so
`(c)` looked like the honest resting state. What the artifacts could not say is
that the phase would have claimed it had it known, which only the maintainer
could supply. A wrap audit that finds a spec promise half-delivered should
surface it as a question rather than settle the stance itself; `(c)` is a
resting state for a defect nobody wants, not for one whose owner has simply
finished.

## The seek table is read back, and a claim the file contradicts condemns the cache

`M61`, closing `KD15`. The walk the audit above found being paid on every
command is now paid by the command that first parses a file and by nothing
after it. The mechanism is beside the mechanism
([`../../design/architecture.md`](../../design/architecture.md), "The compressed
source"); what belongs here is the reasoning that produced its shape.

**The claim recognition is handed is three-state, not an `Option`.**
`cache::known_compression` answers `Unknown`, `Plain` or `Xz(table)` before any
source exists, and `open_local` takes that instead of deciding alone. An
`Option<SeekTable>` was the obvious parameter and loses one case: "the cache
says this file is plain" is a claim the file's own magic can contradict, and
folded into "nothing is known" it would leave a cache written from a *different*
file at that path silently believed for its span index while its absent
compression layer went unchecked. Three states cost one enum and catch both
directions of the same fault.

**A condemned cache survives the second pass, which is what decides `parse`'s
branch.** The design already said a rejected table condemns the whole cache,
table and span index having been one `save`; what it did not say is that
`map_file` goes on to call `CacheMode::load`, whose identity check the condemned
cache still passes — so nothing downstream would stop a scan resuming from a
span index recognition had just refused. Extending `load` to cross-check the
envelope's compression against the live source's `seek_table()` was the
alternative and was refused: the design says `load` is unchanged for that pass,
and the cross-check would put the same verdict in two places. What answers it
instead is `parse` refusing at startup, beside `info` and `query`, which is
`P17`'s rule reaching this path ([`../../design/architecture.md`](../../design/architecture.md),
"The cache").

**All three commands refuse rather than walk, and the condition has a sentence
of its own.** None of the four `CacheStatus` sentences fits it. `SourceChanged`
reads as right and states its own refutation: it quotes the two stored sizes as
evidence, and reaching this point means they are equal — the envelope's identity
check passed. `Unreadable`'s "… is not a pgdq cache — check the path, or run
`pgdq parse --source X`" was borrowed while `parse` still rescanned, and P17.3
ended the borrow: once `parse` refuses, its remedy names the command that just
refused, and the bytes at that path *are* a pgdq cache, for another file
([`../../design/architecture.md`](../../design/architecture.md), "The CLI's two
refusals are worded as one"). The refusal also makes `query` refuse a cache for
the first time; it tolerates every other unusable cache by rescanning, and this
one it cannot, because the alternative on the file that motivated the phase is
85 s of footer seeks followed by a full scan the user did not ask for.

**The saving is tested by making a silent walk succeed where it should fail.**
`xz_seek::SeekTable::validate` is strict enough that almost any corruption is
refused outright, which proves the table was *consulted* but not that it was
*used*. The one field validate does not police is a stream's declared check
algorithm, and a walk would never get it wrong: hand the constructor a table
naming `Crc32` where the file's streams are `Crc64` and a read must fail, where
a source that had quietly re-walked would read the payload back happily. The
end-to-end half is a CLI test that overwrites an `.xz` fixture with plain bytes
of exactly the same length, which is the only arrangement a user can reach that
puts a cache's compression claim and a file's content into contradiction while
the stored-size identity check still passes.

**Two facts went to P14's inbox** and its entry was rewritten around them,
since half of what it asserted is now built. The identity check on the load
path is a `stat` on the dump *path*, and recognition sniffs the magic with a
small read from the path rather than through a `ByteRangeSource` — both are
local-file assumptions sitting on the warm path a remote source has to take.

## The size-mismatch refusal still walks an `.xz` file's footers first

`M62`, admitted and not landed. A `parse`/`info`/`query` against an `.xz` file
whose cache records a different stored size pays the stream-footer walk — 85 s
on the koji download, one read on every other shape — before the refusal, and
everything needed to refuse is on disk before the walk starts.

The path is `open_with_cache` → `cache::known_compression`, which compares the
envelope's stored size against a `stat` of the dump, sees them disagree, and
answers `KnownCompression::Unknown`; `open_local` then walks the file, and
`map_file` refuses in a millisecond. `known_compression` collapsing *every*
unusable outcome to `Unknown` is deliberate — it hands over knowledge or it does
not, and the pass behind it reports why through `load`
([`../../design/architecture.md`](../../design/architecture.md), "The compressed
source"). What P17 changed is that the pass behind it now refuses, so for this
one outcome the collapse throws away an answer nothing downstream can use
cheaply.

It is out-of-band rather than a P17 slice: no decision P17's spec records says
where that answer is read, and no slice of the phase is built around it — hence
an empty Blocks column. What it will have to decide is where the fact lives.
Widening `KnownCompression` is the wrong place, `io.rs` naming nothing in
`crate::cache` by rule; a sibling of `known_compression` answering the cache's
recorded stored size, or a richer cache-level return that `open_with_cache`
narrows, are the two shapes in view.

## P17 is wrapped

All three slices landed, the checklist is gone and the index row reads
`Complete`. No `(b)` register entry named the phase, so nothing was re-homed and the
deficiency register is unchanged. No phase is open.

**The audit found one claim the phase had falsified and left standing.**
`architecture.md`, "The compressed source" said that rejecting a seek table
reads no bytes, "which is what keeps a changed `.xz` from spending its footer
walk to reach an error it was always going to reach". That is true of the
condition it describes — a compression claim the file contradicts — and false of
the *changed* file it reaches for as the example: a stored-size mismatch answers
`KnownCompression::Unknown`, so the walk is spent and only then does the library
refuse. It was written while `M61` was the newest thing in the section and P17
had not yet made the second condition a refusal at all. The two refusals are now
separated there, with the cost and `M62` named beside the one that still pays
it.

**Three mechanism facts had not reached the subject-filed doc**, all of them
about where the refusal gets what it says: that the path comes from
`CacheMode::source_mismatch` rather than from `CacheLoad`, which carries none
because `Disabled` has none; that `open_with_cache` answers a source or bails,
only `CacheMode::Enabled` being able to claim anything about the file; and that
the guarantee is asserted by reading the cache file back byte for byte, a
refusal that wrote anyway being indistinguishable from one that did not by
every other assertion available.

Two decision-letter references into phase specs went at the same time — one to
P13's `D2`, dangling since that spec was struck, and one to P17's `D7`, which
would dangle at the next keystone.

**`M62` earned no `KD<k>`, deliberately.** It is a defect with a known fix and a
named destination, which is the `(b)` stance's shape, but the ledger row is that
destination; a register entry would put a second index over one queued item.
What the register exists to guarantee — that a session touching the mechanism
meets its limitations — is bought instead by the fact sitting in "The compressed
source" beside the refusal it qualifies.

**One fact went to P14's inbox**: the mismatch payload names two `u64` sizes, in
the `CacheLoad` variant and in `Error::CacheSourceMismatch` alike, and a remote
source identified by an ETag has no two sizes to quote. That phase's existing
entry says a `Remote` identity variant is an added match arm rather than a
redesign; at the refusal it is not, and deciding it late means deciding it
inside a message a user reads.

## The keystone: a partial ledger strike, and the one thing that had no subject-filed home

Striking the cache-replacement work's centering had almost nothing to distil.
The wrap audit had already filed the mechanism by subject — the rule, the
five-arm `CacheLoad`, where the refusal's path comes from, the four refused
alternatives and the byte-for-byte assertion — and the sweep found no citation
of the spec anywhere in the tree outside the two rows that named it. Today's
history sections were already written against `architecture.md` rather than
against the spec, so the same-day rule two sections above fired and found
nothing to repair.

**The ledger strike is the first partial one, and the watermark sentence had to
change shape for it.** `M61` had landed and its row was provenance; `M59`, `M60`
and `M62` have empty Date columns and are live obligations that keep their
numbers. So the struck set is no longer a range — `M1`–`M58` and `M61` — while
the reuse floor moved to `M62`, which is the highest number spent rather than the
highest struck. The two are different quantities and the old sentence stated them
as one, which was only ever true because every keystone before this struck a
contiguous tail. `M61`'s one citation, in P14's inbox, was repointed at the
history section that says why rather than at the number.

**One finding had no subject-filed home, and it was split rather than forced
into one.** Reversing a decision already implemented at several sites was cheap
because the slice before it replaced `Option<DumpIndex>` with a five-arm
`CacheLoad` and changed no behaviour at all — so the reversal was one arm at each
of three exhaustive matches, and "is there a scan entry point we missed" was
answered by the compiler rather than by a search. The half that is about *this*
mechanism went beside `CacheLoad` in
[`../../design/architecture.md`](../../design/architecture.md), "The cache". The
half that is about *slicing* — that a phase reversing an implemented decision
should land its make-the-sites-enumerable slice first, reviewable on a yes/no
question — was deliberately **not** written into
[`../../process.md`](../../process.md). That doc's one named seam earned its
paragraph over eight instances and says so; this is one, and a rule added on a
single instance reads as complete while resting on nothing. It is raised for the
maintainer instead, to be written if a second phase meets the same shape.
