# 2026-09-06

## P13's blocker is discharged: a positioned read over `.xz` exists

The decision to vendor an unpublished decoder
([`architecture.md`](../../design/architecture.md), "The compressed source";
written that day into the phase spec's D9, and into its now-struck "Blocked"
section before that) rests on a survey concluding that no crate answers
`read_range(offset, len)` over an `.xz` file.
That is no longer the case. `xz-seek` — the crate carved out for it, at the path
`CLAUDE.local.md` records — ships `Reader::read_at`, held to `xz -dc`'s own
output over 531,684 `(offset, len)` pairs on its fixture corpus under every
backend it compiles, and confirmed over both koji files including `xz -dc | cmp`
across all 730 GiB the 40 GB file decodes to.

The three properties P13's decisions need are all present: the exact
uncompressed size from the stream index (D1), a `SeekTable` that is a plain
value handed out and taken back with no re-walk, behind a `serde` feature (D5),
and compressed bytes arriving through a caller-supplied trait rather than a file
the crate opens (D3's composition, and P14's).

**P13 needs serial decode only.** D6 is one streaming decoder restarted on seek,
and it hands parallel decode to P16 explicitly. So `xz-seek`'s own `P3`
(parallel block decode) is not on P13's critical path — its consumer is P16,
which has no spec.

**What this leaves for P13's grilling**, which is now the next thing this phase
needs: the "Blocked" section is false and comes out; the roadmap index row's
caption goes with it; and the phase's remaining decisions — how a source is
recognised as xz, the diagnostic that announces a non-seekable file, the
fixtures, the figures owed, and the slice list — are still ungrilled, as that
row already says.

## What `xz-seek` was told, and what it commits us to

That crate's `P3` grilling stopped at questions only its first downstream could
answer, and put them to this project in two rounds — eleven about the interface,
then eight more once those were folded in. They were answered as `pgdump_query`
rather than as a neutral reviewer, which is what was asked for. The answers
themselves are machine-local and uncommitted, beside the questions
(`CLAUDE.local.md` names the directory); what belongs in the tree is the part
that binds phases here, and it is filed by destination:

- **P16's inbox** — the decode pool is `xz-seek`'s and the pieces are what that
  phase probably wants; the memory bound it must promise is in bytes; ordered
  delivery was asked for and the unordered case routed to the pieces on purpose;
  the decode/consumer rates say the pool suits `parse` and not `query`; and
  whole-block decode makes the retained unit a block rather than a chunk, which
  the byte budget does not count.
- **P14's inbox** — the fetch policy over a remote source is that phase's to
  own, the crate ships no knob for it, and the sync/async seam bites there and
  nowhere else.

**One round-one answer was withdrawn in round two**: the fetcher-count parameter
asked for on P14's behalf. Two things removed it — a correction to the crate's
evidence (the 249.6 MB/s reading was one thread issuing *block-sized* reads in
file order, so coalescing has nothing measured to buy on a spindle), and the
recognition that a fetcher inside a synchronous crate reaches an async object
store only by blocking on a future from a blocking thread, so a count multiplies
parked threads rather than removing them. What replaces it is the public
pre-fetched window, which hands P14 the whole fetch policy. The one thing asked
for in its place is a promise that the single fetcher walks blocks in ascending
order, without which a prefetching source cannot anticipate it.

Four answers bind P13 instead of a later phase, and they are inputs to its
grilling rather than decisions taken here:

- **Delivery is repeated fill** — `read(&mut buf) -> Result<usize>`,
  fill-or-EOF — because that is what the three read loops already are, and
  because an iterator of owned chunks would reintroduce the per-chunk `calloc`
  the buffer pool exists to remove *and* hand the query path 24–128 MiB buffers
  to retain behind Arrow string views that address a few kilobytes of them.
- **The boundary is blocking, wrapped here**, matching what
  `io::LocalFileSource` already does and leaving the runtime the binary's
  choice. An async API inside `xz-seek` was refused outright.
- **Verify-before-return is wanted as the bulk path's default.** This is the
  answer with the most force behind it: a scan persists the structure it
  discovers into the cache as it goes, so bytes whose check fails two calls
  later have already been recorded as fact and nothing re-examines them. The
  crate's seeking path keeps the weaker default, which matches `xz -dc`; the
  bulk path can afford the stronger one because it decodes each block whole
  anyway. On failure: bytes valid up to the fault, with the uncompressed offset,
  because that is the coordinate space this project's whole index lives in.
- **`SeekTable` gains `blocks_in(range)`.** D2 already commits this project to
  announcing a non-seekable container when it is discovered rather than letting
  a user meet it as a stall; the block count over a range is that warning with a
  number in it, and the same remedy attached.

**Contingent on `xz-seek`'s `P3` landing as specified.** The answers were given;
nothing is built against them.

## `xz-seek` is not published until this repo has integrated against it

Settled by the maintainer. **This project is `xz-seek`'s first real-world
consumer, and that consumption happens before publication, not after.** The
crate's interface is vetted by being used — bugs and shape changes shaken out
locally, against a caller with a cache format, an async trait and a 512 MB
cgroup — rather than frozen into a published version and then discovered. The
gate is both phases complete, P10 and P13, with the shape questions resolved;
publication and a proper versioned dependency follow.

**The mechanism is a frozen copy of the crate inside this repo, committed** —
not a path dependency pointing at the sibling working tree. The distinction
decides whether the repo stays self-contained. A path dependency is resolved
when the dependency graph is built, **not** when a feature is activated, so an
optional `xz-seek` behind an off-by-default feature does *not* rescue a checkout
lacking the sibling repo: `cargo check` fails with `failed to read
…/Cargo.toml` before features are considered. A committed copy has neither
problem, and it also decouples this build from the state of a tree that is still
iterating — which is the arrangement's purpose, since `xz-seek` continues
through its own `P3` while this phase runs.

The copy is a **snapshot, never a fork**: read-only, stamped with the commit it
came from, re-synced by script when `P3` lands, and replaced by a versioned
dependency at publication. That discipline is what answers the standing
objection to vendoring — that it creates a second authority over the source.
The mechanics, including the manifest transformation the copy requires and the
C-toolchain consequence of the default `liblzma` backend, are in
[`../../design/architecture.md`](../../design/architecture.md), "The compressed
source" (filed at this phase's grilling as the spec's D9; the inbox this was
first written into had already been drained and deleted, and the spec went at
the phase's keystone).

Publishing early was the alternative and is rejected on the ground that
publishing an interface nobody has consumed is what produces the 0.x churn it
was meant to avoid.

## The vendored copy of `xz-seek` now exists

Ahead of `xz-seek`'s own P3 (parallel block decode), which was still at 0/8 in
its checklist, so the crate's shape was stable to snapshot. `scripts/
vendor_xz_seek.py` extracts `src/` and a trimmed manifest from `git archive
HEAD` in the source checkout and writes them to `vendor/xz-seek/`, excluded
from this workspace (`Cargo.toml`'s `exclude`) and depended on by nothing yet.
The crate had no `LICENSE-MIT`/`LICENSE-APACHE` to vendor despite declaring
`MIT OR Apache-2.0` since its first commit, so those were added upstream first
(`54c7983`, one commit past the `bf26bf0` this project's own inbox entry had
stamped) and the copy carries them. `cargo check` passes both for this
workspace (the vendor directory excluded and untouched) and standalone inside
`vendor/xz-seek/` against the default `liblzma` backend.

Full mechanics in
[`../../design/architecture.md`](../../design/architecture.md), "The compressed
source" — first filed into the (since-drained) inbox as a plan, folded into the
spec as a numbered decision once this phase's grilling landed, and struck into
the subject-filed doc at its keystone.

## P13's wrap audit: the seek table is persisted and never read back

The wrap's audit of what the slices learned against
[`../../design/architecture.md`](../../design/architecture.md) turned up one
thing that was a gap rather than a filing job. D1 promised that the seek table
would be "persisted in the cache, so only a source with no usable cache ever
pays for" the stream-footer walk. Persisting landed and reading back did not:
`cache::save` records the table through `ByteRangeSource::seek_table()`,
`cache::load` round trips it, and `XzSource::open` walks the footers anyway,
because nothing constructs a reader from a cached table. The decoder crate
supports that construction; this tree never calls it.

**No slice is unfinished by its own row.** 13.3 owed the source and the seek
table's content, 13.4 owed recognition and the diagnostic, and neither row
mentioned consuming a persisted table — 13.3's and 13.4's notes both named the
optimization and left it unclaimed, each pointing at the other or at P14. The
gap is between the spec's prose and what the five rows between them covered,
which is exactly what an audit at the wrap is for and what a checklist cannot
see.

What it costs is bounded and lopsided by container shape: a single-stream file's
walk is one read whatever its size, while the koji upstream download's 31,150
concatenated streams cost **85 s** of HDD seeks, on every command, however
complete the cache is. So it is a real cost on the one file that motivated the
phase and nearly free on the shape a user gets by compressing in one go.

Filed as `KD15`, unowned — the fix is located (recognition is the layer that
already decides which source to build, so it is the layer that can consult a
loaded cache first) but nobody holds the intent, and manufacturing an owner
would be inventing one. Detail beside the mechanism
([`../../design/architecture.md`](../../design/architecture.md), "The compressed
source"), an entry in
[`../../design/roadmap-P14-remote-input-inbox.md`](../../design/roadmap-P14-remote-input-inbox.md)
because that phase's inbox already asserted the mitigation as settled and it is
that phase's worst latency case, and a caveat in
[`../../manual/dump-inspection.md`](../../manual/dump-inspection.md) because a
user meeting a minute per command deserves to have been told.

## A keystone landing the same day as the work it strikes must repoint that day's own citations

`citations.py` exempts a dated entry **whose day has closed**, on the ground
that an entry states what was true on its date; today's entry is still read,
because a typo is wrong the moment it is written
([`README.md`](README.md), "An entry carries yesterday's truth"). The keystone
that struck the compressed-input work ran on the same day as three sections
above that cite its spec by section, so those citations came due immediately
rather than being covered by the exemption.

They were repointed at the subject-filed sections that now hold the same
mechanics, and no claim in them was altered — the reasoning being that the
exemption is about a *closed* day, so a live one is still governed by the
rewrite-in-place rule those entries are written under. Leaving them dangling was
the alternative: it would have put the check red for one day with nothing wrong,
and a check that is red for a reason nobody should act on is the signal the
register rules exist to prevent.

Worth knowing for the next keystone, because the two rules read as if they
settle it and neither does on its own. The general case is narrow: only a
keystone run on the same day as work that cited the docs it strikes.
