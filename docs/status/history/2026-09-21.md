## Arrow semantics is DataFusion's comparison

Reviewed with the maintainer after 6.2 landed. **Pick up at 6.2.1**
([`../STATUS.md`](../STATUS.md), "P6 progress").

- **The measure is DataFusion's `apply_cmp`, not Arrow's bare `cmp` kernels.**
  In 55.1.0 it makes a float operand's `-0.0` into `+0.0` before the kernels
  run (`datafusion/physical-expr-common/src/datum.rs`, `apply_cmp`;
  `normalize_float_zero` in `datafusion/common/src/utils/mod.rs`; upstream
  #22835). 6.1 and 6.2 checked against the kernels, so 6.2's `Float32Total`
  and `Float64Total` answer `-0 < 0` where DataFusion answers `-0 = 0`. With
  zeros equal, a float's order is PostgreSQL's. The spec's "Comparison means
  what DataFusion means" and its Verification item 1 were amended, and 6.6
  carries the DataFusion-side check, the library taking no DataFusion
  dependency.
- **A nested column stays refused in Arrow semantics**: DataFusion orders it by
  `make_comparator` under default `SortOptions`, marked `TODO` upstream
  (`compare_op_for_nested`, same file). Filed as D40's `Rejected` line.
- **A column with no plan is ordered bytewise in Arrow semantics** — DataFusion
  orders `Utf8View` so, and under `--schema-mode strings` every column is
  planless. 6.2.1 builds it; 6.2 refuses those ordering operators today.

## Collated text gets bytewise bounds

Reviewed with the maintainer after 6.2 landed. Gathering takes bounds and row
order only where the kind orders exactly in PostgreSQL's semantics
(`ColumnGatherer::new`, `gather.rs`; D79), so a text column with no `COLLATE`
(`UnknownCollation`) gets neither, and in Arrow semantics prunes only `=`,
through its dictionary. Text bounds are bytewise heads whatever the collation
(D76), which is DataFusion's `Utf8View` order exactly, so the gate, not the key,
is what withholds them.

- **Admitted as slice 6.9, ordered before 6.7**: gather them for every text
  column, believed only in Arrow semantics; no `CACHE_FORMAT_VERSION` bump (D78
  bumps for a changed order or equality, and this is neither), an older cache
  reading `Absent` until a re-parse adds them, which the slice verifies;
  `statistics-gathering` re-taken to report the volume, not to decide it. D79
  changes when 6.9 lands.
- Rejected: dictionary-derived bounds at read time — they cover only groups
  under `DICTIONARY_MAX_ENTRIES`, and D75 already refuses a dictionary answering
  ordering.

## 6.3.2: what Arrow-semantics registration announces

Reviewed with the maintainer after 6.3.1 landed; **6.3.2** admitted before 6.4,
6.3.1 having shipped the report's shape wrong in two places.

- **Text-emitted kinds keep their equality warning.** A user's literal is
  compared bytewise with the emitted text, so a non-canonical spelling
  (`'12:00+00'`, `'10.0.0.1/32'`, an unpadded `character(n)` literal) misses a
  value PostgreSQL matches. The sentences name the literal's spelling, and a
  unit case pins one.
- **A nested column announces ordering only**, PostgreSQL ordering a NULL
  element or field last (`array_cmp`, `record_cmp`) and `make_comparator`
  first, while both equate two NULLs (`array_eq`, `record_eq`). Each element
  or field position reports its own Arrow divergence under its path, as
  PostgreSQL's semantics already does.
- **`EmittedText` is retired**: every column it fired on already carries a
  `Warning` fall-back column note, whose sentence says the value compares as
  its text. Whether `:strings` should warn per column at all is not settled
  here.

## A nested float's `-0` is announced, and 6.6 checks it

Reviewed with the maintainer after 6.3.2 landed; the call and its rejected
alternative are the rustdoc on `ComparisonDivergence::UnnormalizedZero`.

- **6.3.2's own check does not reach DataFusion**: its unit case calls Arrow's
  `make_comparator` directly, so an upstream release normalizing zeros in
  `compare_op_for_nested` would leave the note false and every test green. The
  spec's Verification item 1 was amended so 6.6 checks a nested column's
  announcements through DataFusion, though its terms are never pushed down.
