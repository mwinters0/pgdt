# 2026-08-24

## Slice 3.2.1 was mis-sized

3.2.1's spec row bundled two changes of different confidence. Landed as
scoped: `DumpIndex::spans` as the primary structure (`blocks()`/`blocks_for`
derived, `Span::Data` holding `CopyBlock` inline), the cache format storing
spans (format version 2 → 3), `build_index` producing spans in its existing
scan pass by driving `map::Builder` directly instead of `build_map` costing a
second pass, and `scan_preamble`/`preamble_only` producing a real
`SpanBody::Unscanned` tail for the one genuinely partial scan that exists
today. See `docs/design/roadmap-phase3.2.1-span-wiring-notes.md`.

Split out as 3.2.1.1, not delivered this slice: `DumpMetadata` as a derived
view over `spans`, and `crate::stream::table_stream`'s live segment
classifying the DDL between discovered blocks so a query-built `DumpIndex`
tiles the way `build_index`'s does.

Both pieces turned out to need real design work, not just plumbing, once
inside the slice:

- `DumpMetadata`'s current producer (`PreambleBuilder`) tracks state a span
  list doesn't yet carry anywhere: the two version-header lines (no
  `SpanBody` variant stores them — they classify as generic `Framing`
  today), and `ALTER TYPE ADD VALUE` folding a `--binary-upgrade` dump's enum
  labels back into an already-open `TypeDef` span (`crate::map::classify`
  gives that statement its own `Unparsed` span, with nothing to fold into).
  Making `DumpMetadata` a real derived view means deciding both shapes first,
  not just wiring the read side.
- `stream.rs`'s live segment is deliberately minimal today — it tracks
  `CopyStart`/`CopyEnd` and `\connect` only, not full DDL classification —
  because it runs in the per-row query hot path. The phase's own "Scan
  shape" section frames the cheap DDL-classification tier as unconditional
  and running "over any scan (full or incremental)", which means this is
  real, expected work, not an oversight; it's a rework of an already-tested
  path (resume tokens, ambiguous-table detection, the `Recorder`), not a
  self-contained addition, so it doesn't belong in the same review as the
  mechanical change above.

Recorder's interim state (each live-discovered block recorded as its own
`Span::Data`, with no span for the DDL between them) does not tile — accepted
for now since nothing yet reads a non-`Data` span back out of a query-built
`DumpIndex`; `check_tiling` is exercised only against `build_index`'s output
(always a full scan) until 3.2.1.1 lands.

## A pre-existing `pgdq info` cache-trust bug, found incidentally

`Command::Info` (no `--preamble-only`) trusts any cache `CacheMode::load`
returns and never checks whether it actually covers the whole file: running
`pgdq info <file> --preamble-only` followed by `pgdq info <file>` prints the
preamble-only cache's `DumpMetadata` (correct) but zero `COPY` blocks
(wrong) instead of running `build_index`'s full scan. Reproduced against
`main` before this slice's changes (`git stash`), so it predates Phase 3.2.1
and isn't part of its contract — recorded in `STATUS.md`'s "Known gaps" for
a future slice to fix (likely: compare `scanned_through` against the source
size before trusting a loaded cache as complete).
