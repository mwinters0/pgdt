# 2026-10-01

## 28.9's readings wait on a bounded warm set

28.9's sweep failed on `/dev/shm`'s per-user quota
([2026-09-30](2026-09-30.md), "28.9's sweep failed on `/dev/shm`'s per-user
quota"). The maintainer settled the way forward: out-of-band `M185`, which
blocks P28 ([`../../design/out-of-band.md`](../../design/out-of-band.md)).
After it lands, one fresh `measure.py --all` and the profile recipe take 28.9's
and 28.9.1's readings together. The failed sweep's tables in
`runs/measure-20260930T214416/` are not folded, even in part.

**What `M185` delivers.** The rule's reasoning belongs in `measurements.md`'s
"The apparatus", which still says the budget is computed; `M185` rewrites it.

- **Measurement's RAM is bounded by design.** No sweep co-measures more than
  two full-size inputs. The stager's budget is the constant 2 ×
  `PGDT_MEASURE_SIZE_GIB` + 64 MiB, which is 6.06 GiB at today's 3.00 GiB
  inputs, and `test_measure.py` asserts that every figure's warm set fits it.
  Two full-size inputs are what one paired cross-file difference needs; the
  64 MiB covers a generator's few-KB overshoot, replacing `WARM_MARGIN`'s 10%.
  A figure that outgrows the bound splits. The room is not grown: the quota is
  not raised, and the stager gets no mount of its own.
- **A split figure runs one sweep per input.** Inputs are co-measured only
  where a row subtracts one input from another. Each input's `dd` floor runs
  in that input's sweep, while the input is staged. Today the bound splits
  `statistics-gathering` (4 inputs, 12.00 GiB), `scan-throughput-warm` and
  `nested-end-to-end` (9.00 GiB each). None of the three subtracts one input
  from another. `cross-file-floor` (6.00 GiB), `reserve` (4.37 GiB) and
  `parallel-scan-throughput` (3.68 GiB) fit, and every other figure's warm set
  is at most 3.01 GiB.
- **Preflight reserves the budget before trusting it.** It `fallocate`s the
  whole budget in the warm directory and deletes the file, so any limit fails
  there and not mid-sweep. `shmem_fallocate` charges the quota exactly as a
  write does, and rolls back everything it added when it fails (Linux 7.1,
  `mm/shmem.c`).
- **A staging failure aborts the sweep**, because every later figure shares
  the stager. `Stager.warm_path` records an input as staged only once its copy
  has finished, and removes a partial file on failure.
- **`CLAUDE.local.md`'s staging note** ("9.90 GiB … against `/dev/shm`'s
  16 G") is rewritten by the session that lands `M185`, to the constant and
  the quota.

**The quota.** The 12.5G is systemd's default for a regular user: 80% of the
tmpfs's size at login, which is 13,109,721 KiB, applied by
`systemd-user-runtime-dir` to `/tmp` and `/dev/shm` (systemd 258 and later,
`devShmLimit`/`tmpLimit` in the user record). For an `/etc/passwd` user, only a
whole-record userdb drop-in changes it, and only from the next login.
`statvfs` and `df` cannot see the quota; `quotactl_fd` with `Q_GETQUOTA` reads
it without privilege. A tmpfs that root mounts separately carries no quota.
The machine has 31 GiB of RAM, and `/dev/shm` and `/tmp` are each a 16G tmpfs.
