## The cancellation is the mapping pass's argument

The maintainer reviewed 36.6.2's call to keep `cancel` on `ScanOptions`
(its notes, "Negative results") and reversed it. The spec now says so
(spec, "The small fixes"). Settled:
- **A query takes no cancellation.** Dropping its stream cancels it.
- **`map_file` takes the cancellation as a required argument**, not as a
  field of an options value, and not as an `Option`. A caller that never
  stops the pass passes a token it never fires.
- **The token is `tokio_util::sync::CancellationToken`.** pgdt-io's
  `Cancellation` goes.
- **`ScanOptions` keeps its name** and holds a `ReadOptions` and a
  `Parallelism`. `scan`, `preamble_only`, `build_index`, `build_map` and
  `map_file` take it again, which undoes 36.6.2's split of their arguments.
- **A cold query keeps its early stop** (spec, "The opened dump"). The spec
  had a `Dump` built only "by a mapping pass run to the file's end", which
  would have dropped the early stop that a cold `pgdt query` uses by
  default (`ScanExtent::UntilTargetSettled`, through
  `QueryOptions::default()` in `crates/pgdt/src/query.rs`). That would
  change a behaviour, which the spec rules out, and neither `ScanExtent`
  nor `KD6` was mentioned in it. 36.8 designs what an early-stopped pass
  yields. Like the complete pass, it takes the token.
- **It lands as 36.6.4**, earned because 36.6.2 shipped the wrong
  contract. It is not counted: no row of "What a hot-path slice owes"
  applies, and the per-chunk poll becomes one uncontended mutex lock.

Facts found in the code, which decided it:
- **No shipped caller asks a query to stop through the flag.** `pgdt
  query` builds its `ScanOptions` with `cancel: None`
  (`crates/pgdt/src/args.rs`, `scan_options`). The provider takes the
  default and is cancelled by a drop (D90). Only `pgdt parse` sets one
  (`crates/pgdt/src/parse.rs`).
- **A drop stops a query's mapping pass as soon as the flag would.** No
  production code in pgdt-io, pgdt-mapping or pgdt-query spawns a task
  that outlives the stream. The interior workers are `spawn_blocking`, one
  chunk at a time (`crates/pgdt-mapping/src/interior.rs`,
  `scan_partition`). A remote read in flight is a future, which the drop
  cancels outright. `hint_cancellation` exists to do the same for a pass
  that stops by polling the flag.
- **The field meant something different to each taker.** `map_file`
  saves and returns `MapRun::interrupted`. A query's mapping pass returns
  `Err(ScanCancelled)` (D48). The replay is handed the token and never
  polls it.
- **An options value is reused, and the token is one-shot.** `ScanOptions`
  derives `Clone`, which clones the `Arc`. A stored `ScanOptions` reused
  after one interrupted run makes every later `map_file` return
  `interrupted` at byte 0, with nothing saying why.
- **P14.1 refused `CancellationToken` on cost alone**: a dependency for a
  twenty-line type (`git show f06978fd:docs/design/roadmap-P14.1-cancellation-notes.md`).
  The standing rule does not let cost decide. tokio-util 0.7.19 is already
  in the build, through `object_store`/`reqwest` under `remote` and
  through DataFusion. Its API matches ours one for one, its
  `run_until_cancelled` being our `until_cancelled`, and it is `Clone`
  without an `Arc`. Its `is_cancelled` takes an uncontended mutex
  (`tree_node.rs`, `is_cancelled`), polled once per chunk or leader window.

## The mapping pass takes the arrangement

The maintainer reviewed 36.7's call to leave `map_file` on `&ScanOptions`
and `&GatherOptions` while `backfill_block` takes an `Arrangement` (36.7's
notes, "Negative results"). Settled:
- **`map_file` takes the arrangement**, as `backfill_block` does: it reads
  with `Arrangement::parallelism` and bounds its account by
  `Arrangement::statistics_allowance`, and `GatherOptions` loses
  `statistics_allowance_bytes`. The passes that gather nothing (`scan`,
  `preamble_only`, `build_index`, `build_map`, a query's mapping pass) keep
  `ScanOptions`, reading no allowance. `backfill_block` going back to the
  pair was refused: it would copy by hand in two places what D85 defines as
  one carve.
- **`Arrangement::resolve` stays the only constructor.** A caller stating a
  parallelism and no allowance passes `Allowance::NoneFound` with
  `Jobs::Stated`, which `estimated` resolves to the parallelism asked for
  and an allowance declining nothing (D1). A constructor taking a
  `Parallelism` and an allowance would bring back the pair that can
  disagree; one taking a `Parallelism` alone needs a provenance `Allowance`
  does not have. So `Arrangement` takes no `Default` either.
- **Both entry points take `read`, `&Arrangement` and the mode as three
  arguments, in that order, and `GatherOptions` goes.** A reusable
  `GatherOptions { read, postgres_invalid_values }` beside the arrangement
  was refused: it groups `ReadOptions` a second way to save one argument.
  One value holding all three was refused on this morning's reasoning: an
  arrangement is resolved for one run, against the source and the opened
  cache's statistics (`held`), and options are reused across runs.
- **It lands as 36.7.1**, before 36.8, which builds the `Dump` from what
  `map_file` hands back. It changes the spec's "The small fixes", so it is
  a slice, not an out-of-band item; the spec's "The arrangement" now says so.

Facts found in the code, which decided it:
- **The spec names the hand copy as a defect and no slice removed it.**
  Cluster B: `GatherOptions::statistics_allowance_bytes` "must equal
  `statistics_allowance(allowance, budget)`"; "The arrangement" returns the
  allowance "that `GatherOptions` and `StatisticsRequest::backfill` take
  today by hand". 36.2's notes gave the back-fill half to 36.7, which took
  it, and the `GatherOptions` half to nobody.
- **The two numbers are one carve.** `Arrangement::resolve` computes the
  allowance from `parallelism.budget_bytes()` (D85), so a `ScanOptions` and
  a `GatherOptions` built apart can pair a parallelism with an allowance not
  carved from it. `pgdt parse` (`crates/pgdt/src/parse.rs`), the one
  production caller, holds the arrangement and copies both out of it.
- **This morning's decision is not reversed.** It placed the cancellation
  and made `ScanOptions` a `ReadOptions` and a `Parallelism`, listing
  `map_file` among its takers because that was what `map_file` read; it
  weighed nothing about the allowance.
