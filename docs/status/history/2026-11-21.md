## The observer contract splits in 43.6

- **The maintainer reversed 43.5's one-trait call**, so 43.6 splits `BlockObserver` into a row trait and a block one,
  and makes the `Recorder` generic over its observer (`../../design/roadmap-P43-block-model.md`, "One recorder, a held

  recorder's own `finish`. Only the interior host makes pieces (`interior.rs`), and it uses each one only for rows,
  then absorbs it.

## 43.6's row count, reviewed

- **The maintainer affirmed that the recorder holds no row count** (D169's `Rejected`). The count is the line
  machine's: the scanner counts it (`pgdt-dump/src/scan.rs`), interior pieces sum to the serial `CopyEnd` (D52), and
  the back-fill checks a re-read's against the cache's (`CachedBlockChanged`). Every host already hands every held row
  to `Recorder::row`, the metadata-level parse included; only a streamed row of a block folding nothing reaches no
  recorder. A recorder's count would check only that a host hands each row on.
- **That check exists through the gatherer's count**: its groups' rows sum to the block's `row_count`, asserted per
  gathered block by `pgdt-query/tests/statistics.rs`'s `assert_describes_the_file` alone. `M306` asserts it in
  `Recorder::finish` on every host's tests, ahead of 43.7's one open and one close. A declined or checked block keeps
  no count and stays unchecked.
- **The spec's "and the row count" (`../../design/roadmap-P43-block-model.md`, "One recorder, a held row split once")
  stands as intent**; 43.6's notes record the deviation. "Count" in D169 and `recorder.rs` now says it is D96's.
