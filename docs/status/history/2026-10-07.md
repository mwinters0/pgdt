## 29.3's unattended calls, reviewed

The maintainer reviewed the two calls 29.3 flagged under STATUS's "Decisions
worth another look".

- **The release variable must name the workspace version**, any other value,
  an empty one included, failing the compile — affirmed as built. The reasoning
  is at `RELEASED` in `pgdt/src/main.rs`.
- **The spec left "a tag with no matching draft" unmatched by anything**, and
  matching by commit alone lets a tag naming the wrong version publish another
  version's archives under it, past repair once releases are immutable.
  `../../design/roadmap-P29-releases.md`, "Building, tagging and publishing"
  now says a draft is matched by name. 29.4 builds it, with both checks as
  tests of its script.
- **The notices are rendered by `release.py` from `cargo-about`'s JSON** —
  affirmed. The spec's "produced by `cargo-about`" names a means; its own
  requirements, the linked closure and every `NOTICE`, are what `cargo-about`
  alone cannot meet (`../../design/roadmap-P29.3-licence-notes.md`, "Negative
  results"). The reasoning is at `step_notices` in `scripts/release.py`.
- **The notices are now checked at a dependency upgrade**, the `upgrade-deps`
  skill running `release.py notices` after a `Cargo.lock` change, since every
  way they break is a dependency moving; `mise run check` stays offline.

## 29.4's unattended calls, reviewed

The maintainer reviewed the three calls 29.4 flagged under STATUS's "Decisions
worth another look", and agreed each recommendation.

- **The workflows run `release.py`'s host wrappers, not `container:` jobs** —
  affirmed, the spec's wording amended (`../../design/roadmap-P29-releases.md`,
  "The build image"). A `container:` job takes an image reference and builds no
  Dockerfile; a local Docker action would build it but run one step per
  container, with no memory limit and a command path a rehearsal does not
  take. The reasoning is at the header of `scripts/release.py`.
- **The arm64 suite is nextest alone** — affirmed. The gap is empty: no
  workspace library holds a doctest (`check.doctest_packages`), and
  `release.SUITE` is built from the unnarrowed `check.CHECKS`, so the x86-64
  job compiles the workspace for a doctest check the round itself drops.
  `M220` narrows it and adds a test that fails when the first doctest lands,
  so whether arm64 then runs it is decided at that point and not found later.
- **The archives are attested in the `draft` job** — affirmed, the spec's
  "when it is built" amended (`../../design/roadmap-P29-releases.md`,
  "The artifacts"). Beyond the entry's reason, per-build attestation would put
  `id-token: write` and `attestations: write` in jobs that run every
  dependency's build script. What is given up is that the attestation's builder
  is the `draft` job's run, not the job that compiled the bytes; the run and
  commit are the same, so `--source-digest` verifies either way. The reasoning
  is at the `draft` job in `.github/workflows/release-build.yml`.
