## 29.4's unattended calls, reviewed

The maintainer reviewed the three calls 29.4 flagged under STATUS's "Decisions
worth another look", and agreed each recommendation.

- **The workflows run `release.py`'s host wrappers, not `container:` jobs** —
  affirmed, the spec's wording amended (`../../design/roadmap-P29-releases.md`,
  "The build image"). A `container:` job takes an image reference and builds no
  Dockerfile; a local Docker action would build it but run one step per
  container, with no memory limit and a command path a rehearsal does not
  take. The reasoning is at the header of `scripts/release.py`.
- **The arm64 suite is nextest alone** — affirmed. The gap is empty: no
  workspace library holds a doctest (`check.doctest_packages`), and
  `release.SUITE` is built from the unnarrowed `check.CHECKS`, so the x86-64
  job compiles the workspace for a doctest check the round itself drops.
  `M220` narrows it and adds a test that fails when the first doctest lands,
  so whether arm64 then runs it is decided at that point and not found later.
  It blocks P29: 29.6's release-build runs the suite it narrows.
- **The archives are attested in the `draft` job** — affirmed, the spec's
  "when it is built" amended (`../../design/roadmap-P29-releases.md`,
  "The artifacts"). Beyond the entry's reason, per-build attestation would put
  `id-token: write` and `attestations: write` in jobs that run every
  dependency's build script. What is given up is that the attestation's builder
  is the `draft` job's run, not the job that compiled the bytes; the run and
  commit are the same, so `--source-digest` verifies either way. The reasoning
  is at the `draft` job in `.github/workflows/release-build.yml`.

## 29.5's unattended call, reviewed

The maintainer reviewed the call 29.5 flagged under STATUS's "Decisions worth
another look", and agreed each recommendation.

- **`/release` bumps and commits before it rehearses** — the call changed, and
  the spec's "`/release`" (`../../design/roadmap-P29-releases.md`) now orders it
  so. Bumping before rehearsing was right: `release_ci.py archive` names the
  archives and `release.py build --release` stamps the binary from
  `release.workspace_version()`. But leaving the bump uncommitted meant
  `/release` could never pick up again: step 1 refuses the dirty tree that the
  bump leaves. `commit_time()` also took the archives' mtime from the previous
  commit. Rehearsing the commit fixes both, and the tree id becomes `HEAD`.
- **A failed rehearsal keeps its `Release v<V>` commit**: the next run finds
  `V` unreleased and rehearses `HEAD` again, and a fix lands after the commit.
  `git reset --keep HEAD~1` only abandons the release.

## `M217`: the interrupt banks its own block

Landed as admitted (2026-10-06, "`M217`: an interrupt test that load can
fail"). The race was the save throttle's clock, not reading against scanning:
the serial pass hears a flag tripped at a block's end at the next chunk's check
point, which banks the last spliced watermark, and the block's close splices
only when the throttle is due (`../../design/decisions.md`, "D62"). A loaded
machine slows the save the throttle is timed from. `assert_an_interrupt_inside`
in `pgdump_query/tests/map_file.rs` now trips on the read delivering the block's
terminating LF, so its close hears the interrupt and banks it ("D63"), and it
asserts `scanned_through` is that block's end. The concatenated-file test
shares the helper and is fixed with it. With `SAVE_THROTTLE_K` raised by hand
so the throttle never reopened, the old trip failed both tests and the new one
passed them; the constant was put back. That run is not a figure.
