# 2026-10-03

## `M205`: an integer literal is read at its column's width

Landed as admitted, closing `KD76`. `CompareKind::Int` carries its width in
bytes, and `predicate::int_literal` reads a `smallint`, `integer` or `bigint`
literal in PostgreSQL's semantics, refusing one past the width as `int2in`,
`int4in` and `int8in` refuse it (I60, marked `pg-refuses: I60`), at every
literal site `literal_key` and `equality_comparison` reach, so an array
element, a range bound and an `IN` value included. A field, and a literal in
DataFusion's semantics, are read as an `i64` unchanged: a field past its width
is 31.12's. `accepted_form` names the width's range. No persisted byte moved,
the cache keeping bounds as text, and no oracle file was regenerated:
`literals.tsv` already refuses one past each width at every major.

Evidence: `predicate.rs`'s
`an_integer_literal_past_its_width_is_refused_and_one_inside_it_read`,
`an_integer_literal_past_its_width_is_not_refused_in_datafusion_semantics`
and `oracle::an_integer_literal_is_read_as_the_server_reads_it`, every major.

## `M206`: a date, time or timestamp is bounded as `datetime.c` bounds it

Landed as admitted, closing `KD77`. The decoders a field and a literal share
(`decode::civil_days`, `parse_time_of_day`, `extract_offset`,
`decode_date32`, `timestamp_micros_wide`) refuse what I61 records the server
refusing: a day its month lacks, year zero, a time past `time_overflows`, a
zone past `±15:59:59`, a date or a timestamp's instant past the range. A part
carrying a sign is refused, so `12:-5:00`, which the server reads as a zone,
is refused rather than read; a year under three digits, a three-digit month and
a run-together `+0530` are refused as shortfalls (D55). A refused field is an
undecodable field, `FieldDecode` where it is read; a parse refusing it is
31.12's. `CACHE_FORMAT_VERSION` is 42: such a field, which a hand-written
dump can hold, now loses its group's bounds and leaves the unrepresentable
count where it was keyed or counted before; neither pinned digest moved. No
oracle file was regenerated: the koji replica (PG16) answered every probe I61
lists.

Evidence: `decode.rs`'s `a_date_the_calendar_does_not_hold_is_refused`,
`a_time_past_time_overflows_is_refused`,
`an_offset_past_fifteen_hours_is_refused`,
`a_timestamp_past_postgresqls_range_is_refused` and
`the_date_range_constants_are_julian_days_from_1970`; `predicate.rs`'s
`a_date_or_time_postgresql_refuses_is_refused_as_literal_and_field` and
`oracle::a_date_or_time_literal_is_read_as_the_server_reads_it`, every major.

## `M207`: an interval is bounded as `interval_in` bounds it

Landed as admitted, closing `KD78`, and two refusals of the same function
beside it. `decode::interval_parts` now returns the `Interval` struct's own
widths, `(i32, i32, i64)`, for a field and a literal alike, refusing what I62
records the server refusing: a count or the month total past `int32`, a time
past `int64` microseconds, a minute past 59 or a second past 60
(`interval_time_micros`), and a unit given twice, which the grammar had
accepted as a deliberate widening and D55 rules out. `accepted_form` names the
bounds. A refused field is an undecodable field; a parse refusing it is
31.12's. `CACHE_FORMAT_VERSION` is 43: such a field, which a hand-written dump
can hold, now loses its group's bounds, and one past `int64` microseconds
leaves the unrepresentable count; neither pinned digest moved. I40 had put the
time's ceiling at `2562047:47:16.854775807`, which is Arrow's nanoseconds; it
now cites I62's `2562047788:00:54.775807`, which the `types` fixtures already
hold and the koji replica (PG16) reads.

Evidence: `decode.rs`'s `an_interval_interval_in_refuses_is_refused` and
`predicate.rs`'s
`an_interval_postgresql_refuses_is_refused_as_literal_and_field`, every probe
cast on the koji replica.

## `M208`: a number is bounded as `numeric_in` bounds it

Landed closing `KD79`, short of the row's wording on one cell. A literal on
every `numeric` kind, in PostgreSQL's semantics, and a bare `numeric`'s field
are refused past I63's display scale and weight
(`decode::numeric_in_stores`), and a `jsonb` number, field and literal, past
them and an exponent past `PG_INT32_MAX / 2` (`JsonCursor::number`), which
replaces this build's own bound at a point position of 100000 — that refused
`1e100000`, which the server reads. **A `numeric(p,s)` field is not capped**:
`COPY` rounds it to the scale before the bounds are checked, so the server
reads `1.` and 16384 zeros as `1.00` and so does this build; capping it would
refuse a valid field, which 31.12 would make an abort no restore makes.
`accepted_form` names the bounds. `CACHE_FORMAT_VERSION` is 44: such a field
now loses its group's bounds, and a `jsonb` one past 100000 integer digits
gains them; neither pinned digest moved. No oracle file was regenerated: the
koji replica (PG16) answered every probe I63 lists.

**Filed as `KD81`, slice 31.15**: the rest of `apply_typmod` is not applied to
a `numeric(p,s)` field, so `1.005` in a `numeric(10,2)`, which `COPY` stores as
`1.01`, is refused on a typed column and read unrounded on a text-held one,
and a field past the precision is read. The refusal is a shortfall, not the
server's, and becomes a false abort if 31.12 lands first.

Evidence: `decode.rs`'s `numeric_in_stores_up_to_its_display_scale_and_weight`;
`predicate.rs`'s
`a_numeric_past_numeric_ins_bounds_is_refused_as_literal_and_bare_field`,
`a_jsonb_number_is_bounded_as_numeric_in_bounds_it` and
`oracle::a_numeric_literal_is_read_as_the_server_reads_it`, every major, whose
helper now lets the newest major's reading of a literal an older one refuses
bind (I35), as a v13 `numeric`'s `Infinity` is.

## 31.15 runs ahead of 31.12

Its checklist line sits above 31.12's. `KD81`'s refusal of a `numeric(p,s)`
field `COPY` rounds is a decoder refusing what the server stores, which 31.12
would turn into a parse abort no restore makes. 31.15 is a decoder fix of the
kind `M203` and `M205`–`M209` are, which the run order in the
[2026-10-02](2026-10-02.md) entry ("The ceiling binds a field too") lands
before 31.12, so that every refused field becomes an abort at once.

## `M209`: a `uuid` is read by `uuid_in`'s grammar

Landed closing `KD80`, and one step past the row's wording under D55's
ceiling. `decode::decode_uuid`, which a field and a literal share, now ports
`string_to_uuid` whole (I64, marked `pg-refuses: I64`): a hyphen is taken only
after a group of four digits but the last, so one leading, trailing, doubled or
mid-group is refused, and a value in braces, which the server reads and this
build had refused as a shortfall, is read, at no cost the canonical form pays.
`accepted_form` and the manual's refusal examples say so. A refused field is an
undecodable field; a parse refusing it is 31.12's. `CACHE_FORMAT_VERSION` is
45: such a field, which a hand-written dump can hold, now loses its group's
bounds, and a braced one gains them; neither pinned digest moved. No oracle
file was regenerated: `literals.tsv` holds the braced form at every major, and
the koji replica (PG16) answered every probe I64 lists.

Evidence: `decode.rs`'s `a_uuid_takes_a_hyphen_only_after_a_group_of_four` and
`uuid_agrees_with_the_shape_it_replaced`; `predicate.rs`'s
`a_uuid_postgresql_refuses_is_refused_as_literal_and_field` and
`oracle::a_uuid_literal_is_read_as_the_server_reads_it`, every major.
