# 2026-10-23

## `gz-seek`'s backend and `unsafe`, reviewed

The maintainer reviewed 15.4's "Decisions worth another look" entry on
`gz-seek` reaching zlib-rs through its C API.

- **No plan waits on upstream** (`../../../.claude/skills/upstream-issue/SKILL.md`).
  The UF4 request is still made, filed by the maintainer from
  `runs/UF4-upstream-request/issue.md` (`../upstream.md`, "UF4").
- **Any engine giving what an index needs is a backend candidate**, a C
  library or a crate's C ABI as much as a safe crate, those known to be slow
  last. **Slice 15.9 measures them through `gz-seek`** before 15.1.2 and
  decides the backend, which becomes a `D<k>` of its own; ISA-L is excluded
  (`../../design/roadmap-P15-gzip.md`, "Settled in the grilling", "Slice
  order").
- **`unsafe` is acceptable where necessary, and a crate declares itself free
  of it wherever possible.** D27's count is the seven libraries'
  (`../../design/decisions.md`, "D27", "D68"), so `gz-seek` linked leaves it
  true. No library declares anything today (`gz-seek` `deny`s, the vendored
  `xz-seek` `forbid`s), so the count holds by inspection alone until `M246`
  (`../../design/out-of-band.md`) lands the declarations and their check.
- **CMake is not refused as such**: it was kept from the shipped build so that
  `aws-lc-sys` builds under its `cc` builder, and a backend built by CMake is
  acceptable once that is guarded another way (`../../design/decisions.md`,
  "D111").
- **Facts.** `crates/gz-seek/src/zlib.rs` speaks the zlib API, which
  `libz-rs-sys`, `libz-sys`'s stock zlib and its zlib-ng compat build all
  export. `libz-sys` 1.1.30 builds zlib-ng with `cc`, no CMake, under its
  `zlib-ng-no-cmake-experimental-community-maintained` feature. Neither stock
  zlib nor a `cc`-built zlib-ng has been timed here.
- **ISA-L's igzip cannot stop at a block boundary upstream** (intel/isa-l
  `469c7d0`, read 2026-10-23: `isal_inflate` returns only on input empty,
  output full, an error or the stream's end). The stopping points
  (`points_to_stop_at`) exist only in rapidgzip's fork, mxmlnkn/isa-l, and
  intel/isa-l#254 asking for them has been open since 2023-08-24. Upstream
  has `isal_inflate_set_dict`, priming only by writing `inflate_state`'s
  `read_in`/`read_in_length` (undocumented), no window read, and no CRC-32
  combine. `isal-sys` 0.5.3 bundles v2.31, built by autotools and nasm.

## A writer that ends no block, reviewed

The maintainer reviewed 15.4's entry on a single member indexed as one unit.

- **Which writers do it** (`runs/p15-level1-writers/reading.txt`): at level 1,
  zlib-ng's default build and zlib-rs write one static block to the last
  write; stock zlib and Fedora 44's zlib-ng-compat, built without
  `deflate_quick`, end a dynamic block every few tens of KB. `pg_dump` (13,
  16, 18) calls `deflate` with `Z_NO_FLUSH` and `Z_FINISH` only, and the
  `postgres` images 15.1's fixtures come from link stock zlib (Debian,
  Alpine). The spec's "the choice of spacing is the reader's" now says so.
- **15.5 warns of one, by D19 as it stands**: `CompressionIndex::is_seekable`
  is false for one unit, so the member opens, reads from its start and raises
  `NonSeekableCompressedSource` in gzip's words; tested on a member
  `libz-rs-sys`'s own level 1 writes, never `flate2`'s, whose backend is
  feature unification's. No Fedora `pg_dump` fixture: another valid writer's
  block layout tests nothing the one-block case does not.
- **15.10, after 15.8, places checkpoints inside a static block** (`KD129`,
  `../deficiencies.md`): a resume at any symbol boundary of one is a synthetic
  three-bit static header primed ahead of the byte's remaining bits, at most
  ten in one `inflatePrime`, plus the window, through the zlib API as it is;
  no inflater stops there, so the forward pass walks the static codes itself
  (`../../design/roadmap-P15-gzip.md`, "Slice order").
