# 2026-10-23

## `gz-seek`'s backend and `unsafe`, reviewed

The maintainer reviewed 15.4's "Decisions worth another look" entry on
`gz-seek` reaching zlib-rs through its C API.

- **No plan waits on upstream** (`../../../.claude/skills/upstream-issue/SKILL.md`).
  The UF4 request is still made, filed by the maintainer from
  `runs/UF4-upstream-request/issue.md` (`../upstream.md`, "UF4").
- **Any engine giving what an index needs is a backend candidate**, a C
  library or a crate's C ABI as much as a safe crate, those known to be slow
  last. **Slice 15.9 measures them through `gz-seek`** before 15.1.2 and
  decides the backend, which becomes a `D<k>` of its own; ISA-L is excluded
  (`../../design/roadmap-P15-gzip.md`, "Settled in the grilling", "Slice
  order").
- **`unsafe` is acceptable where necessary, and a crate declares itself free
  of it wherever possible.** D27's count is the seven libraries'
  (`../../design/decisions.md`, "D27", "D68"), so `gz-seek` linked leaves it
  true. No library declares anything today (`gz-seek` `deny`s, the vendored
  `xz-seek` `forbid`s), so the count holds by inspection alone until `M246`
  (`../../design/out-of-band.md`) lands the declarations and their check.
- **CMake is not refused as such**: it was kept from the shipped build so that
  `aws-lc-sys` builds under its `cc` builder, and a backend built by CMake is
  acceptable once that is guarded another way (`../../design/decisions.md`,
  "D111").
- **Facts.** `crates/gz-seek/src/zlib.rs` speaks the zlib API, which
  `libz-rs-sys`, `libz-sys`'s stock zlib and its zlib-ng compat build all
  export. `libz-sys` 1.1.30's `cc`-built zlib-ng compiles but does not
  initialise (below, "15.9's build routes, reviewed"). Stock zlib has not been
  timed here.
- **ISA-L's igzip cannot stop at a block boundary upstream** (intel/isa-l
  `469c7d0`, read 2026-10-23: `isal_inflate` returns only on input empty,
  output full, an error or the stream's end). The stopping points
  (`points_to_stop_at`) exist only in rapidgzip's fork, mxmlnkn/isa-l, and
  intel/isa-l#254 asking for them has been open since 2023-08-24. Upstream
  has `isal_inflate_set_dict`, priming only by writing `inflate_state`'s
  `read_in`/`read_in_length` (undocumented), no window read, and no CRC-32
  combine. `isal-sys` 0.5.3 bundles v2.31, built by autotools and nasm.

## A writer that ends no block, reviewed

The maintainer reviewed 15.4's entry on a single member indexed as one unit.

- **Which writers do it** (`runs/p15-level1-writers/reading.txt`): at level 1,
  zlib-ng's default build and zlib-rs end no block before the final one,
  which `deflate_quick` opens over its lookahead at `Z_FINISH`; stock zlib and Fedora 44's zlib-ng-compat, built without
  `deflate_quick`, end a dynamic block every few tens of KB. `pg_dump` (13,
  16, 18) calls `deflate` with `Z_NO_FLUSH` and `Z_FINISH` only, and the
  `postgres` images 15.1's fixtures come from link stock zlib (Debian,
  Alpine). The spec's "the choice of spacing is the reader's" now says so.
- **Which of them is warned** is "15.5.3's warning, reviewed", below; the
  warning is tested on a member `libz-rs-sys`'s own level 1 writes, never
  `flate2`'s, whose backend is feature unification's. No Fedora `pg_dump` fixture: another valid writer's
  block layout tests nothing the one-block case does not.
- **15.10, after 15.8, places checkpoints inside a static block** (`KD129`,
  `../deficiencies.md`): a resume at any symbol boundary of one is a synthetic
  three-bit static header primed ahead of the byte's remaining bits, at most
  ten in one `inflatePrime`, plus the window, through the zlib API as it is;
  no inflater stops there, so the forward pass walks the static codes itself
  (`../../design/roadmap-P15-gzip.md`, "Slice order").

## 15.9's build routes, reviewed

The maintainer reviewed the entry a `/gosub` round raised on finding 15.9's
`cc`-built zlib-ng leg unbuildable.

- **15.9 settles its own legs**: which build routes reach each engine, which
  of them work, and which it recommends, the backend's `D<k>` recording the
  routes it rejects (`../../design/roadmap-P15-gzip.md`, "Slice order"). So
  is whether a defect found on the way is a `UF<k>` or an upstream report. A
  route needing a build of our own is weighed, not refused in advance.
- **`libz-sys` 1.1.30's `zlib-ng-no-cmake-experimental-community-maintained`
  build** (`runs/p15.9-zlib-ng-cc-probe/`, `reading.txt` beside the probe's
  `Cargo.toml` and `main.rs`; on a Ryzen 9 3900X, no AVX-512): as shipped,
  `inflateInit2` returns `Z_VERSION_ERROR` after "Zlib-ng functable failed
  initialization!" (`../../design/roadmap-P15.1.1-inflate-notes.md`, "Negative
  results"); with `CFLAGS=-DWITH_OPTIM` the link fails on
  `crc32_chorba_sse2`, `chunkmemset_safe_avx512`, `compare256_avx512`,
  `inflate_fast_avx512`, `longest_match_avx512` and
  `longest_match_slow_avx512`, their sources never compiled. Its `zng/cc.rs`
  has one `cc::Build` (line 103, compiled at line 440), and the AVX-512 block
  (lines 254–287) adds `-mavx512f -mavx512dq -mavx512bw -mavx512vl
  -mavx512vnni -mvpclmulqdq -mtune=cascadelake` to it by `cfg.flag`, so every
  source is compiled for AVX-512, where the SSE blocks use `mflag`. 1.1.30 is
  the latest `libz-sys`.
- **The other legs were read, not built**: `libz-rs-sys` without
  `export-symbols` exports no C names, so it links beside `libz-sys`;
  `libz-sys`'s `static` (stock zlib) and `zlib-ng` (CMake) modes exclude each
  other in one graph, so each leg is a build in a target dir of its own, as
  the allocator legs are; `libz-sys`'s `z_stream` takes non-nullable
  allocator function pointers, so `crates/gz-seek/src/zlib.rs` passes
  allocators on those legs.

## A first pass's windows, reviewed

15.5.2 held every window a gzip first pass places in memory, unbilled
(`KD130`), flagged under "Decisions worth another look". Reviewed with the
maintainer: **a first pass writes each window, as it places it, to an
unnamed spill file the run alone holds, read positionally as a loaded cache's
section is, and a save copies the section out of it** (D114 unchanged). It
is **15.5.4**, earned by 15.5.2 shipping a shape the spec rejected, after
15.5.3 and before 15.6: 15.8 replaces the frontier that places the windows
and 15.7's resident readings mean nothing without it. The spec's "Only
offsets, bit positions and CRCs are resident" names it; `KD130` describes what
is built until it lands.

- **Where the file lives**: the enabled cache's directory — writable by
  construction, every save renaming into it — and the OS temp directory
  (`TMPDIR`) under `--dtcache none`, the convention DataFusion's
  `DiskManager` already holds an embedder to; `open`'s caller names it, so
  `pgdt-io` still names no cache. A file that cannot be made is refused by
  name, never answered from memory. **Rejected**: the temp directory always,
  a tmpfs on Arch's and Fedora's defaults whose pages the run's memory cgroup
  is charged; the directory a disabled cache would have had, beside a dump
  often on a read-only mount, which is a reason to pass `none`.

- **What the review found in the tree**: the spec's "Only offsets, bit
  positions and CRCs are resident" rejects an index "resident and unbilled,
  past the size `KD26`'s argument is sound at", the shape 15.5.2 built for the
  pass it never discussed; `FirstPass::hand_over` keeps the pass's
  `PassWindows` as the complete index's provider, so the windows stay
  resident for the whole run, and for every run under `CacheMode::Disabled`;
  at 32 KiB a `CHECKPOINT_SPACING` they pass `MEMORY_UNPOOLED_BOUND` near
  200 GB of plaintext and reach about 1 GB over koji's (arithmetic).
- **Why a spill file**: it alone keeps the pass flat in every cache mode, the
  spec having kept windows out of memory on the same ground. **Rejected**:
  billing them through a per-source `WorkerMemory` term, which names an
  unbounded term without bounding it; re-basing `PassWindows` onto each saved
  cache (its `earlier` provider), which holds the windows since the last save
  — growing with D62's interval — and covers no disabled cache. **D114's
  objection to a file beside the cache does not reach it**: unnamed (unlinked
  at creation, or `O_TMPFILE`), it has no identity for D20 and D21 to check,
  orphans nothing and is reclaimed on a kill.

## 15.5.3's warning, reviewed

The maintainer reviewed the entry a `/gosub` round raised on stopping 15.5.3
before building it.

- **A unit count says nothing of the writer.** zlib-rs's level 1 indexes a
  member written in more than one call as two units, the second its final
  block, which `deflate_quick` opens over its lookahead at `Z_FINISH`; only a
  member deflated in one call is one unit
  (`runs/p15.5.3-level1-units/reading.txt`; `runs/p15.4-level1-blocks/reading.txt`;
  the zlib-ng row of `runs/p15-level1-writers/reading.txt`). And every gzip
  file under `CHECKPOINT_SPACING` is one unit for its size.
- **A gzip index has no seek structure where a unit is wider than twice its
  spacing**: only there did the writer go a whole spacing without ending a
  block, zlib ending one every 16 K symbols. The spacing is the index's own
  (`Checkpoints::spacing`), so nothing new is persisted and no cache bump
  follows; a file under the spacing is never warned, its one unit being the
  reader's choice; 15.10 leaves the rule true and stops it firing on
  `deflate_quick` output. Rejected: marking the checkpoint that opens a
  member's final block and warning where it is the only block checkpoint,
  persisted and keyed to one encoder's ending; no gzip warning before 15.10,
  which leaves a koji-scale such member to the declined-block note, telling
  the user to raise the budget to the member's size.
- **One predicate gates both messages**: gzip's `is_seekable` is that rule,
  so the warning and the declined-block note stay exclusive, the note meaning
  a seekable file whose units the budget cannot afford.
- **`.xz` is unchanged**: D19 warns a one-block file whatever its size, its
  blocks being the writer's and `--block-size` always splitting them; a width
  rule there would make a large-block file that needs only a budget one with
  no seek structure. D19 gains gzip's clause when 15.5.3 lands.
- **The warning carries the number that is the rule**: the kind gains
  `largest_unit`, plaintext bytes, on both codecs, `.xz`'s its one block;
  gzip's text names it against the spacing and the remedy, recompressing with
  `gzip` or writing at a level above 1, `bgzip` waiting for 15.6. Rejected: a
  gzip-only kind for the same finding.

## The repoint's code-side findings, grilled

The repoint at the stamp's move read four things the code falls short of,
which it corrects nowhere but in the comments; the maintainer settled each.

- **A complete map is saved before its reads are completed**:
  `pgdt_mapping::forward`'s end-of-file save, and the back-fill's after it,
  run `SourceWatch::check` alone, `map_file`'s last save alone following
  `SourceWatch::finish`: `KD131`, unowned.
- **A read behind a gzip first pass's frontier is compared with nothing**: its
  decode begins with the checkpoint's CRC-32 cleared and is never finished,
  so over a resumed index's cached windows a bad window hands out wrong bytes
  unrefused: `KD132`, owned by 15.11, a slice admitted for it and ordered
  after 15.5.4 — whether a read is checked being a review apart from where
  the windows live.
- **The first pass's 64 KiB skip scratch is charged nowhere** (`Pass::scratch`,
  one a pass beside its two decodes), where the indexed codecs' skip buffers
  are 4 KiB on the stack. 15.5.4 charges it, being the slice that restates
  what the pass holds; rejected, shrinking it to 4 KiB (a throughput question
  nobody has priced) and leaving it to `MEMORY_RESERVE`, a known term being no
  reason to leave a charge short.
- **The smoke run stays unlimited**: under a container limit `pgdt` carves the
  cgroup's, where an installed archive on an ordinary host carves half of what
  is available, and five rows hold next to nothing; `smoke_argv` says so, and
  `release.py`'s `MEMORY` binds the builds and tests alone.
- **The parallel figures' allowance is 2.00 GiB under the reserve**, the
  margin's ceiling binding below it from two workers up, which the harness's
  own count arithmetic already used; only the emitted sentence was wrong.
