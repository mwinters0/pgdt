## The recurrence has two halves, and the harness only fixes one

`M17` was specified against apparatus drift: every re-take so far had been a
one-off `runs/` script, so each one re-derived the apparatus from scratch. That
is the visible half.

The other half is that **code changes silently invalidate figures**. `M11`
changed one line in `map::Builder::on_row` and invalidated both census figures.
`M12` changed a generator's output bytes and armed a stale-input trap in the
whole-file bench that `M15` had to disarm. In neither case did anything
announce it — someone noticed, which is not a mechanism.

So each figure **declares the paths it depends on**, and the harness can say
which figures a diff has made stale: the census figures on `map.rs`, the nested
tables on `nested.rs`/`batch.rs`, the quadratic on the map plus the cache, every
figure on its generator. It is the same forcing function as the emit contract's
table shape — a figure that cannot say what invalidates it is one nobody has
thought about. `CLAUDE.md` gets the command and its read-trigger when the
harness lands, because the answer should be *computed* rather than remembered,
and remembering is exactly what failed twice.

## One sweep means the whole doc, not the stale parts of it

`M17`'s run replaces every table, including the seven already on the current
footing, and `measurements.md` gains a one-line session stamp — the sweep's
date and the commit it ran against — with per-section apparatus notes kept only
where a section genuinely departs (koji's medium, `criterion`'s absence of a
container).

Re-taking seven correct tables looks like churn, and the argument that it is not
is that **the doc differences across tables**: the census-attribution table is
quoted as reproducing the census `parse` figures to within 3%, and the warm
scan-throughput table exists so the `INSERT` ratio becomes a division against
its cold twin. A doc whose tables come from two sessions reintroduces the
fourth standing rule's failure — differencing across sessions — one level above
where that rule was written. Seven tables moving by the session drift is evidence
the drift is real, and the ninth rule already forbids reading a small movement
as a result.

The stamp is what makes "one session" checkable instead of asserted, and it
answers "are these figures from before or after my change" at a glance. Every
previous answer to that question was archaeology.

## The harness lands; the doc still has every one of its old recipes

`scripts/measure.py` and `scripts/test_measure.py` are in, with `CLAUDE.md`'s
command block and read-trigger, `CLAUDE.local.md`'s paths, and
`measurements.md`'s "each section's recipe below is the durable record"
retargeted at the harness. **No figure in that doc has moved.**

The split is deliberate and is the "never mix high- and low-confidence work in
one review cycle" rule applied to a doc: a prose recipe is replaced by the
table that replaces it, per section, and deleting a runnable recipe in favour
of a harness that has not yet emitted a real figure for that section would
leave the doc with neither.

**Thirteen inventory rows are eleven figures.** The two census sections each
carry *one* table whose rows are the cold and the warm regime, so cold and warm
are not separately selectable there — a table is the unit that may not be half
re-taken, and that is the whole reason the fourth standing rule exists. The
warm scan-throughput table is genuinely a second table, as its contract says.

**Both throughput tables share their `COPY` row with the census table.** The
contract named this for the warm one; the cold pair has the identical
duplication — same binary, command, input and regime — so the harness shares
both, and a selection naming `scan-throughput-cold` pulls `census-brace-free`
in with it.

The harness reproduces the recorded figures where they could be checked
cheaply: the quadratic table's save counts come back 503 → 15, 1003, 2003,
4003; its wall times land within 3–8% of the doc's on a single rep; the
4000-table dump's first `COPY` header is at byte 980,996 of 1,998,741, exactly
as recorded.

## A sweep is a measurement, so nothing else may build while one runs

A `cargo test --workspace` across 24 cores moves the numbers a sweep is taking,
which is `measurements.md`'s "a koji figure taken while local work ran is not a
figure" one scale down. `CLAUDE.md`'s long-running section now says so, and the
verification for this session was run *before* the sweep was started rather
than beside it.

The same section now says to stop a sweep by **process group**. Killing
`measure.py` alone orphans whichever generator it had running, and that
generator carries on writing a multi-gigabyte file into the input cache — a
file with no stamp beside it, so the next sweep regenerates it, but the disk
fills in the meantime.
