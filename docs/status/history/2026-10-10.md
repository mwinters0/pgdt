## P35.3 grilled before landing

35.3 was grilled with the maintainer before any code moved, the row naming
fewer cuts than the spec's graph needs. Read off the `use crate::` edges
under [`../../design/roadmap-P35-seams.md`](../../design/roadmap-P35-seams.md),
"The crate graph", these cross a crate boundary the wrong way today:

- `io` → `scan`: `Cancellation`, `SCAN_CHUNK_DEFAULT_SIZE_BYTES` (named by the
  row).
- `index` ↔ `cache`: `DumpIndex` and the loader (named by the row).
- `leader` → `stream`: `cut`, `worker_count`. The spec puts the interior split
  in `pgdt-dump`; both are worker sizing and go to `io`.
- `decode` → `scan`: `PostgresInvalidValues`; `pgtype` → `preamble`:
  `canonical_type_name` (with `parse_type_name`, which needs only
  `copy::Cursor`); `unrepresentable` implements `map::FieldCount`. The codec
  reaches only core and model, so each goes down.
- `error.rs` names `arrow::error::ArrowError`, `xz_seek::Error`, bincode's
  `EncodeError` and tokio's `JoinError`, so a core holding it compiles Arrow,
  xz-seek and bincode into every crate. `tests/layering.rs` never checked
  layer 0. Tests match `Error::Xz(xz_seek::Error::BlockCheckFailed { .. })`
  and `Error::Io` by variant.

Settled:

- **`model` is a directory module**: submodules `catalog`, `span`, `block`,
  `statistics` and `diagnostic` (`diagnostic.rs` moved in whole), re-exported
  flat, so code names `crate::model::X`. The old public module paths go, no
  shims; the crate root's re-exports keep their names. `tests/layering.rs`
  learns a module's production submodules.
- **The ordering keys move to the codec in their own slice**, 35.7, after
  35.3 and before the carve; 35.3 leaves them in `predicate.rs`, a query
  module.
- **The core error type names no dependency's error** (the spec, "The crate
  graph", `pgdt-core`): `Arrow`, `Xz`, `CacheEncode` and `Join` hold their
  cause boxed, each crate meeting one converting by `map_err`, a test that
  matched `xz_seek::Error` by variant downcasting instead. Nothing on a
  success path changes: no option grows `Error` past its largest variant,
  and a decoder's per-field failure is `Unread`, not `Error`.
- **`FieldCount` and `BlockObserver` go to `model::block`**, beside the data
  they observe (the spec's `pgdt-model` line, amended to say so).
- **`PostgresInvalidValues` goes to `model::statistics`**, beside the refusal
  records it governs; **`parse_type_name` and `canonical_type_name` go to
  `lex`**.
- **`statistics.rs` keeps the request and the account**, assigned to
  `pgdt-query`; renaming it or folding it into a split `gather` is 35.6's.
- **`index.rs` becomes `load.rs`**, `pgdt-dump`: the preamble prepass,
  `preamble_only` and the diagnostics a map carries. `DumpIndex` goes to
  `model::span`.
- **D68 and D74 are rewritten in 35.3**, the change that falsifies them: D68
  to the six-crate assignment with no deviations, D74 to the rules above. 35.5
  repoints paths only. The maintainer allows the register's line cap up by 25
  if the rewrite needs it.

## P35 re-grilled with the maintainer

The spec was written without its branches put to the maintainer; this
grilling walks them, every earlier call open. Facts it stands on:

- **No `[profile.release]` exists**: Cargo's defaults, no cross-crate LTO,
  16 codegen units. No `D<k>` or figure has priced a profile.
- **About forty `pub(crate)` items cross a target crate boundary**, methods
  and fields beside them: `map::Builder`, `index::scan_preamble`, the
  `instrument` hooks, the `unrepresentable` counters, `copy::Cursor` among
  them.
- **Unit tests reaching up a crate**: `io`'s drive `scan`, `stream`, `batch`
  and `leader`; `pgtype`'s and `resolve`'s parse DDL through `preamble`.
- **Tooling by path**: `check.py` finds packages through `cargo metadata` and
  names none (its tests do); `file_limits.py`'s exemption, `repoint.py`'s and
  `citations.py`'s root lists, `deficiencies.py`'s `CODE_ROOTS`,
  `emitter_register.py`'s readers, `floor_mapping.py`, `oracle_register.py`,
  and `measure.py`'s mechanism lists, `depends` entries and two
  `release.Build`/`Bench` calls on `pgdump_query` name paths or the package.
  The release workflows and Dockerfile name no crate. `deficiencies.md`
  carries 56 `pgdump_query/src/` paths. `introspect` and `http` are forwarded
  by hand from `pgdt` and the DataFusion crates.

Settled:

- **Six crates, as specified**; why `pgdt-core` stays apart from the model is
  in the spec.
- **The split's runtime cost is the phase's to read**, and a regression's
  remedy is in the code, the shipped profile being its own `D<k>` with a
  figure (the spec, "Why now").
- **Forced-public plumbing goes in each crate's `internal` module**, checked
  never named by an embedder (the spec, "What this phase does not do").
- **The runtime reading is a `release-profile` figure**, one tree per sitting,
  before and after the carve, and the shipped profile is decided from it
  whatever it shows (the spec, "Why now"). Slices 35.8 (the figure and its
  first sitting) and 35.9 (the second and the decision) are admitted; the run
  order is 35.3, 35.7, 35.8, 35.4, 35.9, 35.5, 35.6, and 35.4 stays one slice.
- **Unit tests reaching up**: the codec dev-depends on the dump crate, which
  never depends on it; `io`'s upward tests move whole to the lowest crate
  holding what they use, query depending on `io`. The three `#[cfg(test)]`
  helpers 35.2 named need nothing: their one importer, `predicate`'s tests,
  is query like them.
- **No compile-time reading is taken** (the spec, "Why now"); 35.4's row no
  longer owes one.
- **The facade is retired, not kept as a public face** (the spec, "Naming
  and layout").
- **Versions in `[workspace.dependencies]`**, landed by the carve with the
  `upgrade-deps` skill repointed; **the graph check becomes
  `scripts/layering.py`** over `cargo metadata` when the facade goes;
  **`CACHE_FORMAT_VERSION` moves to `model`** in 35.3 (the spec, "The crate
  graph" and "Naming and layout").
- **The profile figure times `allocator`'s three shapes**, each leg a named
  profile inheriting `release` that `pgdt --version` names (the spec, "Why
  now").

The grilling's frontier is empty; P24's inbox carries the one fact it
produced for a later phase. No slice landed: 35.3 is next, as settled in the
section above.

The maintainer set two standing rules after 35.8's sitting showed legs

## The `internal` boundary, reviewed

STATUS's "Decisions worth another look" carried 35.4's call that a method a
crate above calls, and an item in a `pub` module, stay reachable by their
own path. Facts: the carve widened about 150 `pub(crate)` items to `pub` —
42 methods, 68 functions, 27 types, 8 fields — and `float_field`, say, is
both `pgdt_codec::internal::float_field` and `pgdt_codec::decode::float_field`.
The 8 fields are on `pgdt-dump`'s `leader` types, which only `internal`
names. Embedders name `cache`, `decode`, `instrument` and `pgtype` items by
module path as API. `pgdt_dump::cache` re-exports
`pgdt_core::internal::OVERWRITE_WAYS_OUT`, which `pgdt` uses.

Settled with the maintainer, the spec amended ("What this phase does not
do"): **every library module private**, API namespaces public modules of
named re-exports, **methods a crate above calls behind extension traits in
`internal`**; the entry's only argument against it was cost. A
`clippy.toml` of `disallowed-methods` per embedder was refused: it fails
silently on a forgotten entry and puts the boundary in a config file rather
than the module tree. **`internal` is per crate**: a crate above may adopt a
lower crate's `internal` item as its own API, as `cache` does
`OVERWRITE_WAYS_OUT`.

The rest settled the same round: **35.5's check also refuses `timed!` and
`row_evaluated!`** in an embedder, `#[macro_export]` rooting them at
`pgdt_core` whatever module declares them; and **the reshaping is slice
35.10**, admitted after spec time, run after 35.9 and before 35.5 so the
check is written against a tree it can hold — a visibility and trait change
across six crates reviewed apart from 35.5's repointing.

## The codec's `arrow-buffer`, reviewed

STATUS carried 35.4's call that `pgdt-codec` names `arrow-buffer` for `i256`
beside `arrow-schema`. Facts: `OrderKey::Decimal(i256)` in `key.rs` is the
only use, never leaving the codec nor persisted; `arrow-buffer` adds `bytes`,
`half`, `num-bigint` and `num-traits`, which every build compiling the codec
already compiles through `pgdt-query`'s `arrow` or the codec's own
dev-dependency. Affirmed with the maintainer; the refusals are D74's. The
spec's "names `arrow-schema` only" is corrected, and **35.5's script holds the
codec to no `arrow_buffer` item but `i256`** by path, a dependency list being
unable to see which items a crate uses.

## `datafusion-cli-pgdump`'s versions, reviewed

STATUS carried 35.4's call that the crate takes `async-trait`, `clap`,
`datafusion` and `tokio` from `[workspace.dependencies]`. Affirmed with the
maintainer: `datafusion-cli = "=55.1.0"` carries upstream's requirements

comment now says so and the mirroring convention is dropped; no version moved.
