# 2026-09-26

## P27 is being grilled; `KD45` moves to `M173`

The grilling's record so far is
[`roadmap-P27-dynamic-filters.md`](../../design/roadmap-P27-dynamic-filters.md),
written a round at a time; a session resuming it reads that file's
"Decisions" and continues from what they leave open.

`KD45`'s two stated reasons did not survive reading the code, and it leaves
P27:

- **Order.** The provider's summary is computed in Arrow semantics
  (`datafusion-pgdump/src/statistics.rs`, `table_statistics`), which for an
  enum reads the label-text set gathering keeps beside declaration order
  (`pgtype.rs`, `ComparisonPlan::bounds_read_by`; `decisions.md`, "D79") — the
  set the provider already declares an enum's ordering from
  (`tests/statistics.rs`, `enum_proved`).
- **Type.** Every reader of a column's `min_value`/`max_value` in DataFusion
  55.1 accepts the column's own `Dictionary(Int32, Utf8)`, which is what
  `bound` builds. `Utf8` is the wrong one: filter estimation fills a missing
  end with a `Dictionary` null and `Interval::try_new` refuses the pair
  (`physical-expr/src/analysis.rs`), and an uncoerced `MIN` returns the
  column's type. Coerced SQL answers `MIN(e), MAX(e)` from statistics only
  through the common-subexpression projection, which casts either type.

So `M173` is removing the early return, with a test answering `MIN(e)`,
`MAX(e)` and both together from statistics and planning a numeric-only filter
over a table holding an enum; it strikes `KD45`.
