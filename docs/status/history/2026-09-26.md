## Grilling the open calls

The maintainer, on the five rows above.

  (c) unowned or rescinded; now stated in `out-of-band.md`'s admission rule.

  file's stored size, unreadable, another build's format — is an error that
  aborts the run, being almost certainly a user's accident: pointing at the
  wrong file, or a file that silently changed. Silently overwriting stays
  available behind a flag, not the default (a name floated:
  `--ignore-source-identity`), for using a cache while it is valid and

  pgdt cache is refused with the flag too. Today `CacheStatus::Unreadable`
  covers foreign bytes and a cut-short file alike, and a cold start's save
  renames over it, so `--dtcache mydump.sql` would replace the dump; and
  `KD30` makes an old build's cache read as `Unreadable`. `M159` closes
  `KD30` — a magic number and the version read before the rest — so the
  two are told apart.

  reason, where "stale" may come to mean something narrower after 1.0; its
  help says a file that is not a pgdt cache is never overwritten.
- **`CACHE_FORMAT_VERSION` is still bumped freely**, and after `M159` a bump
  refuses every existing cache until the flag or a deletion: a silent
  multi-hour re-scan after an upgrade is what a user should be told about

- **`M160` is withdrawn.** Opening an uncached `.xz` on the calling task

- **`M162` is kept**: a tree's newest run of any command list decides, and a

## A dump changed mid-run: what happens

Traced over all four sources and `parse`, `query` and the provider, and
forced 20 times on a release build (a 3 GiB one-block plain dump and its
`.xz`, truncated, overwritten, appended to and renamed over 1.5–2.5 s in;
remote through `nginx:alpine`). **Nothing panicked**: each run exited 1 on an
`Error`, or 0 under `--strict-identity=none`.

- **The first to notice is often a read or a decode, and its error does not
  say the file changed**: a truncated plain file is `Error::Io`, "failed to
  fill whole buffer" (`io.rs`'s `read_exact_at`); an overwritten or truncated
  `.xz` an `Error::Xz`; a warm `query` over rewritten bytes `InvalidUtf8`.
  `pgdt`'s `about_the_source` does not count `Io` or `Xz` as about the source.
- **`SourceWatch` catches an append or a same-size rewrite** at the next save
  or at run end: `parse`'s saves ride a closed `COPY` block, so one huge
  block goes unchecked until it ends; a warm `query` checks only as each
  sub-stream ends, **so rows read from changed bytes can reach stdout before
  the abort**. A rename is never noticed and harmless: the descriptor keeps
  the old inode (`pgdump_query/tests/identity.rs`).
- **A remote source is guarded by its per-read precondition alone**: its
  `size()` and `modified()` are the probe's, so `SourceWatch` compares the
  probe with itself; the server's 412 is `SourceChangedWhileRead` at once.
- **`--strict-identity=none`** reads through a rewrite silently, as it says:
  one run wrote a cache from both versions (818162 rows for 814362).
- **One panic site, debug builds and the library API only**: the unchecked
  `size - read_pos` of `gather_block_statistics` below a truncation (`M165`).
- **Beside the question**: the piecewise `.xz` arm's bytes precede their
  block's check, and the block a run stopped inside went uncompared (`M167`);
  a rewritten block header's dictionary is held to `xz_seek`'s 64 MiB.

Grilled with the maintainer:

- **`M165` makes the abort say what happened**: a failing read or decode
  re-checks identity before it is reported, naming the change and its remedy.
- **Rows printed before the abort are a property of streaming**, stated in
  the manual (`dump-inspection.md`, beside "Nothing is saved and nothing is
  deleted"); a per-chunk check would narrow the window without closing it,
  and reverses D21's read loop left unchecked, so it waits for a user caught
  by it.
- **`M166` reproduces the weak-tag refusal, then fixes it.**
- **`M167` finishes the piecewise arm's check**: a run exiting 0 on bytes
  that failed their own check is a silent wrong answer; bytes still precede
  their check, as rows precede an abort.
- **The dictionary past the budget is rescinded**: `partition_bytes`' doc and
  D15 already say the table's dictionary is an estimate and the layout's
  memory limit the bound, and only a hostile or changed file exceeds it.
- **A change `xz_seek` needs goes to `@xz-seek`**, once the maintainer has
  confirmed (`CLAUDE.local.md`).

## `M159` landed: an unusable cache is refused

`CacheMode::refusal` is the one decision (`pgdump_query/src/cache.rs`);
D20 and D22 carry the why, `KD30` is struck, and the manual's "When `info`
says it cannot answer" is the user's account.

- **Every cache written before this change reads as not a pgdt cache**: the
  header (`CACHE_MAGIC`, then the version) is new, so no flag replaces one.
  Any such cache — a koji leg's under `runs/` included — is deleted before
  its next run, which otherwise stops at once naming the path.
- **`load` now compares the compression layer as well as the size**
  (`Unusable::CompressionContradicted`), so `pgdt` under the flag can reopen
  a file whose claim recognition refused with nothing claimed and still start
  cold; before, a source opened without the claim was handed the old map.
- **The provider refuses an unusable cache with the library's own error**,
  naming `--overwrite-unusable-cache`, where it had sent the user to a
  `pgdt parse` that would itself now refuse.

## `M161` landed: a successor past the subtype is refused

`NestedCompare::Range`/`Multirange` carry `Option<Discrete>` in place of the
`discrete` flag, and `make_range` refuses a successor past
`Discrete::largest` (`pgdump_query/src/pgtype.rs`, `predicate.rs`); I46 states
the three points and its probe asks for two of them, run on 13.23, 16.15 and
18.6. The manual's range paragraph (`type-handling.md`) says such a literal is
refused.

- **A bound past the subtype's own range is still read as a value where no
  successor is taken** — `int4range '[1,3000000000)'` compares as written —
  which is `order_key`'s `i64` widening for every integer leaf, not this
  item's; the server refuses it in `int4in`.

## `M162` landed: a later failure is the verdict

`verify` reuses the newest run of its own list only when no run of the tree
since, of any list, failed (`scripts/check.py`, `runs_of` and `verify`; the
module doc states the rule). `test_check`'s
`test_a_later_failure_of_another_list_is_the_verdict` fails against the
previous `check.py`; a later *pass* of another list leaves the earlier pass
reusable.

## `M164` landed: a quote inside a value is data

`tokenize` (`pgdt/src/where_expr.rs`) tracks which part of a term it is in
and finds the operator by `split_filter_op`'s own rule, `filter_op_at`
(`pgdt/src/main.rs`); `KD49` is struck and the manual's "Combining terms:
`--where`" gives the example.

- **Before the operator a quote still opens a region wherever it stands**,
  not only at the start of the name as the row's gloss had it: that is
  where `split_filter_op` skips one, and matching the term grammar is what
  `KD49`'s closing asked. So `--where "don't is null or x=1"` is still one
  leaf, refused as an unbalanced quote.
- **A string that read a quoted `and` inside an unquoted value now splits
  there**: `--where "note=x'a and b'"` is refused (the leaf `b'`), and
  `--filter` refuses it for its `AND`, where both took it before as one
  equality against `x'a and b'`.

## `M165` landed: a failure names the change

`SourceWatch::attribute` (`pgdump_query/src/cache.rs`) wraps every watched
entry point's failure — `map_file`, `preamble_only`, `map_for_query` and
each replayed batch, serial, partitioned and `TablePartitions`'. D21 and the
manual's `--strict-identity` section say so; `tests/identity.rs`'s
`a_failing_read_is_checked_before_it_is_reported` fails against the previous
source.

- **Any failure is re-checked, not a list of read errors**: a truncation is
  met as a short read, an `.xz` error, invalid UTF-8 or an unterminated
  block alike, and re-checking a refusal that read nothing costs a `stat`.
- **The underflow is refused before reading**: `reread_block` answers
  `CachedBlockChanged` for a block ending past the source's size
  (`stream.rs`); only the per-block entry point reaches it, every scan entry
  point refusing the cache by its stored size first.

## `M166` landed: a weak tag gives way to `Last-Modified`

`RemoteObject::precondition` (`pgdump_query/src/io.rs`) pins a read by
`If-Unmodified-Since` where the probe's tag is weak, and leaves it unpinned
where no `Last-Modified` was stated either; D21, the manual's
`--strict-identity` section and STATUS's remote row say so. The oracle now
compares `If-Match` strongly and `If-None-Match` weakly (RFC 9110, §13.1.1–2)
and `with_weak_etag` states a weak tag; `tests/remote.rs`'s two weak-tag tests
failed against the previous source, the unchanged object's first read after
the probe refused as `SourceChangedWhileRead`.

- **Between runs a weak tag still decides** `weak_against` (`cache.rs`),
  advisory unless `--strict-identity=time` binds it.

## Grilling the unpinned remote run

The maintainer, on `M166`'s open call: the unpinned run said only in the manual.

- **A remote run nothing can check during it is refused by default**, and
  `--strict-identity=none` reads it anyway: a server stating neither a strong
  tag nor a `Last-Modified`. The in-flight check binds under every selection
  but `none` (`StrictIdentity::in_flight`), and silence under a binding term is
  refused (`WeakIdentity`'s doc); `none` costs such a run nothing, there being
  no check to turn off. Rejected: the manual alone, which no library caller
  reads and whose "stops the run" is false for it; a warning `Diagnostic`,
  the promise stated and unkept. Admitted as `M168`.
- **The library cannot tell today**: `remote_identity()` and `modified()`
  give the inputs, and deciding "unpinned" from them restates `precondition`'s
  rule (`is_weak_tag`, RT16's epoch) outside `io.rs`, so the source answers it.
  **A caller's own source defaults to the watch checking it**, today's
  contract in `hint_in_flight_identity`'s doc; one whose size and modification
  time are frozen at open is the one that must answer otherwise.
- **The provider takes a `StrictIdentity` option**, defaulting to `ADVISORY`,
  where `datafusion-pgdump/src/dump.rs` hardcodes it: one question, one answer
  in every front end, `none` reachable from each. Part of `M168`.
- **Between runs a tag decides only if strong**: strong tag, then
  `Last-Modified`, then a weak tag, which proves equivalent content rather than
  the same bytes (RFC 9110, §8.8.1) and so cannot outrank a moved
  `Last-Modified` for a map of byte offsets — `M166`'s judgement on the pin,
  applied to `weak_against` (`cache.rs`). Admitted as `M169`.

## `M167` landed: a run ends on its blocks' checks

`ByteRangeSource::complete_reads` (`pgdump_query/src/io.rs`) completes the
block a piecewise `.xz` read left open, and `SourceWatch::finish` (`cache.rs`)
calls it where a run succeeds: after each query stream's last batch, before
`map_file`'s and `preamble_only`'s final save. `tests/cache.rs`'s
`a_query_stopping_inside_a_block_fails_on_the_block_s_check` fails against the
previous source. **`xz_seek` needed no change** — a block read to its end
compares on that read — so no `@xz-seek` conversation was opened.
