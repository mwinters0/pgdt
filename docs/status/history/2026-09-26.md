## The repoint's open calls

The repoint at `9d885cb` corrected what the code refuted and left five things
it could not settle by correcting a sentence. Each is admitted as its own
out-of-band item, none blocking, no phase being open.

- **`M159`, the cache rule's wording.** D20's body is what the code does:
  `CacheLoad::Unreadable` and `UnsupportedVersion` start cold
  (`pgdump_query/src/stream.rs`, `map_for_query` and `map_file`), and the next
  save renames over them. Its title and `CLAUDE.md`'s standing rule say the
  library never replaces cache data at all. Refusing to overwrite an
  unreadable cache instead would change D20's decision, and is not this item.
- **`M160`, the `.xz` open on the runtime.** `open_local` calls
  `XzSource::open` and `with_table` directly, so a cold open walks every
  stream footer on the calling task. Only the CLI's first open of an uncached
  `.xz` reaches the walk; the DataFusion provider reads a complete cache,
  which carries the seek table.
- **`M161`, a narrow subtype's successor.** `make_range` reads every integer
  bound as `i64`, so only `int8range`'s successor overflow is caught; the test
  beside it says `int4range` "cannot". A literal the server refuses is
  answered instead, matching no stored value.
- **`M162`, `--verify` behind a newer failure.** `newest_run_of` drops runs of
  other command lists before picking the newest, so a plain `--verify` can
  reuse an older full pass over the same tree after a newer `--affected` run
  failed.
- **`M163`, "re-reads a block once".** The blind reader of `statistics.rs`
  found that a block first mapped flagless is re-read at the default group
  size under a stated maximum, which cannot come out finer, while the test
  asserts a finer size after one run; `stream.rs` decides whether that is a
  second re-read.
