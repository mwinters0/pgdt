## A dump changed mid-run: what happens

Traced over all four sources and `parse`, `query` and the provider, and
forced 20 times on a release build (a 3 GiB one-block plain dump and its
`.xz`, truncated, overwritten, appended to and renamed over 1.5–2.5 s in;
remote through `nginx:alpine`). **Nothing panicked**: each run exited 1 on an
`Error`, or 0 under `--strict-identity=none`.

- **The first to notice is often a read or a decode, whose error did not
  say the file changed**: `Error::Io` for a truncated plain file, `Error::Xz`
  for an `.xz`, `InvalidUtf8` for a warm `query` over rewritten bytes.
- **`SourceWatch` catches an append or a same-size rewrite** at the next save
  or at run end: `parse`'s saves ride a closed `COPY` block, so one huge
  block goes unchecked until it ends; a warm `query` checks only as each
  sub-stream ends, **so rows read from changed bytes can reach stdout before
  the abort**. A rename is never noticed and harmless: the descriptor keeps
  the old inode (`pgdump_query/tests/identity.rs`).
- **A remote source is guarded by its per-read precondition alone**: its
  `size()` and `modified()` are the probe's, so `SourceWatch` compares the
  probe with itself; the server's 412 is `SourceChangedWhileRead` at once.
- **`--strict-identity=none`** reads through a rewrite silently, as it says:
  one run wrote a cache from both versions (818162 rows for 814362).
- **One panic site, debug builds only**: `gather_block_statistics` (`M165`).
- **Beside the question**: the block a piecewise `.xz` run stopped inside
  went uncompared (`M167`).

Grilled with the maintainer:

- **`M165` makes the abort say what happened**: a failing read or decode
  re-checks identity before it is reported, naming the change and its remedy.
- **Rows printed before the abort are a property of streaming**, stated in
  `dump-inspection.md`; a per-chunk check would narrow the window without
  closing it, so it waits for a user caught by it (D21).
- **`M166` reproduces the weak-tag refusal, then fixes it.**
- **`M167` finishes the piecewise arm's check**: a run exiting 0 on bytes
  that failed their own check is a silent wrong answer; bytes still precede
  their check, as rows precede an abort.
- **The dictionary past the budget is rescinded**: `partition_bytes`' doc and
  D15 already say the table's dictionary is an estimate and the layout's
  memory limit the bound, and only a hostile or changed file exceeds it.

## `M159` landed: an unusable cache is refused

`CacheMode::refusal` is the one decision (`pgdump_query/src/cache.rs`);
D20 and D22 carry the why, `KD30` is struck, and the manual's "When `info`
says it cannot answer" is the user's account.

- **Every cache written before this change reads as not a pgdt cache**: the
  header (`CACHE_MAGIC`, then the version) is new, so no flag replaces one.
  Any such cache — a koji leg's under `runs/` included — is deleted before
  its next run, which otherwise stops at once naming the path.
- **`load` now compares the compression layer as well as the size**
  (`Unusable::CompressionContradicted`), so a source opened without the
  claim is never handed the old map.
- **The provider refuses an unusable cache with the library's own error**,
  naming `--overwrite-unusable-cache`, where it had sent the user to a
  `pgdt parse` that would itself now refuse.

## Grilling the unpinned remote run

The maintainer, on `M166`'s open call: the unpinned run said only in the manual.

- **A remote run nothing can check during it is refused by default**, and
  `--strict-identity=none` reads it anyway: a server stating neither a strong
  tag nor a `Last-Modified`. The in-flight check binds under every selection
  but `none` (`StrictIdentity::in_flight`), and silence under a binding term is
  refused (`WeakIdentity`'s doc); `none` costs such a run nothing, there being
  no check to turn off. Rejected: the manual alone, which no library caller
  reads and whose "stops the run" is false for it; a warning `Diagnostic`,
  the promise stated and unkept. Admitted as `M168`.
- **The source answers whether it can be pinned**, deciding it elsewhere
  restating `precondition`'s rule; a caller's own source defaults to the watch
  checking it, one frozen at open answering otherwise.
- **The provider takes a `StrictIdentity` option**, defaulting to `ADVISORY`,
  where `datafusion-pgdump/src/dump.rs` hardcodes it: one question, one answer
  in every front end, `none` reachable from each. Part of `M168`.
- **Between runs a tag decides only if strong**: strong tag, then
  `Last-Modified`, then a weak tag; `weak_against` says why. Admitted as `M169`.

## Grilling the provider's strictness

The maintainer, on `M168`'s open call: `STORED AS PGDUMP` taking its
strictness from the factory, not the statement.

- **Strictness is each dump's, the session's answer its default**, as
  `schema_mode` is: which signals a source states is a fact about it, and a
  session attaching one unpinnable remote dump would otherwise read every
  other under `none`, off the in-flight check `M168` keeps. `pgdt` never
  meets this, a run reading one source.
- **Both front doors take it**: a `pgdump.strict_identity` table option and
  a `--dump …:strict-identity=TERMS` suffix, stripped from the right as
  `:strings` is (terms hold `,`, never `:`). A statement key alone would open
  a many-table dump once per table, its map resident each time.
- **The session default stays the factory's**, and `register_table_factory`
  takes it. Rejected: `SET pgdump.strict_identity` (the factory's rustdoc
  says why), which would also reach no `--dump`, opened before `-c` or
  `--rc` runs. Admitted as `M170`.

## Grilling the weak tag's last tier

The maintainer, on `M169`'s open call: the last tier comparing weakly.

- **A weak tag can show a change and never confirm one**: differing opaque
  tags are `TagDiffers`, equal ones confirm nothing — a map of byte offsets
  needs the same bytes, which is why `io.rs` pins no read by one and RFC
  9110, §13.1.5 forbids one in `If-Range`. Rejected: weak comparison, as
  landed; exact equality, `W/` being strength and not part of the tag.
- **One pairing binds**: a cache recording `W/"abc"`, written under `none`,
  against a live `"abc"`, neither stating a `Last-Modified`. A live weak tag
  with no `Last-Modified` is `M168`'s uncheckable source, refused before any
  comparison under every selection but `none`.
- **Equal but weak is its own state**, `WeakIdentity::Unconfirmed`, carrying
  both tags so a refusal under `time` names the weak one rather than calling
  a source stating a strong tag silent, as `Absent` would. **Silent under the
  default**, as `Absent` is: an advisory warning means evidence of a change,
  and such a cache was written under `none`, which chose not to be told.
  Admitted as `M171`.

## `M170` landed: each dump its own strictness

`PgDumpTableOptions::strict_identity` (`datafusion-pgdump/src/factory.rs`)
and `DumpArg::strict_identity` (`datafusion-cli-pgdump/src/pgdump.rs`) carry
a dump's own terms, falling back to the factory's, which
`register_table_factory` now takes. The manual's `--dump`, `STORED AS
PGDUMP` and `--strict-identity` sections and STATUS's provider and shell rows
say so. `tests/registration.rs`'s
`a_statement_s_strictness_overrides_the_session_s` and `tests/cli.rs`'s
`a_dump_s_own_strictness_overrides_the_session_s` fail against the previous
source.

- **The two suffixes strip in either order, each once**; a `:` after
  `:strict-identity=` is the source's, so a path holding the text is read
  as a path.
- **No term spells `ADVISORY`**, so an override can tighten a session, or
  drop to `none`, and not loosen it to advisory; STATUS's "Decisions worth
  another look" carries it.
