## M222: the `release-profile` figure counts `instructions:u`

Every `pgdt` leg of `release-profile` now runs its timed command under
`count-instructions`, a static workspace member beside `peak-rss`
(`crates/count-instructions/src/main.rs`): one hardware counter opened on
itself, inherited by every task the command clones and enabled at its `exec`,
so the count is every thread's and none of the wrapper's, taken in the run its
wall clock is. A multiplexed count is refused, never scaled. The figure
declares it by `Figure.counts_instructions`, and its renderer prints a count
table and the rule's verdict per workload (`downstream_verdict`).

The pinned image's default seccomp profile refuses `perf_event_open`
(`EPERM`); `--cap-add PERFMON` admits it, so a counted figure's containers
carry that capability and no other's do (`COUNT_INSTRUCTIONS_CAPS`). A sweep
selecting a counted figure counts `/bin/true` in the image before its first
reading and refuses where it cannot (`counter_preflight`).

The rule's attribution clause is written
([`../../design/roadmap.md`](../../design/roadmap.md), "A downstream build is
within 3% of ours"). No sitting was taken: the readings are 35.24's, from a

## The attribution clause's profile, reviewed

Reviewed with the maintainer, closing M222's entry under STATUS's "Decisions
worth another look". The clause names a profile of the default leg, and
`--profile-recipe` profiles `target/profiling/pgdt`, which inherits `release`'s
fat LTO (D105), so it cannot show a call only the default build leaves out of
line.

**The timed legs are already profilable.** `runs/pgdt-release-{default,fat}`
keep `.symtab`, so a flat `perf` profile of either names its functions with no
rebuild; only call chains need the profiling build's frame pointers.
`profile_recipe`'s docstring said otherwise and is corrected. **A profile of
the default leg alone cannot attribute lost inlining**: it lists every
cross-crate call left out of line, the ones fat LTO leaves too among them.
`perf diff --sort symbol` of the two legs on one workload names the symbols
out of line only in the default leg. An untimed check on `query --schema-mode
typed`, one rep per leg and no figure (`runs/attribution-profile-check-20261011/`),
named `pgdt_codec::decode::digits::push_padded`, `decode_uuid` and their
siblings — ours, which `#[inline]` reaches — and std's
`core::slice::memchr::memchr_aligned`, which only a call that no longer
crosses reaches. `#[inline]` goes on the callee, so the callee's name is the
remedy's input and a call chain is not needed; a callee not ours has its call
sites found by `graft callers`.

**M223 admitted, blocking 35.24**: the recipe prints that differential, from a
sitting's own leg binaries on the failing workload's `RELEASE_PROFILE_SHAPES`
argv, and amends the clause to name it when it lands. Per
[`../../design/roadmap.md`](../../design/roadmap.md), "Attribution is
introspective; only the gate is blind", the instrument comes before the
sitting, and a sitting overwrites `runs/pgdt-release-*`, so a failure is
profiled before the next one. A `profiling-default` build profile was refused:
it profiles a rebuild rather than the timed binary, and lists rather than
isolates lost inlining.
