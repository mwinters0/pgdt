## P35: the trees designed before the rest is cut

A file past a limit indicts the design around it, not just itself
([`../../process.md`](../../process.md), "Seams"); the `seams` skill now
designs the crate's tree first and cuts toward it. 35.6 had cut only the
files past a hard limit, at their banners, and 35.10.2 had moved what
`internal` re-exports into children: four read-only reviews at `2df93720`,
under `runs/seams-review-20261011/`, found most crates' trees undesigned —
sibling modules importing each other in cycles, children importing from their
parent, `pub(super)` widened to let a cut compile, one concept's items split
across files by visibility. `pgdt-core`, `pgdt-model` and the two DataFusion
crates read as designed.

The maintainer amended the spec ([`../../design/roadmap-P35-seams.md`](../../design/roadmap-P35-seams.md)):
an API namespace's file **declares** its API, `pub use` from the private
children that define it, rather than defining it, which had forced each type
family apart along the API line; and the trees are designed in one no-code
slice, 35.11, which then slices the cuts toward it by concept — each slice
owning whole concepts, none split between two (35.13's row) — and 35.12
closes the phase. `scripts/layering.py` already reads a namespace's
`pub use` as its API, so the check is unchanged.

## The concept map

The seams round designed one crate's tree at a time, and nothing said which
crate a concept's part belongs in: the reviews under
`runs/seams-review-20261011/` found statistics, filter resolution, the strict
parse and a cache's identity each spread across modules, and nothing read the
spread across crates. [`../../design/concepts.md`](../../design/concepts.md)
now maps each concept to the modules holding it in every crate, each crate's
part with its reason, and a "Not in one place" line for what the layering does
not explain; `scripts/concepts.py` holds every production file to exactly one
concept. A spec places what a phase adds, and a slice adding, moving or
removing a module updates the map ([`../../process.md`](../../process.md),
"The loop", "Seams"); the `seams` skill designs the map's next version, across
crates first. 35.11 is that design. D68 cites the map rather than listing
modules, and `decisions.md`'s section headings lost their pre-carve file lists.
The maintainer raised `process.md`'s cap to 525 lines.

## The module graph, computed

35.11's design placed modules by concept and stated their edges' direction
unread: 35.16 found `compare` ↔ `grammar`, which the design said ran one way.
A read of `use` paths at `6cfaeb33` found four two-way pairs in code;
`scripts/module_graph.py`, reading rust-analyzer's index (method calls,
`impl`s and `Self` included), finds eleven cycles across 116 modules. One is
kept (`ACCEPTED`: `origin` ↔ `remote`); the other ten are `OWED`, each naming
the slice or design that removes it. **Five no slice removes**, so 35.11.1
checks the design before 35.17: 35.11's design
leaves datafusion-pgdump's root cycle, pgdt-dump's `cache/`, pgdt-model's four
modules, the `gather/` that 35.18 moves whole, and codec's `compare` ↔
`grammar` ↔ `pgtype`.

The rule is [`../../process.md`](../../process.md), "Seams": every module
edge runs one way, a design's moves are projected by the script before any
cut, and the `seams` skill says how. A doc link is no edge — the maintainer
kept them, concepts explaining one another — but `--docs` lists those against
the edges. `rust-toolchain.toml` now pins the `rust-analyzer` component, and
`mise run check` runs the graph wherever a package's code changed.
