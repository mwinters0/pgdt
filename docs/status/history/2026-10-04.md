## A built-in type with no reader is outside the strict promise by scope

The review of 31.21's call affirmed it, and the roadmap's "A literal is
guaranteed in `*_out`'s form and never read past `*_in`'s" now says so: a
built-in type pgdt has no reader of (`tsvector`, `tsquery`, `pg_lsn`,
`jsonpath`, `tid`, `oidvector`, `pg_snapshot`, `txid_snapshot`) is outside what
a `strict` parse promises, though its input is the field's, and no `KD` is
filed. The rule had bound `strict` to every field-decided built-in, and the
2026-10-03 enumeration of the gaps inside it was `builtin_scalar`'s and
`text_grammar`'s arms alone. The `reg*` types and `aclitem` join the rule's
inputs the restoring server decides, reading its catalog.

`unread`'s `NoReader` holds more than that class, read against each
`pg_catalog` base type's input function at v13.23 to v18.6: a type whose
`*_in` refuses every value (`pg_node_tree`, `pg_ndistinct`,
`pg_dependencies`, `pg_mcv_list`, the `pg_brin_*_summary` types,
`gtsvector`), one whose `*_in` refuses nothing at some supported major
(`"char"`, `refcursor`, and `xid`, `xid8` and `cid`, which v16 narrowed —
VD2), a type the dump does not declare, and pgdt's own shortfalls (a
composite whose fields did not parse, `KD3`'s array shapes). **Slice 31.21.1
splits them**, 31.21 having shipped a reason that presents some as no reader
and leaves the checked-by-nothing ones listed; `xid`, `xid8` and `cid` are
read as `oidin` is, refused only where every supported major refuses, so
nowhere.

## A partition's bound is outside the strict promise

The roadmap's "A literal is guaranteed in `*_out`'s form and never read past
`*_in`'s" and the manual now name it beside the `CHECK`: it is the table's
declaration, not the column's, compared under the partition key's operator
class and collation, the key possibly an expression, and under
`--load-via-partition-root` a row is refused only when every partition's bound
excludes it.

**Slice 31.27 names it per block**, as 31.21 names each `CHECK`: the preamble
reads the `ATTACH PARTITION` `pg_dump` writes before the data at every major,
and a hand-written `PARTITION OF`, into the partition's `TableDef` with its
bound as text, and a block the map marks as loaded through its root is named
as routed. Read from the statement rather than the `TABLE ATTACH` TOC comment,
which a hand-written dump lacks. When it lands, the P32 inbox's list of ignored
`ALTER TABLE` forms loses `ATTACH PARTITION`.
