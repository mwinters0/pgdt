# 2026-09-15

## The pruning figure prices its cost as well as its best case

Reviewed with the maintainer; filed in the P10 spec, "Measurements". Slice 10.10's instrument is
uncommitted in the tree with its box unticked, and adds a third `statistics-pruning` filter before
any reading is taken.

- **Both existing legs are one best case**: the range `id > 400000 AND id <= 403000` and
  `v_category=category-200` each select 3,000 of about 815k rows in about a dozen contiguous 1 MiB
  groups of about 3,072, skipping over 99% (`generate_pruning_bench.py` at its seed, rows averaging
  about 3,960 bytes).
- **Nothing priced consulting statistics that skip nothing**, though gathering and a query's use of
  it are both on by default (`decisions.md`, "D19") and the cache's statistics grow with the groups.
  `pruning_problems` refuses a pruned leg skipping no group, so the third leg is admitted there
  alone, asserted to skip nothing.

## Carrying statistics is priced too, as 10.10.1

Reviewed with the maintainer; the P10 spec, "Measurements", now says so. The third filter was agreed
as pricing loading and evaluating statistics, but the spec said "consulting", and 10.10 built legs
differing by `query --statistics` alone: both decode the whole cache (`cache::read_cache_file`),
statistics included, so no reading holds the decode. 10.10.1 adds the leg against a cache written by
`parse --statistics none` and re-takes `statistics-pruning` before the wrap. The pruned legs' floor
already bounds the decode at 3,072 groups ([`../../design/measurements.md`](../../design/measurements.md),
"What row-group statistics buy a query").

## `--json` exports the whole cache file

`M108`, admitted at [2026-09-14](2026-09-14.md), "`--json` exports the cache, group values included";
a report changing no recorded decision, `decisions.md`, "D67" restated as the whole file.

- **`cache::CacheEnvelope`** carries what `CacheFile` persists beside the index and `total_size`,
  moved out of the decoded file on `CacheStatus::Valid`/`Incomplete`. Its fields stay private and its
  `Serialize` is the persisted types', so `SourceIdentity` and `CompressionIndex` export with their
  variant tags (`LocalFile`, `Xz`). The on-disk layout is untouched: no `FORMAT_VERSION` bump.
- **The seek table exports as `seek_table`**, since the derived `CompressionShape` already holds the
  top-level `compression` key; `IndexJson` flattens the envelope beside the index.
- **Pinned by** `pgdump_query-cli/tests/xz_source.rs`'s `seekable_xz_parses_to_the_same_index_as_plain`:
  table length against the shape, `stored_size` against the file and the table's compressed size,
  and the cache-only export's envelope equal to the live one's.

## A moved block's refusal names its cache

`M109`, admitted at [2026-09-14](2026-09-14.md), "A back-fill keeps what a block held, and refuses a
moved block"; a message changing no recorded decision, `decisions.md`, "D20" and "D34" untouched.

- **`Error::CachedBlockChanged { path: Option<PathBuf>, header_offset }`**: `map_file`'s back-fill
  names the `CacheMode::Enabled` path it loaded, the only mode holding a block that can lack
  statistics. The public per-block entry point, `gather_block_statistics`, is handed a map and no
  cache, so it answers `None` and the sentence names the map alone.
- **Not taken: a `&CacheMode` argument on `gather_block_statistics`.** That entry point neither loads
  nor saves, and a mode taken only to be named in one refusal would read as one it persists through.
- **Pinned by** `tests/statistics.rs`'s `a_block_rewritten_at_the_same_size_is_refused`, now over a
  cache outside the dump's directory: the back-fill's path and message against that cache, and the
  per-block entry point's `None`. Dropping the path from the back-fill fails it.
