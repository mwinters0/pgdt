## The architecture review, read against the record

A review of the architecture at `ec20c8fd`, made outside the repo, was checked against the code, the register and the
inboxes. What it found is now filed by destination, so nothing cites the review itself:

- **Three phases, all `Sketched`** (`roadmap.md`). **P43**, the block model, separates `CopyBlock`'s identity, address
  and record, and moves recording into one recorder; it runs ahead of P8 and the archive phases, which each need a part
  of it. **P44** moves the embedder protocol into the library, before P24. **P45** gives the codec one resolved
  PostgreSQL type, before P39.
- **Inbox entries**: P8 (the escape-dialect fork, and `line == row`), P18 (the gzip-only open-extent source), P41
  (zlib-framed entries, the linear address space), P42 (a new inbox: each source sizes itself as the only one), P32
  (the fold's cut-off, the `ALTER TYPE` variants), P22 (the carve derived in several places).
- **`M299`–`M305`**: behaviour-preserving cleanups that fit one session each. `M300`, `M301` and `M303` touch the row
  path, so each lands under D108's `--count-pair`. Where a pair resolves a rise that rework cannot remove, the shape
  stays and its reason is written beside it. A shape that is messy because performance needs it is kept.
- **Not taken**: merging `FirstPass`'s sync and async serve loops, which D126 and D15 keep apart, and the duplicated
  block-arm logic between `file.rs` and `fetched.rs`, which is D15's. The review's ordering argument, a refactor
  before the first cache-format bump, carries no weight before 1.0; its argument from P8 and P41 does.
