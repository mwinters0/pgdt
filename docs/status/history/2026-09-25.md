## M146's calls, reviewed

**A query's mapping-pass shortfall moves onto a span the CLI opens around the
mapping await**, printed only on the lines the pass emits:

- `mapping arrangement` prints before the map is read, so it names a pass
  that runs only after an **interrupted** `parse`: `parse` gathers statistics
  by default and a complete cache returns from `map_forward` before
  `scan started`, so the common query states a pass that never runs.
- The library already receives both counts (`ScanOptions`, `QueryOptions`
  in `table_stream_partitions`) and can size the statistics itself; what it
  cannot know is the cause, `bound_by="statistics"` being true only because
  `pgdt` carves the two passes that way (D64). So the line does not move into
  `map_forward`.
- A `tracing` span the CLI enters around the `table_stream_partitions` await
  puts its fields in front of `scan started`, `scan arrangement` and `scan
  complete`, all emitted by the async `map_forward` inside that await, and on
  nothing when the pass does not read. The library is unchanged; the status
  output gains one line family carrying its facts as a span prefix, which a
  span's meaning — a fact of the whole pass — earns. Admitted as `M147`.
- **The span is `mapping`, opened whenever the cache holds statistics**
  (`held > 0`), not only when they cut the count: the mapping pass's budget
  then always differs from `resolved the arrangement`'s, stated `--jobs` or
  not. `held_bytes` is always on it, the replay's count only where the count
  was cut, as `replay_jobs=` — `asked=` would sit beside `scan arrangement`'s
  own `asked=`, the mapping pass's count, on one line; `bound_by="statistics"`
  goes, the span's presence being the cause.
- Rejected: `CacheClaim` reporting completeness (a query-shaped fact on a
  table-agnostic claim, still wrong on a partial cache whose target is
  settled).

**An interrupted `parse` dies by the signal it caught, and one during the
listing stops it** — D26's "owing 128+signal" kept, its mechanism changed:

- `exit(128 + n)` is a normal exit, and bash's wait-and-cooperative-exit
  runs a calling script on past a child that exits after a Ctrl-C: a child
  trapping SIGINT and exiting 130 left its outer script continuing, one that
  re-raised aborted it (process-group SIGINT, bash, this machine). So
  `pgdt parse big.dump; pgdt query …` queried a partial cache.
- So after the save and the re-run line, `signal_hook::low_level::
  emulate_default_handler` re-raises; `$?` is 130/143 either way, as `query`,
  which installs no handler, already ends. Tests assert `status.signal()`.
- The cache is saved before the listing prints, so once the scan returns
  `flag::register_conditional_default` is armed: a signal during the listing
  takes the default action in the handler, and a pipe nobody drains cannot
  hold the process. One between the last cancellation check and the arming is
  still recorded, and a check before the listing honours it.
- **The second signal dies in the handler**: `register_conditional_default`
  registered first, then `flag::register` on the same `armed` flag, which the
  scan's return also sets. `cache::save` encodes and writes synchronously on
  the runtime thread (`write_beside`), so the `tokio` task's exit could not
  cut a wedged save short; the task keeps only `cancel.cancel()`.
- **`signal-hook` stays**, now for all four primitives above. Rejected: an
  `unsafe` `sigaction`/`raise` in `pgdt` reimplementing them; `tokio` alone,
  which reaches neither the listing nor a synchronous save. D26 and its tests
  are amended when this lands. Admitted as `M148`.

## M148's call, reviewed

**pgdt behaves correctly as its PID namespace's init, for every command** —
M148's `getpid() == 1` branch stays, and the rest of the binary owes the same.

- `getpid() == 1` is the kernel's own test, and `signal-hook`'s
  `emulate_default_handler` ends in `abort()` whether or not the raise landed,
  so a raise-then-exit fallback needs the `unsafe` unblocking M148 rejected
  (RT19, D26).
- **An init discards `SIGINT`/`SIGTERM` under the default action from any
  sender**, the host's included (RT19, corrected; an `unshare -Urpf` probe
  signalled from the host). So as PID 1, `query`, `info`, and `parse` outside
  its guard ignore Ctrl-C and `docker stop` until `SIGKILL` (137).
- Rejected: requiring an init. `docker run image pgdt …` makes pgdt PID 1
  unasked; `nerdctl run --init` runs the host's `tini`, absent here, and
  moves the koji recipe's `State.Pid`, whose `VmHWM` is its peak-RSS reading,
  off pgdt.
- **As init, both binaries end on every signal whose default action ends
  them elsewhere, exiting `128 + n`**; `parse`'s guard keeps `SIGINT`/`SIGTERM`
  for its scan. Not INT/TERM alone, which leaves Ctrl-\ and a closed terminal
  deaf under `docker run -it`; not a list of who sends what.
- **`datafusion-cli-pgdump` too**: it installs no handler, and upstream's REPL
  calls `tokio::signal::ctrl_c()` only around a statement (`exec.rs`, 55.1.0),
  so as init `-c`/`-f` ignore INT and TERM, and the REPL TERM. The REPL's
  `ctrl_c()` must still cancel a statement, so the init handler stays off the
  signals it catches; `signal-hook` runs every registered action.
- **Pinned under `unshare --user --map-root-user --pid --fork`**, signalled
  from the test by the child's host pid, asserting an exit code and no
  `status.signal()`; failing loudly where unprivileged user namespaces are
  refused (Ubuntu ≥ 23.10's AppArmor default), as `xz_source.rs` does without
  `xz`. One test per binary, plus `parse`'s saved-then-130.
- Admitted as `M149`; the `getpid() == 1` comment in `pgdt/src/main.rs`, D26,
  RT19's "Relied on by" and the manual's init sentence move when it lands.

## M149: every signal ends an init

- `pgdt/src/namespace_init.rs`: as init only, `register_conditional_shutdown(n,
  128 + n)` on every signal whose default action terminates, bar
  `SIGKILL`/`SIGSTOP`, `SIGPIPE` (the Rust runtime ignores it before `main`)
  and `signal-hook`'s `FORBIDDEN` three; the realtime range included, whence
  `libc` as a plain dependency of `pgdt`. Both calls sit under "Decisions worth
  another look".
- `parse` registers its guard, then `InitShutdown::release`s `SIGINT` and
  `SIGTERM` (`signal_hook::low_level::unregister`); a signal between the two
  runs the older action first and exits. The shell leaves `SIGINT` out in the
  REPL alone, `-c`/`-f` running no `ctrl_c`.
- `pgdt/tests/namespace_init.rs` holds each run at a stalled oracle request;
  its every-command test fails at its deadline with the handlers disabled. The
  saved-then-130 case stalls the first read past the file's midpoint, found by
  an unstalled run. `-f` refuses a FIFO (upstream's `parse_valid_file` wants
  `is_file`), so the shell's test holds at a `--dump` origin that accepts and
  never answers.

## M149's calls, reviewed

**The init handlers move into a workspace crate, and the fault signals are
left to the kernel.** Both land as `M150`; until then `namespace_init.rs` and
D26 describe what is built.

- **A crate, not `#[path]`**: the include made `datafusion-cli-pgdump` restate
  `libc`/`signal-hook` "at `pgdt`'s versions" and allow `dead_code` for
  `release`, so the drift it avoided in the signal list moved into two
  manifests. A `publish = false` member states them once and exports what each
  binary uses; the `unshare` helper sits behind a test-support feature the two
  `[dev-dependencies]` enable. Nothing in the workspace is published. Rejected:
  a default-off `pgdump_query` feature — library API only a binary may call
  (D13's reasoning).
- **`ILL`, `TRAP`, `BUS`, `FPE`, `SEGV` and `SYS` keep the kernel's forced
  default as init**; every other signal whose default ends the process,
  `SIGABRT` included, keeps `_exit(128 + n)`. As built, a genuine `BUS`/`TRAP`/
  `SYS` fault as init `_exit`s with no core where elsewhere it dies by the
  signal: `std`'s stack-overflow handler resets a `SEGV`/`BUS` to the default
  and returns, and the kernel forces the re-fault (RT19), but `signal-hook`
  runs our action after that handler returns. And a hand-sent fault signal
  does not reliably end a Rust binary anywhere: `std` swallows the first
  `kill -SEGV` (exit 7 after one, 139 after two, a plain Rust binary here).
- Rejected: `register_unchecked` on all six, acting only on `si_code ≤ 0` —
  `unsafe` in a fault handler, which must reset `ILL`/`FPE` itself or loop on
  the faulting instruction, to answer a request nobody makes.

## M150: the init handlers in a crate

- `namespace-init/` (`publish = false`) holds `InitShutdown` and, behind
  `test-support`, the `unshare` helper as `namespace_init::unshare`; both
  binaries depend on it, their `[dev-dependencies]` enabling the feature. It
  re-exports `SIGINT`, `SIGTERM` and `c_int`, so the shell names no `libc`;
  `pgdt`'s `libc` is `introspect`-only again. `citations.py`, `repoint.py`
  and `deficiencies.py` read it as a workspace root.
- `SIGTRAP`, `SIGBUS` and `SIGSYS` left the handled list; the unit test
  `the_handled_signals_leave_the_faults_to_the_kernel` pins all six out. RT19's
  scope limit now names the six and `force_sig_info_to_task` (v7.1,
  `kernel/signal.c`) clearing `SIGNAL_UNKILLABLE` under `SIG_DFL`. Not
  observed: nothing here provokes a real `SIGBUS`/`SIGTRAP`/`SIGSYS` as init.
