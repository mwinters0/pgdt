## The parsing and decoding audit: five defects, one phase

A read of the parsing and decoding path — `copy.rs`, `decode.rs`,
`nested.rs`, `pgtype.rs`'s mapping, `preamble.rs`, `lex.rs`, `scan.rs`,
`map.rs`'s builder, `batch.rs`, `resolve.rs`, `unrepresentable.rs` — against
`pg_dump` 16.15's source and against real output taken from throwaway 16.15
and 18.6 containers (`runs/parse-audit-20261002/`: `schema.sql` is the probe,
`run.sh` and `connect.sh` took the dumps, and each `*.sql` beside them is one).
It did not read `statistics.rs`/`gather.rs`, `predicate.rs`'s literal
parsers, `pgtype.rs`'s comparison register, `pgdt`'s `--where` grammar or the
`INSERT` run.

Five defects, each confirmed on the probe dumps with the `13:19` release
build, each now owned by P31:

- **`KD64`** — an inheritance child's inherited columns resolve `NotDeclared`
  (`public.child`: `extra` is `Date32`, `id` and `name` are text, and a
  query prints `extra` first). `shouldPrintColumn` is the emitter.
- **`KD65`** — `CREATE UNLOGGED TABLE` is not classified; every column of
  `public.scratch` is text. `CREATE FOREIGN TABLE` under
  `--include-foreign-data` falls the same way, unprobed.
- **`KD66`** — a `--binary-upgrade` composite with a dropped attribute keeps
  the `/* dummy */` field, and `query --table public.trios` refuses its first
  row on both majors; `ALTER TYPE … DROP ATTRIBUTE` is read by nothing.
- **`KD67`** — under `bytea_output = escape`, set on the database, `pg_dump`
  writes `\000\377\\\011` and a typed `bytea` query refuses it
  (`16-bytea-escape.sql`). `pg_dump` pins no `bytea_output`.
- **`KD68`** — `CREATE DATABASE "My-App"` dumps as `\connect
  -reuse-previous=on "dbname='My-App'"`; `pgdt info` over its `pg_dumpall`
  lists `template1` and `postgres` only, the table landing in `template1`
  (`16-dumpall-myapp.sql`).

**What the probe cleared.** A zero-column table's empty rows, NBSP and a tab
inside `text[]` and composite values (neither `array_out` nor `record_out`
quotes a non-ASCII byte), `character(5)[]`, `"char"`, `interval day to
second(3)`, `timestamp(3)`, `time with time zone`, enum labels holding a
backslash and a newline, a default holding `ARRAY[1, 2]`, a `numeric(5,2)`
`NaN` beside unconstrained `Infinity`, a partition's full column list, and
`COMPRESSION`/identity written as separate `ALTER`s — every one reads as the
dump holds it.

**P31 is grilled and sliced**
([`roadmap-P31-correctness-evidence.md`](../../design/roadmap-P31-correctness-evidence.md)):
an emitter register read mechanically out of `pg_dump`'s source, a value
oracle, and the fixes for what they find. It owns `KD64`–`KD70`, `KD69` and
`KD70` filed by the grilling from its inbox, and a `KD` of its class found
later becomes a P31 slice without asking — the spec's opening note.

**P32 is allocated**, the schema model: the maintainer's aim is to capture
every object and property a dump declares, which P31 does not. Its sketch is
in [`roadmap.md`](../../design/roadmap.md), "P32 — The schema model: every
object and property a dump declares", and its inbox holds what the grilling
found; the maintainer sets its order.

## `M199`: a keyword ends at a word boundary

Landed as admitted, closing `KD61`: `strip_kw` refuses a keyword the next byte
would continue as an identifier (`scan.l`'s `ident_cont`), for every caller.
Evidence: `tests/map.rs`'s `a_tablespace_among_the_globals_is_no_table`, over
every fixture holding a `CREATE TABLESPACE`, and `preamble.rs`'s
`classify_statement_recognizes_the_four_span_shapes`; the known-failure row
went with it.

## `M200`: each database keeps its own version pair

Landed as admitted, closing `KD62`: a header pair arriving into a segment that
already holds one waits for the next `\connect`, whatever that segment's data

Evidence: `tests/preamble.rs`'s
`every_dumpall_database_keeps_its_own_version_headers`, every major, eager and
`map_file`, and `preamble.rs`'s
`a_segment_with_no_data_keeps_its_headers_and_the_next_gets_its_own`.

## `M202`: a parse fix bumps the cache format, and a check says so

Reviewed with the maintainer: a fix changing what the preamble parse persists —
`SpanBody::Table`'s columns, which statements are tables, a database's version
pair, all in the cached `DumpIndex` — bumps `CACHE_FORMAT_VERSION` (D22), as
`M143`'s did. `M202` is the one bump owed for `M199`, `M200` and 31.5, which
bumped nothing; 31.6–31.11 each bump in their own change where they move what
is persisted. The `bump-cache-format` skill is the rule's pre-1.0 form.

Landed as admitted: the version is 34, `GOLDEN_ORDER` re-pinned beside it, and
`tests/cache.rs`'s `persisted_index_is_pinned_to_the_format_version` pins a
digest of every fixture's encoded `DumpIndex` at every major, the hand-written
`edge_cases.sql` included, under one fixed `map_file` setting, identity left
out; a regenerated fixture re-pins it alone. Refused: a preamble-only digest,
which covers this morning's misses and nothing beside them. No `CLAUDE.md`
trigger for the skill: the failing check carries the instruction.

## `M201`: a scale past the precision widens it

Landed as admitted, closing `KD63`: `map_numeric` types `numeric(p,s)` at
precision `max(p, s)`, and a typmod no Arrow decimal carries — a precision
or positive scale past 76, a scale below `-128` — as text compared by value.
`CACHE_FORMAT_VERSION` is 35, a scale past `i8` having been typed at scale 0
with statistics kept under that kind; neither pinned digest moved, no
fixture or oracle value holding such a column. The bound the widening relies
on is I51's, extended. Evidence: `tests/decode.rs`'s
`a_scale_past_the_precision_or_arrows_reach_reads_every_value`, which panics
at `batch.rs`'s builder without the change, and `pgtype.rs`'s
`numeric_widens_a_precision_below_its_scale_and_texts_a_scale_arrow_lacks`.
