## 30.8's read-back goes with it

The maintainer settled, reviewing 30.9's unattended call, that `introspect`'s
`mimalloc_purge_delay` line goes with the rest of 30.8: the line, its
hand-counted `MI_OPTION_PURGE_DELAY`, `purge_delay` and
`the_purge_delay_read_back_is_purge_delay_s` are on 30.9's removal list
(`../STATUS.md`, "P30 progress").

- **Its one reader is 30.8's `purge0` leg**, which 30.9 removes; nothing else
  reads the line.
- **The hand count has no running guard**: `scripts/check.py` runs the suite
  without `--features introspect`, so the test pinning the index runs only by
  hand, and a mimalloc upgrade moving `mi_option_e` would pass the check.
- **P23 is not committed to an option.** The remedy chain ranks a library
  change suiting both allocators above one
  (`../../design/roadmap-P30-one-binary.md`, "What the move owes before a
  release"), unlike 30.7's diagnostic legs, which stay because P23's re-take
  needs their attribution.
- **A general read-back was not built ahead of a phase asking for it**; if P23
  sets an option, how it is read back is P23's call, filed in
  `../../design/roadmap-P23-resident-reserve-inbox.md`.
