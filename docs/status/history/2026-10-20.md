## M239 admitted: a filter literal's equality form, grilled with the maintainer

The literal's canonical equality form, `equality_comparison` in
`crates/pgdt-query/src/predicate/resolve.rs`, is value semantics D68 already
assigns to pgdt-codec ("the ordering keys it shares with a filter are value
semantics, so codec's"), so moving it there is a cut, admissible out of band
with no `D<k>` text changed. Until it lands, `concepts.md`'s "Comparison
semantics" carries a **Not in one place** line for it, struck by the item.

What the cut meets:

- **The function is pure and codec-typed**: text in, `CompareKind`,
  `OrderKey` and `String` out, no Arrow and nothing of query's. It runs once
  per literal per block, from `resolve_term` (reached by `resolve_expr`, once
  a block, and `resolve_loosened`, once a dynamic filter's generation), never
  per row.
- **It is pgdt-query's only reason to name seven codec internals**: `int_in`,
  `numeric_in_stores`, `time_of_day_micros`, `timestamp_postgres_micros`,
  `render_timestamp_postgres_micros`, `render_macaddr`, `special_order_key`.
  Moved, they leave `pgdt_codec::internal`. `literal_key` stays there
  (`resolve_term`'s ordering bound, `believed_bounds`), and so do
  `accepted_form`, `unlisted_labels` and `nested_accepted_form`, read where
  `Error::PredicateValueDecode` is built with the term's column and operator.
- **It returns three of `Comparison`'s five variants** (`Canonical`,
  `Trimmed`, `Decoded`); `Ordered` and `Nested` are built in `resolve_term`.
  `Spellings` is built by it, by `resolve_term`'s text fallback and by
  `predicate/test_support.rs`; read per row by `eval.rs`'s
  `Spellings::matches`, by `ResolvedMembership::implies` and by `Lookup::of`.
- **No test calls it directly**; `predicate/tests.rs`'s `oracle` module drives
  it through `resolve_term` against `comparisons.tsv` and stays in query.
- **Cited by path**: `key/form.rs` and `value/network.rs` doc text,
  `predicate.rs`'s intra-doc links, `postgres-invariants.md` ("`Spellings`"),
  and KD82's and KD86's markers in its body.

Settled with the maintainer:

- **The equality form alone moves** — `equality_comparison`, `Spellings` and
  `Spellings::matches` — which empties the split the map's line names. Not
  a codec entry point reading the ordering bound and the refusal's form too:
  that is `resolve_term`'s choice of plan and semantics, the filter's own.
  Not `believed_bounds`: which stored set a term reads (D79) is pruning's.
- **One type for the concept, nested in query's**: a codec enum of the three
  equality variants (`Canonical(Spellings)`, `Trimmed`, `Decoded { kind,
  bound }`), held as one `Comparison` variant beside `Ordered` and `Nested`,
  never converted back into flat variants defined twice. The codec holds the
  literal's reading and `Spellings::matches` (I56's test of a field against
  its spellings); eval keeps the per-row arms and their timing, as it does
  for `Ordered` and `Nested`. Not the per-row test whole in the codec:
  `timed!` reads the calling crate's `introspect`, which the codec has none
  of, and the instrument's parts are a filter's row evaluation; untimed, a
  `Decoded` key's time would read as `Compare`. The per-row match changes, so
  D108's `--count-pair` is owed.
- **One item, the count inside it**: the cut lands as one commit, the pair is
  launched detached at `HEAD~1`, and the row's Date is filled once it is
  read; a resolved rise is placed by callgrind and reworked or accepted under
  the same item.
- **No new tests**: `predicate/tests.rs`'s `oracle` holds the behaviour end
  to end and stays; `predicate/test_support.rs` repoints `Spellings`.
- **`key/equality.rs`**, a child of the `key` namespace beside `form.rs` and
  `order.rs`, `key.rs`'s doc widened to the literal's equality form; reached
  through `pgdt_codec::internal`, since `Decoded` carries `internal`'s
  `OrderKey` and no embedder of the codec relates a literal. The two codec
  doc lines pointing up at query (`key/form.rs`, `value/network.rs`) point
  beside them instead.
- **Names**: the codec's enum is `Equality`, held as `Comparison::Equal`;
  `Spellings` keeps its name, its fields private behind `Spellings::one` and
  a `first()` accessor, which `ResolvedMembership::implies` reads.

## `M240` admitted: arm64's archive built here, attested by its release alone, chosen with the maintainer

**CI cannot hold the arm64 link without a cost the maintainer refused:**
swap on the runner (`release.py` ties `--memory-swap` to `-m`, so it is also
a cap change, sized against an uncapped peak nobody has read, and a fat link
paging to disk may run for hours); `ubuntu-24.04-arm` (the same memory and
the same aarch64 backend, expected no better, unmeasured); a larger paid
runner (the maintainer's account and cost); an arm64-only profile (reopens
D105, the targets shipping different builds). So arm64 is built on the
maintainer's machine.

**mise's `github:` backend**, read in mise's source at `v2026.10.15` and not
yet exercised against a live release, is what the archive must satisfy:

- `github.github_attestations` defaults on, and the check names **no
  expected signer workflow** (`src/backend/github.rs`, "We don't know the
  expected workflow").
- It requires a Sigstore bundle whose subject digest is the download's and
  whose **source repository** is the tool's, or its rename's redirect:
  `crates/mise-sigstore/src/github.rs`,
  `verify_github_attestation_sources_for_artifact`, into
  `crates/mise-sigstore/src/certificate.rs`'s `bundle_source_repository` and
  `crates/mise-util/src/github.rs`'s `attested_by_repository`.
  `bundle_source_repository` accepts **GitHub's release attestation** — made
  for every asset of an immutable release, signed by GitHub's internal CA as
  `https://dotcom.releases.github.com`, the repository named in its signed
  in-toto statement.
- Nothing checks the runner's type. SLSA provenance is checked only where a
  user sets `slsa_signer_identity` and `slsa_signer_issuer`. An asset with no
  attestation is skipped, not refused, unless mise's registry marks the tool
  as requiring them or a `mise.lock` recorded `github-attestations`
  provenance.

**The four ways to an attested arm64 binary that backend installs:**

1. **A self-hosted runner here, for `arm64-release` alone.** The workflow
   still checks out the dispatched commit, builds with `release.py` in the
   pinned image and attests with the workflow's identity and source digest;
   the certificate records a self-hosted runner. Passes mise, and
   `installing.md`'s `--source-digest` check unless a user adds
   `--deny-self-hosted-runners`. The `draft` job, GitHub-hosted, attests
   every archive today, so the honest form attests arm64 in its own
   self-hosted job, `id-token: write` there. Refused: GitHub advises against
   self-hosted runners on a public repository (a small exposure where every
   workflow is dispatched or tag-triggered, but a standing setting); the
   runner needs `sudo nerdctl` and must be up at each dispatch; SLSA Build
   L2, not L3.
2. **Signed keyless with Sigstore under the maintainer's own identity**
   (cosign or sigstore-python), verified by `cosign verify-blob
   --certificate-identity …`. Honest — the maintainer signed these bytes —
   but a signature, not build provenance. Refused: **it fails mise's
   `github:` backend**, a personal identity's certificate naming no source
   repository, and that backend has no cosign-identity option (aqua's has).
3. **The local build uploaded to a workflow that attests it with
   `actions/attest`.** Passes mise, but its provenance says the workflow
   built from that commit what it only received: a false claim that
   verifies cleanly. Refused.
4. **Chosen: GitHub's release attestation alone, for arm64.** The arm64
   archive is built here (the release image; `release.py build --release
   --target=aarch64-unknown-linux-gnu`, its `notices`, `release_ci.py
   archive`) and uploaded to the draft before it is published; an immutable
   release has GitHub attest every asset, which mise counts as verified for
   `mwinters0/pgdt`. x86-64 stays CI-built with build provenance. What
   arm64's attestation then proves: the file is an asset of that immutable
   release, put there by someone with write access to the repository — not
   which commit or machine built it.

**What `M240` designs**, for a later session to grill before code:

- **The manual.** `installing.md`'s "Verify" says both checks must pass; for
  arm64 the first, `gh attestation verify … --source-digest`, fails. It says
  arm64's build is not CI-attested and points at `gh release verify-asset`.
- **The draft takes an archive built elsewhere.** `release-build`'s `draft`
  needs every build job and computes `SHA256SUMS` over every archive, and
  `plan_publish` refuses a draft not holding exactly `expected_assets`; so
  the flow needs a way in for the local archive, and the checksums must
  cover it. `arm64-suite` (real arm64, needing nothing built) and
  `arm64-smoke` (needing `arm64-release`'s artifact) are revisited, with the
  undecided "whether an emulated run verifies a release" above.
- **What describes the flow**: `scripts/release_ci.py`'s module docstring
  ("Build first, tag second", "Verification needs no key we hold"), the
  `release-build.yml` comments, `/release` (`.claude/skills/release/SKILL.md`,
  whose rehearsal already builds and archives both targets, and whose step 5
  is the maintainer's commands), and `STATUS.md`'s "Versioned binary
  releases" row.
- **Filed at landing**: the choice as a `D<k>` under "Releases", the three
  refused options and the refused CI routes its `Rejected`, a runner holding
  the fat arm64 link its `Reopens`; mise's checks above as an
  assumptions-register entry, the decision depending on them.
- **An open check before relying on it**: install v0.1.0 through
  `github:mwinters0/pgdt` with mise's debug logging on, to see which
  attestation mise verifies end to end.
