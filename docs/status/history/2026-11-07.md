# 2026-11-07

## An unquoted element's whitespace run is rewound, not held: 33.21 admitted

Closed from STATUS's "Decisions worth another look" with the maintainer. 33.18's `Blanks` (`value/source.rs`) holds an
unquoted array element's whitespace run as `(u8, u32)` run lengths until the byte after it decides whether the run is
interior, so a run alternating its bytes costs eight bytes of state a byte: at I71's bound, an uncharged ~8 GiB in a
parse. `ArrayWalk` holds it in two places, inside an unquoted element and after the letters `NULL` (`Stage::NullBlanks`),
the second outside the entry's framing. No `pg_dump` writes either, `array_out` quoting every element holding an
`array_isspace` byte, so the cure costs nothing on a dump and only the guarantee decides.

- **Bound, not named.** The spec's one admitted growth, `json`'s depth, rests on being an eighth of the field and bounded
  only by a setting; `Blanks` is neither, and the spec already rejected "a line's worth on one whitespace run". Packing
  the run holds about 2.6 bits a byte, six symbols, and still grows. The spec's "A pass holds a line only where it
  decodes it" and "Where it lives" are amended.
- **The rewind is `Parts`'s**, not each leaf reader's: the walk marks the part where a run starts and feeds it on; an
  `Element` or `Fields` restores the `Check` it held there, bounded by the plan since D144's readers carry a fixed
  state; `Collect` and a query's builder truncate. A refusal inside the run is one bit in the walk, standing only if the
  run turns out interior: `array_isspace` includes `\v` and `\f`, `json_in` neither (I72), so `{1\v}` is a valid
  `json[]` that an eager feed alone would refuse.
- **33.21**, a slice admitted after spec time, lands after 33.18 and before 33.13.3, which then writes its scalar
  readers against the protocol; it works on today's `Check::Scalar`, which truncates its collected text. `KD167` is
  `(b)` P33 and names it. D144 still describes `Blanks` until 33.21 lands.
