## The broken BGZF chain, reviewed

The maintainer reviewed the entry 15.13's round raised on a broken BGZF chain
being read by a pass that coalesces up to the break, on both arms.

- **The rule stays the pass's, on both arms** (D116): every file the walk
  accepts has only BGZF headers, so the pass builds the walk's index there,
  and one the walk refuses is a pass's on either arm. A resume reads whether
  the run reached a member start off the unit before it. The local fallback
  is coalesced up to the break, where before 15.13 it was one unit a member.
- **The run ends for good** (`coalescing &= bgzf`,
  `crates/gz-seek/src/forward.rs`): after one header that is not BGZF's,
  every BGZF member is a unit of its own to the file's end, and a file
  opening with a plain member is never coalesced. The test
  `a_run_of_bgzf_members_is_coalesced_until_a_header_is_not_bgzf_s` asserts
  it. Such a file is valid gzip, so this is `KD135`.
- **Settled: decide per member.** A member start joins the unit only where its
  own header is BGZF's and the unit began at a BGZF member start and is short
  of the spacing; no block boundary inside a BGZF member is a checkpoint, and
  a plain member begins a unit and takes the block rule. The walk accepts only
  files whose every member is BGZF's, where the two rules agree, so its index
  is unchanged. A resume reads the rule off the member's header alone, the
  unit before it no longer consulted. That test is rewritten to assert the
  trailing run coalesced, and one is added for a file opening with a plain
  member.
- **It is slice 15.14**, a spec rule amended (`../../design/roadmap-P15-gzip.md`,
  "A checkpoint's place is a function of the file alone"), placed before 15.8,
  which inherits whichever rule the pass has. D116 states the rule as built
  until 15.14 lands.

## A taken chunk's plaintext, reviewed

The maintainer reviewed 15.8's call that a taken chunk hands out the native
decoder's plaintext (D117 as built).

- **The facts.** In a single member — the case slice 8 exists for — no chunk
  but the last holds a trailer, so the native plaintext is checked by the
  member's trailer alone, after the scan has its rows; the unit CRC-32s are
  recorded from it, and an interrupted pass saves native-derived windows and
  CRCs no trailer has covered. Damage is exposed so on the serial pass too;
  what is new is the exposure to a fault of the crate's own decoder, which
  `native/tests.rs` holds to one writer, `flate2`, at four levels. A re-decode
  through the engine need not be serial, which D117's rejection assumed.
- **Settled: the engine's plaintext, every chunk decoded in parallel.** A
  speculation supplies where its chunk begins and the 32 KiB of history it ends
  with, still marked; the frontier resolves those windows in order, and the
  engine decodes every chunk from its start with the window before it, as a
  unit decode is resumed (D112), on the caller's threads. The engine's decode
  of chunk *k* ending at chunk *k + 1*'s start with the same history proves
  that start and window, by induction from the member's first chunk; one it
  contradicts is decoded again from the engine's own. Why: it keeps both of
  the spec's statements — the inflater bought, never written
  (`../../design/roadmap-P15-gzip.md`, "Settled in the grilling"), and
  rapidgzip's technique implemented natively ("Slice order") — the native
  decoder only finding where chunks begin and what they begin with, as slice
  10's walker is no inflater of our own. The cost is one engine decode a byte
  on the caller's threads, wall time only where cores rather than the
  one-partition scan hold the pass; D117 reopens on a reading where that
  second decode keeps the pass from lifting the inflate at the counts a
  machine runs and the native plaintext would.
- **Which writers' files the lift reaches is 15.7's reading**: a native
  refusal or fault then costs only the chunk, never a byte handed out.
- **It is slice 15.15**, placed before 15.8.1, whose contract with `Parallel`
  it changes (`../../design/roadmap-P15-gzip.md`, "Slice order"). D117 and the
  code describe the native plaintext as built until it lands.

## 15.8.1's chunking, reviewed

The maintainer reviewed 15.8.1's chunk length and plaintext limit, set without
a figure (`Chunking::SHIPPED`, `first_pass/ahead.rs`).

- **The facts.** A guess cut at the limit stops short of where the next
  chunk's guess begins, so `Chain::extend` has nothing to queue past it: the
  frontier decodes on to that guess, anchors there and decodes the anchored
  chunk itself (`Here::Frontier`), and a run of chunks each past the limit is
  the serial pass for its length, not the rest of one chunk as the entry had
  it. rapidgzip meets the same cut and continues it: a chunk stopped at its
  decompressed cap (`stoppedPreemptively`) has its end inserted into its
  block finder, so the next chunk begins exactly there (`GzipChunk.hpp`,
  `GzipChunkFetcher.hpp`'s `appendSubchunksToIndexes`, in the
  `rapidgzip-rs` checkout `CLAUDE.local.md` names). The chunk length's
  coupling to `INPUT_CHUNK` is a convenience: `run_task` reads in
  `INPUT_CHUNK` pieces whatever the chunk is. The limit is most of a task's
  charge (`Chunking::task_bytes`), the chunk length hardly any of it.
- **Settled: a cut continues.** The pass speculates on from a limit-cut
  guess's stop, a start it need not search for, so a limit never ends the
  chain and bounds only what one speculation holds. It is slice 15.16, in
  `gz-seek`, before 15.7, which should not read a cliff the design does not
  keep (`../../design/roadmap-P15-gzip.md`, "Slice order"). D117 and the code
  describe the cut as built until it lands.
- **Settled: 15.7 prices the chunk length**, its parallel first-pass figure
  taking a leg at rapidgzip's 4 MiB beside the shipped length at one worker
  count, a constant chosen for one positioned read being no reason the
  register would keep.
- **Settled: the limit is a constant of its own**, twice the largest block
  zlib ends at its largest `memLevel` — `lit_bufsize - 1` symbols of at most
  258 bytes (`deflate.c`, the zlib checkout `CLAUDE.local.md` names) — since a
  piece reaching no boundary under it returns nothing; held fixed across
  15.7's chunk-length legs, restated when 15.16 lands.
- **Settled: no leg prices the limit.** Its floor fixes it within a factor of
  two, and 15.7's resident readings hold what a task keeps against
  `Chunking::task_bytes`; it reopens on a resident reading where the charge
  rather than the cores bounds the workers at a memory a user runs.
- **Affirmed: the frontier is one of the workers** (D2's "Rejected").
