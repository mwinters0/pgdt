## A `parse` over a gzip first pass, reviewed

The maintainer reviewed the entry 15.5.3's round raised on a `parse` not
announcing a gzip first pass.

- **A cold gzip `parse` says nothing of why it is serial**: `jobs=1
  (recommended by the source)` with `--jobs` omitted, `scan arrangement …
  bound_by="source"` above one, the first pass's `PlanNote` reaching only a
  query (`fixtures/16/edge_cases/compress.sql.gz`, parsed cold in a container).
- **The gzip source announces its first pass**, started and complete, as the
  `.xz` walk is (`crates/pgdt-io/src/source/compressed/xz.rs`); the spec's
  "A first pass is a `PlanNote`, not a diagnostic" says what each line names.
  The `.xz` line exists so a silent wait does not read as a hang; a gzip pass
  is no silent wait, its scan lines running, so what the line adds is the
  reason and that it is paid once. Rejected: the reason folded into
  `resolved the arrangement`'s provenance and `scan arrangement`, which would
  put codec knowledge in the arrangement.
- **It is slice 15.12**, a spec decision amended and so no out-of-band row,
  placed next, before 15.5.4 and 15.7's manual. 15.6's walk is announced the
  same way, being the silent wait the `.xz` line exists for, and 15.8
  rewrites the started line where the pass is no longer serial
  (`../../design/roadmap-P15-gzip.md`, "Slice order").

  `WALK_CHUNK`, 1 MiB, and a member is at most 64 KiB

## The broken BGZF chain, reviewed

The maintainer reviewed the entry 15.13's round raised on a broken BGZF chain
being read by a pass that coalesces up to the break, on both arms.

- **The rule stays the pass's, on both arms** (D116): every file the walk
  accepts has only BGZF headers, so the pass builds the walk's index there,
  and one the walk refuses is a pass's on either arm. A resume reads whether
  the run reached a member start off the unit before it. The local fallback
  is coalesced up to the break, where before 15.13 it was one unit a member.
- **The run ends for good** (`coalescing &= bgzf`,
  `crates/gz-seek/src/forward.rs`): after one header that is not BGZF's,
  every BGZF member is a unit of its own to the file's end, and a file
  opening with a plain member is never coalesced. The test
  `a_run_of_bgzf_members_is_coalesced_until_a_header_is_not_bgzf_s` asserts
  it. Such a file is valid gzip, so this is `KD135`.
- **Settled: decide per member.** A member start joins the unit only where its
  own header is BGZF's and the unit began at a BGZF member start and is short
  of the spacing; no block boundary inside a BGZF member is a checkpoint, and
  a plain member begins a unit and takes the block rule. The walk accepts only
  files whose every member is BGZF's, where the two rules agree, so its index
  is unchanged. A resume reads the rule off the member's header alone, the
  unit before it no longer consulted. That test is rewritten to assert the
  trailing run coalesced, and one is added for a file opening with a plain
  member.
- **It is slice 15.14**, a spec rule amended (`../../design/roadmap-P15-gzip.md`,
  "A checkpoint's place is a function of the file alone"), placed before 15.8,
  which inherits whichever rule the pass has. D116 states the rule as built
  until 15.14 lands.
