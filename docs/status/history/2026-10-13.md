Reviewed with the maintainer, closing 35.24's entry under STATUS's "Decisions
worth another look". At `ef442ad6`
([`../../design/measurements.md`](../../design/measurements.md), "What
link-time optimization buys the shipped build";

ranks fat above either other leg on `pgdt sql` and `typed`: wall clock meets
for every pair there, and user time meets for the default and fat too, so a

the legs; a wall clock resolving another leg ahead overrides it only at
successive trees, one tree's clock carrying its layout; the downstream-build
gate stays in wall clock. User time as the ranker is refused as being as
layout-exposed as wall clock. The rule lives in D105 alone, the roadmap's
order ("Where a setting trades one workload for another, the typed DataFusion
query wins") staying in wall clock, since no other settings figure takes a
count; a general clause is proposed when a second one does. DataFusion's
profile stays a Reopens trigger, as the path upstream benchmarks on. D105 is
rewritten to all of this ([`../../design/decisions.md`](../../design/decisions.md),
"D105"); the profile is unchanged. No work admitted.
