# 2026-09-09

## `M75`: a blanket acknowledgement reaches every figure and no declared section

`Acknowledged.figures` left empty now means **every figure and no declared
section**. A declared section — koji, and `rss-attribution` until `M74` deletes
its row — is excused only by an entry that names it. The permission itself is
unchanged and was not the defect: an entry naming a section still discharges its
red, which is what
[`../../design/measurements.md`](../../design/measurements.md), "A commit can be
acknowledged" settled, since the harness cannot re-take a section it does not
own.

**What the empty tuple was quietly claiming.** `M66` gave `measure.Outside` an
invalidation edge and `--check` began resolving an entry's names against
`NOT_OURS` as well as the register. Two functions read the empty tuple as
"everything the caller knows about", and after that change the caller knew about
the declared sections too: `excuses` matched an empty tuple against any id, and
`spent_acknowledgements` computed `covered = ack.figures or tuple(bases)` over a
mapping `--check` builds as `{**figure_bases, **outside_bases}`. So an entry
written about durations reached koji's byte-for-byte comparison of what a scan
concludes — block offsets, row and byte totals, the `info --detail` report
compared as text — without its author deciding it. That is the escape hatch the
review named, and it opened by accident rather than by anyone's choice
([2026-09-08](2026-09-08.md), "A declared section's red, and which oracle
discharges it").

**Both halves are narrowed, and `--check` still passes the union.**
`excuses` matches an empty tuple only against an id `NOT_OURS` does not hold;
`spent_acknowledgements` computes a blanket entry's coverage over the figure
bases alone. The union stays at the call site, because an entry that *does* name
a section must be spent against that section's own marker rather than against
the session stamp — the two are different questions, and only the first one was
wrong.

**No live entry exercises the narrowing.** All three entries in
`scripts/acknowledged.py` name their figures explicitly, so `--stale` prints
what it printed yesterday and koji is red on the same nine paths. The change is
a bound on what the next entry may claim, not a re-colouring of the doc.

**`session-drift` is red for this change and no acknowledgement is claimable.**
It declares `scripts/measure.py`, which this touches — and the register's own
rule is that a landing on an already-red declared path owes an entry or a stated
reason not to write one. The reason is that none of the three oracles reaches
it. Byte-identity settles generator changes only; reachability is vacuous when
the changed code is the harness's own excuse machinery, which every `--stale`
run executes; and the diff is not comment-only, since `excuses` and
`spent_acknowledgements` both change what they return. `session-drift` was
already red on twenty-three commits under that path, and this is the
twenty-fourth.

## P16 wrapped: the audit, and what it moved

The phase is complete, its checklist deleted, its nineteen slice notes gone and
its roadmap row `Complete`. The spec and the consolidated notes stand; the
keystone that strikes them is separate work.

**The audit found architecture.md already holding almost all of it**, which is
what a wrap after a keystone is for — the slices had been filing beside the
mechanism as they landed, so what was missing was the residue rather than the
substance. Five things moved in, each because the slice note was the only place
it lived:

- **The koji density profile's consequences**, into "The compressed source". The
  section already said the corpus runs 5.02×–33.05× against a whole-file 19.41×;
  what it did not say is what follows — that fitting the figure's two legs gives
  rate ∝ ratio^0.71, so no document may write "koji decodes at 435 MB/s"
  unqualified; that the control's 5.45× sits on the sampled *floor*, which is why
  two legs bracket the corpus and a third koji column at a second offset was
  refused; and why the density gate fires at the cut rather than at the emit. The
  section had been citing the slice note for all of it.
- **The chunk-release rule**, into "Arrow assembly and the zero-copy path". The
  doc said a chunk is evicted "once the scanner has moved past it for good"; the
  rule is `end() <= floor`, and rounding it the other way loses exactly the row
  that straddles a boundary — the one the carry hands over after the scanner is
  already inside the next chunk. That, `retain`'s borrow, and the refusal of an
  accessor over the deque are all filed there now.
- **Steady state in the k-way merge is one read in flight, not N**, into
  "`pgdq query` merges the sub-streams back into file order". Only the first
  round fills every slot, so `--jobs 24` does not turn a plain-file query into
  twenty-four interleaved sequential reads — which is what a reader of "N
  sub-streams" assumes it does.
- **The block pool's eviction ordering has a number**: bounding the retained set
  and the free list independently read 89.2 MiB on the 3.00 GiB control where
  evicting before acquiring reads 64.7.
- **`hint_wait_policy` was missing from the trait's own code block** in
  "Execution model and API surface", which said "seven defaulted methods" over a
  listing of six.

**The two-commit property is now a rule rather than a phase anecdote**
([`../../design/measurements.md`](../../design/measurements.md), "A figure may
be published outside the sweep"): a slice that builds a measuring instrument and
publishes from it lands in two commits, because a sitting run from a tree
carrying its own uncommitted apparatus has no commit to name. Three figures have
been published that way, and the seam was re-earned twice in this phase alone.

**One number disagreed and the harness won.** A slice note recorded jemalloc's
500-block baseline as 9.65 MiB against glibc's; the published table reads 9.58.
The table is the harness's own output and the note was a hand-quote of it, so
nothing was moved.

**The deficiency register needed nothing re-homed.** Its only `(b)` entries are
`KD6` (P6) and `KD9` (P8), both owned by phases the index still calls
`Sketched`; `KD14` was `(c)` already and was merely *paired* with a ticked slice
through the checklist, so the pairing goes with the checklist and the entry is
unchanged.

**Dangling slice numbers were repaired rather than left for the keystone**,
because they stop resolving at this change and not at that one: the checklist
was the only thing they resolved against. Eleven bare `16.x` citations in
`architecture.md`, `measurements.md`, `roadmap.md`, `acknowledged.py`,
`measure.py`, `test_measure.py`, `io.rs` and `main.rs` now name the mechanism
instead. Closed dated entries keep theirs, by rule.

**No figure changed colour, and no acknowledgement is written.** The whole
executable-path diff is comment-only — doc comments in `io.rs` and `main.rs`,
`#:` comments in `measure.py`, a docstring line in `generate_xz_input.py`, a
comment in `test_measure.py` — which is the shape both of P7's standing
acknowledgements have. One is not written because it would buy nothing: every
figure the diff touches was already red on other paths, `nested-decode-micro`
(the one green figure) declares none of them, and the only *new* stale path is
`scripts/generate_xz_input.py` appearing under the two parallel figures, both of
which were already stale on four others. An acknowledgement spends a slot and
adds sediment; there is no red for this one to discharge.

**The negative results the wrap found were left in the spec for the keystone to
take**, rather than copied out beside their mechanisms while the spec still
stood, since duplicating them would have created the second authority a
keystone exists to remove. The keystone took them; where each one landed is
below.

## The parallel-scan work is struck, and the ledger with it

Distil, retarget, sweep, delete — in that order, because deleting first saves
nothing and destroys the source you were about to distil from.

**Distilled.** The wrap's audit had already filed the mechanisms, so the
keystone's harvest was the spec's own: six things that existed nowhere else.
The **split decode-pool/parse-pool** arrangement, refused because the ratio it
would have to be tuned to is a property of the *command* — ~16 decode workers
per discovery thread against ~1.5 per typed-extraction thread, an order of
magnitude apart — which is the reason the fused worker is the shape at all;
**speculative splitting**, refused because a seekable source hands over byte
ranges and not scanner state, so the leader makes speculation unnecessary
rather than cheap; and **cross-block pipelining**, refused because finding a
block's end *is* the work — all three now beside the leader, under "The
interior split". **Copying a field's bytes on the compressed extraction path**
(+7%, and the zero-copy view given up for a whole source class) is beside the
block cache, under "The compressed source". The **`spawn_blocking` dispatch**,
with `std::thread` and `rayon` refused and a blocking task's uncancellability
stated, is under "Execution model and API surface". And the interrupt's
**refusal to bank a partially scanned block** — a partial census being a wrong
answer rather than a weak one — joins the behaviour it explains, under "The
mapping pass is the leader".

**The thesis became a section rather than being deleted**, and it is the one
place the distillate says something the spec did not:
[`../../design/architecture.md`](../../design/architecture.md), "What
parallelism buys, and where it stops". The rule the phase was built on holds —
parallelize what is CPU-bound, which picks decode always, extraction always and
discovery only behind a decoder — but the arithmetic that rule was projected
through does not survive contact with `parallel-scan-throughput`. Two legs
behave as projected and two do not: a compressed `parse` reaches 5.82× at
twenty-four workers, a compressed typed `query` only 1.60×, a plain `parse`
*falls* to 0.81×, and a plain typed `query` is flat at 0.98× although the rule
says it is CPU-bound. So the projections were floors on what would be needed
rather than estimates of what would suffice, and **converting cores into
extraction throughput on a plain source is unfinished work** the
efficient-defaults phase inherits. That section is also what
`parallel-scan-throughput`'s `quoted_by` now names: the figure had exactly one
declared consumer, the spec's projection table, and a figure whose only
consumer is being deleted needs a new one or the edge is a lie.

**Retargeted.** `CLAUDE.md` had no trigger for either parallel arrangement. It
now has one that files them apart — the cold side is the leader's interior
split, the cached side is partitioned replay, they share `stream::cut` and
`worker_count` and differ in what they cut — because the failure it prevents is
reading the wrong section for the arrangement in hand. The performance trigger
gained the parallelism section beside the decomposition, with the fact that
three of the four measured legs are already at a ceiling, so a proposal to
parallelize something meets the evidence before the mechanism.

**Swept**, scoped by the live doc set. Twenty-one code and script citations of
the spec moved to `architecture.md` sections. Four inboxes named the struck
phase and three of them asserted things in the future tense that have since
happened — P14's partitioning advisory, P6's partitioned scan surface, P10's
sparse row index — so each Fact is rewritten to what is now true and each
Origin points at the mechanism rather than at the deleted spec. **Two
contingencies were discharged rather than carried**: P10's index entry was
filed "contingent on the leader arrangement surviving its own slices", which it
did, and P19's plain-path entry was filed contingent on a re-take that has
since happened — its numbers were the superseded `e29939c` sitting's and are now
the published ones. `roadmap.md`'s own phase watermark was a commit behind and
read `P18`; `P19` was allocated on 2026-09-08.

**The ledger is struck to a watermark, and the queue keeps its number.** `M64`
through `M73` and `M75` have landed, so their rows are provenance and go; each
one's mechanism was checked to be filed by subject first, which it was in every
case — `M67`, `M70` and `M72` in `architecture.md`, `M66`, `M69`, `M71`, `M73`
and `M75` in `measurements.md`, `M68` under "Execution model and API surface",
`M65` in the figure register. `M74` has an empty Date, so it stays: it is a
live obligation the P19 inbox, `measure.py` and `test_measure.py` all cite, and
the unattended loop reads this table as a work queue rather than as an archive.
The watermark reads `M1`–`M75`, worded as a high-water mark, and the next item
admitted takes `M76`.

## P19 is specified and sliced, and its grilling reversed two filed positions

The spec is [`../../design/roadmap-P19-efficient-defaults.md`](../../design/roadmap-P19-efficient-defaults.md),
eleven slices, roadmap row `Current`, inbox drained and deleted. Most of it
follows from what 2026-09-08 settled; two things do not, and one of them is a
decision the phase was convened to *adopt*.

**The in-binary arena cap is declined, not adopted.** It came out of `Future`
into this phase on the grounds that a budget discovered from the cgroup and then
blown by arenas seeded at startup is not a sound default. That reasoning stands;
what fails is every available implementation. `mallopt(M_ARENA_MAX, …)` bounds
arena *creation* and frees nothing already made, and glibc seeds an arena per
thread at that thread's first allocation — so a cap keyed to the resolved worker
count removes none of the arenas that already exist by the time it could run,
and the count this phase resolves is the source-dependent one, which is
downstream of source recognition, which is I/O. A cap keyed to the *stated*
`--jobs` is reachable early and is not the number that matters. What is left is
a constant, which re-bases every registered figure's apparatus in exchange for a
value that cannot follow the worker count.

**What replaces it reaches the same place by not creating the threads.** The
CLI moves to a `current_thread` tokio runtime — the library dispatches through
`spawn_blocking` and has never required `rt-multi-thread` — so the threads that
exist are the blocking pool's, created on demand, and the arena count follows
the concurrency dispatched rather than the host's CPU count. `MALLOC_ARENA_MAX`
becomes a published deployment setting for the residual. The price is charged
where it falls: the shipped reserve is sized for the operator who did *not* set
it, so the operator who did gets a smaller budget than their machine could
support, and the spec says so rather than leaving it to be rediscovered.

**`available_parallelism` gets a register entry, against what the inbox filed.**
The inbox concluded the CPU side needed none because the behaviour is `std`'s.
The register's trigger is a decision depending on external behaviour *we do not
control*, and someone else's code is more external, not less: this phase's whole
CPU default rests on `available_parallelism` continuing to read the cgroup
quota, and without an entry a future toolchain moves that default silently.

**Two inbox positions were sharpened rather than reversed.** The span-allowance
entry proposed dividing one allowance among sub-streams; the arithmetic says
that buys no sub-stream at the shipped defaults — `(budget − max_source_span) /
footprint` is zero at 64 MiB against 64 MiB — and that a **plain** source plans
one sub-stream there too, which the entry framed as the compressed case's
problem. The real defect is that the span term is a chunk-shaped source's cost
being charged to a block-shaped one whose `partition_bytes` already covers it,
so the retained unit becomes the source's own to state. And the discovered
budget is `limit − reserve` rather than a fraction of the limit, because the
overhead above a stated budget is measured constant, not proportional — 128 MiB
stated reads the same ~328 MiB resident as 256 MiB stated.

**`KD16` moves to `(b)`, owned by P19 and paired with slice 19.4.** Closing it
re-bases `parallel-scan-throughput`'s one-job row, which runs at the library's
64 MiB default precisely because of the collapse `KD16` describes; that lands
inside the phase's closing sweep.
