# 2026-10-05

## The reserve figure under the two-heap instrument

30.1 left `run_reserve` (`scripts/measure.py`) withholding its account from a
report carrying `mimalloc_scope`, and the maintainer affirmed that: the
account is a model of the reserve's terms, P23's to fit (`KD34`), and P30's
gate is pass/fail on the shipped build. A failure on mimalloc alone is
attributed in a diagnostic sitting on the `introspect` build, a slice the
blocked phase gains: the `parallel-*` readings and a stray kill have no
instrument legs, so no table the sweep prints could attribute them. The spec
says so (`../../design/roadmap-P30-one-binary.md`, "What the move owes before
a release").

The guard also drops the readings table with the account, so a two-heap
sweep publishes only the counter's line, and the `mimalloc_*` and
`glibc_scope=c-malloc` readings live only in per-rep reports under `runs/`.
Readings are not a model, so the reason for withholding the account does not
reach them: 30.2's row now prints them, one column per heap, each labelled with
the memory it covers, nothing subtracted.
