# 2026-10-05

## The reserve figure under the two-heap instrument

30.1 left `run_reserve` (`scripts/measure.py`) withholding its account from a
report carrying `mimalloc_scope`, and the maintainer affirmed that: the
account is a model of the reserve's terms, P23's to fit (`KD34`), and P30's
gate is pass/fail on the shipped build. A failure on mimalloc alone is
attributed in a diagnostic sitting on the `introspect` build, a slice the
blocked phase gains: the `parallel-*` readings and a stray kill have no
instrument legs, so no table the sweep prints could attribute them. The spec
says so (`../../design/roadmap-P30-one-binary.md`, "What the move owes before
a release").

The guard also drops the readings table with the account, so a two-heap
sweep publishes only the counter's line, and the `mimalloc_*` and
`glibc_scope=c-malloc` readings live only in per-rep reports under `runs/`.
Readings are not a model, so the reason for withholding the account does not
reach them: 30.2's row now prints them, one column per heap, each labelled with
the memory it covers, nothing subtracted.

## The heaptrack recipe records a `system` build

30.2 left `--heaptrack-recipe` (`scripts/measure.py`) recording the default
`profiling` binary, whose Rust heap is mimalloc's without `override`, so a
recording carries only C's allocations. The maintainer reversed that: the
recipe records a `system` build. heaptrack counts requests, never what an
allocator kept, and the two builds run the same code, so a `system`
recording holds everything a default one does plus Rust's allocations. On
the default build the recipe's step pair can name only the decoder's
dictionary, already confirmed (`measurements.md`, "What an instrument can
see"), not the block slot and chunk buffer the admitted reader adds
(`HEAPTRACK_AXIS`); and `run_reserve`'s one-heap verdict points at the recipe
for a `system` recording it does not make.

Its build gets a `--target-dir` of its own under `PGDT_MEASURE_ALLOC_BUILD_ROOT`,
as the allocator legs' and the perf recipe's `dfcli-introspect` build do,
`--features system` under `--profile profiling` otherwise overwriting the
`target/profiling/pgdt` the perf recipe records. No valgrind route joins it:
what a valgrind tool could add on the shipped build, and why it does not, is
`KD109`'s detail, which the recipe cites. `M213` lands it.
